## 0. 왜

편성하다 필요한 지점이 없으면 지금은 **편집을 닫고 → 지점 탭에서 만들고 → 코스로 돌아와 → 편성 편집을 다시 연다.** 그 사이 끌어 둔 순서는 사라진다. 지점 고르기 창 안에서 바로 만들게 한다(사용자 제안 2026-11-13).

---

## 🔴 제약 (실측)

1. **`AddPoint` 응답에 새 `pointSeq` 가 없다**(`api-spec.md` — `200 / data: true` 뿐). 만든 지점이 어느 것인지 응답으로 알 수 없다.
2. **미사용 지점은 서버가 후보에서 빼고 준다**(023 실측 2026-10-13). 이 흐름에서 `지점사용` 을 끄고 만들면 **만든 지점이 후보에 안 나타난다.**

## 범위

| 영역 | 지금 | 바꾼 뒤 |
|---|---|---|
| 지점 고르기 창(`AddCoursePointDialog`) | 후보 검색 · 체크 · 추가 | 목록 아래 `+ 새 지점 만들기` · 검색 결과가 없으면 `'검색어' 새 지점 만들기`(이름 미리 채움). 지점이 아예 없을 때의 "순찰지점에서 먼저 추가" 링크는 이 버튼으로 대신한다 |
| 만들기 화면 | 없음(지점 탭에만) | **같은 창 안에서 화면 전환**(`← 지점 고르기`) — 이름 · 설명 · 인증수단(NFC 면 TAG ID). 창을 하나 더 띄우지 않는다(편성 편집 → 지점 고르기 → 3겹 방지) |
| 만든 뒤 | — | 후보를 다시 받고 고르기 화면으로 — **검색창에 그 이름**을 넣어 둔다. 체크는 사용자가 한다 |
| 지점 추가 폼(`AddPointForm`) | 지점 탭 전용 | `defaultName` · `hideUseYn` prop · `onSuccess(name)`. 지점 탭 동작은 그대로 |
| mock `GetClassificationPoint` | 구 지점 mock 에서 읽음 · 미사용 포함 | **지점 저장소**에서 읽음(만든 지점이 나온다) · **미사용 제외**(실서버와 같게) |

### 결정 (사용자 확인 2026-11-13)

- **D1 자동 체크 안 함**: 서버가 새 `pointSeq` 를 주지 않아 자동 체크하려면 전 · 후 목록 비교로 추측해야 한다. 아끼는 것은 클릭 한 번 — **검색창에 이름을 넣어 두는 것**으로 대신한다. 후보를 **다시 받은 뒤에** 돌아온다(먼저 돌아오면 잠깐 "검색 결과 없음" + 만들기 버튼이 보여 또 만들 수 있다).
- **D2 `지점사용` 스위치**: 이 흐름에서는 **숨기고 사용으로 고정**한다(제약 2). 미사용 지점이 필요하면 지점 탭에서 만든다.
- **D3 안내**: 만들기 화면 설명 줄 — "지점은 바로 만들어집니다. 코스 편성은 저장해야 반영됩니다." 편성 편집을 취소해도 만든 지점은 지점 목록에 남는다.
- **D4 캐시**: 성공하면 지점 목록(`pointKeys.lists`, 폼) · 후보(`courseKeys.classificationPoints`, 창) 둘 다 무효화.
