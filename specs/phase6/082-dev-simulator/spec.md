## User Stories

- US1. 개발자가 개발 전용 페이지에서 **사업장을 고르면** 그 사업장의 근무자(로그인 가능 여부 · 근무 · 진행 중 순찰)와 지점 · 코스 수를 본다.
- US2. 개발자가 **구축 작업**(지점 · 코스 · 근무자 일괄 추가)을 실행해 사업장을 손으로 만들지 않는다.
- US3. 개발자가 **순찰 실행** 작업으로 근무자의 순찰을 API로 대신 돌리고, 현장 웹 화면에서 결과를 확인한다(정상 완료 · 미인증 · 도중 종료 · 특이사항 · 시간초과 · 교대).
- US4. 개발자가 **배치 요청 · 복귀 요청**을 근무자 대신 보낸다(승인 · 거절은 웹 화면에서 직접 한다).
- US5. 개발자가 실행 중인 작업과 **단계별 로그**를 보고, 중단하거나 남은 순찰을 정리한다.

## 1. 목적

현장 화면(대시보드 · 순찰이력 · 근무자 · 배치)은 **근무자가 앱에서 뭔가를 해야** 데이터가 생긴다. 지금은 사업장을 손으로 구축하고 앱으로 일일이 순찰해야 해서 화면 하나를 확인하는 데 시간이 많이 든다. 근무자의 앱 동작을 **API로 대신 실행하는 컨트롤러**를 만들어, 개발 · 테스트 중에 원하는 상황을 바로 만든다.

시간을 조작하지 않는다 — **실제와 같이 동작**한다(사용자 결정). 시간초과처럼 오래 걸리는 상황은 지점 제한 시간이 짧은 코스를 만들어 재현한다.

## 2. I/O

### Input

- 라우트: `/dev/simulator` — **개발 서버에서만 등록**(`import.meta.env.DEV`). 로그인 가드 밖
- 쿼리스트링: `?site={siteSeq}` — 고른 사업장
- env
  - `.env.real` — `VITE_APP_API_BASE_URL`(앱 서버 주소 · commit 대상)
  - `.env.real.local` — `VITE_SIM_ADMIN_ID` · `VITE_SIM_ADMIN_PW`(본사 계정) · `VITE_SIM_WORKER_PW`(근무자 공통 비밀번호). **git 제외**(`*.local`), 실서버 모드에서만 읽힌다
- 웹 API(본사 토큰 · 기존 dev 프록시 경유): `Login/W/Login` · `Login/W/sign/AdminSiteSelect` · `User/W/sign/UserList` · `Point/W/sign/GetPointList` · `Course/W/sign/GetCourseList` · (구축) `Site/W/sign/AddSite`
- 앱 API(근무자 · 현장관리자 토큰 · **브라우저에서 직접 호출**): [`docs/app-api-spec.md`](../../../docs/app-api-spec.md) §3 · §6

### Output

- 테스트 서버에 **실제 데이터가 생긴다**(지점 · 코스 · 근무자 · 순찰 회차 · 배치 신청)
- 화면: 사업장 선택 → 근무자 목록 + 작업 목록 → 작업 입력 창 → 실행 목록(상태 · 진행도 · 단계 로그)
- 저장하지 않는 것: 토큰(메모리에만) · 실행 기록(새로고침하면 사라진다)

## 3. 제약

### 기술 제약

- **운영 빌드 제외** — 라우트를 `import.meta.env.DEV` 로 감싸고 지연 로딩한다. `npm run build` 산출물에 시뮬레이터 코드가 없어야 한다
- **mock 모드에서는 동작하지 않는다** — `VITE_USE_MSW=true` 면 실행 대신 "`npm run dev:real` 로 띄워 주세요" 안내
- **앱 서버 CORS** — 허용 출처가 `http://123.2.156.229:5173` · `:5174` 둘뿐이다. `localhost` 로 열면 안내를 보인다
- 🔴 **기존 axios 인스턴스(`src/lib/axios.ts`)를 쓰지 않는다** — `localStorage` 토큰을 붙이고 401 에서 로그인 페이지로 보내므로, 다른 탭의 현장 화면 로그인을 건드린다. 시뮬레이터 전용 클라이언트 2개(웹용 · 앱용)를 둔다
- 🔴 **토큰은 메모리에만** 둔다(`localStorage` 금지 — 탭끼리 공유된다). 근무자 토큰은 `loginId → token` 맵으로 여러 개를 동시에 든다(교대 시뮬은 두 근무자가 번갈아 호출한다)
- 토큰 만료: 재발급 로직 없이 **401 이면 그 계정으로 다시 로그인 1회 → 재시도**
- 코드 위치: 페이지 `src/pages/dev/`, 기능 `src/features/simulator/`
- **UI 는 기존 시스템과 다르게 간다**(사용자 결정 2026-11-18 — 다음 프로젝트 대비 최신 흐름 적용)

| 항목 | 결정 |
|---|---|
| 컴포넌트 기반 | **Base UI**(`@base-ui/react`) — shadcn 의 새 기본(2026-07). 기존 화면은 Radix 그대로 |
| 스타일 | shadcn **Rhea**(촘촘한 간격 · 작은 둥근 모서리) |
| 색 | 기본 **Mist** · 강조 **Emerald** · **다크 고정** |
| 글꼴 | **Manrope**(영문 · 숫자) + Pretendard(한글) · 고정폭 **Geist Mono**(사번 · 번호 · 시각 · 로그) |
| 모서리 | 작게 — 줄(로그 · 표)은 각지게 |
| 실행 로그 | shadcn **`Trace`**(2026-10) — 단계 줄 · 실행 중 반짝임 · 펼침 |
| 상태 색 | 실행 중 = 강조색 + 반짝임 / 완료 = 회색 체크 / 실패 = 빨강 / 중단 = 주황 / 대기 = 흐린 회색 |

  - 컴포넌트는 `src/features/simulator/ui/` 에 **수동 이식**한다 — shadcn CLI 는 `--path` 를 줘도 `src/components/ui/button.tsx` 를 덮어쓰려 했다(dry-run 확인 2026-11-18). 출처: `https://ui.shadcn.com/r/styles/base-rhea/{name}.json`
  - 색 · 모서리 · 글꼴 토큰은 **`.sim-root` 범위에서만** 덮는다 — `src/index.css` 의 값은 바꾸지 않는다. 팝업(선택 목록 · 입력 창)이 `body` 에 그려지므로 페이지가 떠 있는 동안 `<html>` 에 `sim-root dark` 클래스를 붙였다가 뗀다
  - `design-system.md` · `components.md` 의 규칙은 **이 페이지에 적용하지 않는다**(개발 전용 · 의도적 예외). 그 문서들도 고치지 않는다
- 새 의존성: `@base-ui/react` · `@fontsource-variable/manrope` · `@fontsource-variable/geist-mono` — 지연 로딩 청크에만 들어간다

### 비즈니스 규칙 (실측 — `app-api-spec.md` §3)

- **대상 근무자** = 고른 사업장의 근무자 전원. 공통 비밀번호로 로그인을 시도하고, 안 되면 **"로그인 불가"** 로 표시해 작업 대상에서 뺀다
- 아이디는 숫자 6자리. 새 근무자는 **그 사업장 근무자의 가장 큰 번호 다음부터** 만든다
- **순찰은 실행 엔진 하나**다 — 지점 줄마다 상황(미인증 · 특이사항 · 시간초과 · 교대 · 종료)을 켠 **계획**을 실행한다. 상단 프리셋은 정해진 자리에 한 번에 얹는 지름길이다(섞을 수 있다)
- 🔴 **상황은 그 줄에서 일어난다**(사용자 결정 2026-11-18) — 교대 · 종료는 **그 지점을 처리한 뒤**다. 웹 대시보드가 교대를 직전 인증 지점(`lastOrderNo`)에 표시하므로 입력한 줄과 화면의 자리가 같아진다. 첫 지점보다 앞의 일(시작하자마자 교대 · 인증 0개 종료)은 **"순찰 시작" 줄**에 둔다. 마지막 지점은 처리하는 순간 순찰이 닫혀 교대 · 종료를 둘 수 없다
- 인증은 **순서대로만** 된다. 메모가 없으면 **메모 필드를 빼고** 보낸다(빈 문자열은 400). 메모는 지점 줄당 하나
- 인증값은 지점 상세의 `qrCode`(QR) · `nfcTagId`(NFC)를 그대로 보낸다. **인증값이 없는 지점은 "인증"을 고를 수 없다**(건너뛰기만)
- 교대는 코스의 교대 허용이 켜져 있어야 한다. **멈춘 시간은 실제 경과 시간을 재서 보낸다**(서버가 재지 않는다). 새 코스는 교대 허용을 기본으로 켠다
- 인증 간격은 초 단위 입력(기본 10초). 시간초과 프리셋만 지점 제한 시간을 넘겨 기다린다
- 상단 프리셋은 **지금 계획 위에 얹는다**(자리: 미인증 = 가운데 지점 / 특이사항 = 첫 인증 지점 / 시간초과 = 첫 지점 / 교대 · 도중 종료 = 가운데 지점의 앞 지점 뒤). "정상 완료"만 처음으로 되돌린다. 교대는 요청 → **5초 멈춤** → 수락 순서로 돌고, 멈춘 시간은 실제로 잰 값을 보낸다
- 순찰을 맡길 수 있는 근무자는 **로그인되고 지금 순찰 중이 아닌** 사람, 코스는 **사용 중 · 지점 있음 · 대기중**인 것만 고를 수 있다
- 쓰기 응답에 만든 것의 번호가 없다 — **추가 뒤 목록을 다시 읽어** 찾는다
- 구축 쓰기는 **본사 토큰 + 웹 API** 로 한다(현장관리자가 없는 사업장도 구축할 수 있다). 🔴 웹 `AddCourse` 는 지점을 무시하므로(B-27) 코스는 **추가 → 번호 찾기 → `UpdateCourse` 로 지점 편성** 순서로 만든다
- 배치는 **요청만** 보낸다. 승인 · 거절은 웹 화면에서 한다(그 화면이 테스트 대상이다)
- 🔴 **근무자 한 명에 대한 동작은 그 근무자 줄에서 한다**(사용자 결정 2026-11-18) — 근무 스위치 · 배치 요청 · 복귀 요청 · 순찰 종료. 줄에는 **지금 상태에서 할 수 있는 것만** 보인다(원 소속 = 배치 요청 / 배치 중 = 복귀 요청 / 승인 대기 = 없음 / 순찰 중 = 순찰 종료). 드롭다운으로 근무자를 고르는 작업은 두지 않는다. 전체 근무 시작 · 종료는 이미 그 상태인 사람을 건드리지 않는다
- 여러 작업을 동시에 실행할 수 있다. 실패하면 **그 실행만 멈추고 재시도하지 않는다**(서버 응답을 로그에 그대로 보인다). 중단 · 새로고침으로 서버에 남은 순찰은 "진행 중 순찰 종료" 작업으로 닫는다
