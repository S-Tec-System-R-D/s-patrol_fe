## User Stories

- US1. 현장관리자가 대시보드를 열어 두면, 앱에서 순찰이 **시작 · 지점 인증 · 교대 요청 · 교대 · 종료**될 때 새로고침 없이 카드가 바뀐다.
- US2. 순찰이 끝나거나 지점이 찍히면 **오늘 숫자 · 최근 미완료/시간초과**도 따라 바뀐다.
- US4. 순찰이 끝나면 카드가 사라지는 대신 **`최근 종료된 순찰`** 에 나타나, 여러 순찰이 동시에 돌 때도 무엇이 끝났는지 안다(사용자 요청 2026-11-04 — 실서버 확인 중 나온 추가).
- US3. 머리에서 **실시간 연결 상태**(연결됨 / 다시 연결 중)를 본다. 끊겨도 저절로 다시 붙고, 붙으면 놓친 사이를 메운다.

## 2. I/O

### 연결

| 항목 | 값 |
|---|---|
| 주소 | `{VITE_SSE_BASE_URL}/api/v1/Sse/subscribe` — env **신설**. `.env.real` 에만 테스트 SSE 서버(`:5258`)를 넣고, 비어 있으면 **같은 출처**(운영 = 같은 도메인 · mock = MSW) |
| 방식 | `fetch` 스트림 + `Authorization: Bearer` 헤더(`EventSource` 는 헤더를 못 붙이고, 쿼리 토큰은 주소에 남는다) |
| 수명 | **대시보드 화면에 있는 동안만** 연결 — 화면을 떠나면 끊는다. 사업장 전환은 화면이 다시 마운트되며 다시 붙는다(061 `key={siteSeq}`) |
| 재연결 | 끊기면 서버가 준 `retry`(10초) 뒤 다시 연결 |
| 401 | 기존 axios 재발급(single-flight)으로 토큰을 새로 받아 즉시 다시 연결. 재발급 실패는 기존 인증 실패 처리(로그아웃) |
| 개발 | 실서버는 **IP 주소로 연다**(`vite --host` 는 이미 켜져 있음 — CORS 허용 출처가 개발 PC IP + `:5173` 하나). mock 은 `localhost` 그대로 |

### 이벤트 → 화면 (아래 공통 필터를 통과한 것만)

- 공통 필터: `data.siteSeq` ≠ 지금 사업장 → 버림 · `link` ≠ `"Patrol"` → 버림.

| 이벤트 | 처리 | 부르는 조회 |
|---|---|---|
🔴 **알림은 "무엇이 바뀌었다" 신호로만 쓰고, 화면 값은 전부 다시 받는다**(사용자 결정 2026-11-03 — §3 "알림 반영").

| 이벤트 | 다시 받는 것 |
|---|---|
| `connected` | 연결 상태 = 연결됨. **진행 중 목록**. 재연결(두 번째 이후)이면 오늘 숫자 · 최근 기록 · 최근 종료도 |
| `course-started` | 진행 중 목록 |
| `course-paused` | 진행 중 목록 |
| `course-handover` | 진행 중 목록 |
| `point-checked` | 진행 중 목록 + 오늘 숫자 · 최근 기록 · 최근 종료 |
| `course-ended` | 진행 중 목록 + 오늘 숫자 · 최근 기록 · 최근 종료 |

### 화면

- 머리(`DashboardUpdatedAt` 옆)에 **연결 상태** — `실시간`(연결됨) / `다시 연결 중`. 연결 전 첫 순간은 `다시 연결 중` 과 구분하지 않는다(짧다). 새로고침 버튼은 068 그대로.
- 🔴 **`마지막 갱신` = 영역 중 가장 최근에 데이터를 받은 시각**(사용자 결정 2026-11-04) — 새로고침 때만 바뀌면 `실시간` 인데 옛 시각이 보인다. 실패한 조회는 시각을 바꾸지 않는다.
- 새로고침 버튼은 5개 영역 다시 받기만 한다(연결은 건드리지 않는다).

### 최근 종료된 순찰 (사용자 결정 2026-11-04)

- 자리: 진행 중인 순찰 바로 아래, 전체 폭. 행 = 종료 시각 · 코스 · 순찰자 · 인증 수 · 소요 시간 · 결과 뱃지(완료 / 미완료) · 시간초과. 누르면 회차 상세, `전체 보기` = 코스 순찰이력.
- 데이터: `GetCourseHistory` 를 **어제~오늘 · 100건** 받아 화면이 **오늘 끝난 회차 · 종료 시각 순 · 앞 5건**으로 고른다.
  - 🔴 서버는 **시작 순**이다(실측 2026-11-04 회차 81~97) — 앞 5건만 받으면 오래 걸린 순찰이 빠진다. 100건 = 서버 상한(200 은 400).
  - 기간을 어제부터 받는 이유: 자정을 넘긴 순찰도 오늘 끝났으면 보여야 한다.
  - 진행 중 회차는 `status` · `endDt` 로 거른다(거르지 않은 조회에 섞이는지는 미측정이라 기대지 않는다).
- 🟡 `완료` 인데 `2/5`(건너뜀) · `0/2` 가 실존한다(실측) — 인증 수에 색을 입히지 않고 서버 값 그대로 쓴다.
- 🟡 교대 받은 사람이 `userList` 에서 빠진다(§5-1-D) — 행마다 추가 호출하지 않고 서버 수정을 요청한다.

### 타입

- §5-1-D "5. SSE data" 그대로 — `SseEventBase` · `PointCheckedEvent` · `CourseHandoverEvent` · `CourseEndedEvent`. 어댑터 없음.
- 알림 뒤 조회(`GetCourseStart` · `GetPointChecked` · `GetCoursePaused` · `GetCourseHandover` · `GetCourseEnded`)는 **쓰지 않는다** — 타입도 두지 않는다.

## 3. 제약

### 기술 제약

- 스트림 읽기 · 줄 파싱(`event:` · `data:` · `id:` · `retry:` · `:` 주석 · 빈 줄 = 메시지 끝 · **청크가 줄 중간에서 끊김**)은 패키지 없이 작은 함수로 둔다 — `src/lib/sse/`(인프라). 이벤트 처리 · 훅은 `features/dashboard/realtime/`.
- 401 재발급 재사용을 위해 `src/lib/axios.ts` 의 재발급 함수를 **export 만** 한다(동작 변경 없음).
- 캐시는 **고치지 않는다** — 다시 받기(`invalidateQueries`)만 한다.
- 다시 받기는 **몰리면 묶는다** — 마지막 알림 뒤 **0.5초** 기다렸다 영역마다 한 번. 건너뛰기는 지점마다 알림이 한꺼번에 오고(4번을 찍으면 1~3 건너뜀 + 4 인증), 마지막 지점 인증과 자동 종료도 같은 순간에 온다(B-64).
- `eventDt`(타임존 붙음 — B-67)는 쓰지 않는다. 순서 판단에 쓰지 않는다.
- mock: `src/mocks/handlers/` 에 SSE 핸들러 — `retry` + `connected` 를 보내고 연결을 열어 둔다(이벤트 없음).

### 알림 반영 — 전부 다시 받기 (사용자 결정 2026-11-03 · OQ-069-A · OQ-069-B)

§5-1-D 방침은 알림마다 따로 처리하는 것이었다(지점 인증 → 지점 색만 바꾸기 · 멈춤 → 그 카드 경과 멈춤 · 교대 → `GetCourseHandover` · 종료 → 카드 지우기). 이 spec 은 **전부 진행 중 목록을 다시 받는다**.
- **지점 인증**: 알림에 "다음 지점"이 없다. 찍으면 서버가 다음 지점을 `status 1` 로 바꾸는데 그 알림은 오지 않는다 — 찍은 지점만 바꾸면 카드의 `다음: 지점명` 이 사라진다. 화면에서 짐작하면 서버 규칙을 추측하게 된다(A1).
- **멈춤 · 교대 · 종료**: 경과 시간은 목록 전체가 **받은 시각 하나**를 기준으로 센다(068). 캐시를 고치면 받은 시각이 바뀌어 다른 카드의 경과가 틀어지고, 카드 하나만 멈추려면 카드마다 기준 시각을 들고 있어야 한다.
- 목록을 다시 받으면 `status` · `elapsedSec` · `pausedYn` · `users` · `handoverCount` 가 서버 값으로 한 번에 맞는다. 시작 이벤트 없이 다시 열린 회차(B-65 · C1)도 저절로 카드가 생기고, 순서 뒤바뀜(B-64)도 문제가 되지 않는다.
- 비용: 지점 인증 1번에 목록 조회 1번(+ 묶인 오늘 숫자 · 최근 기록). 열린 대시보드 수만큼 곱해진다.

### 비즈니스 규칙

- **이벤트 순서 · 내용에 기대지 않는다** — 알림은 다시 받을 영역만 정한다.
- 지점 단계 · 경과 · 시간초과 계산은 068 그대로(서버 `status` · `elapsedSec` · `totalMin 0` = 기준 없음).

## 4. 엣지 케이스

공통 규칙 따름. 화면 고유:
- 시작 이벤트 없이 다시 열린 회차(B-65 · C1 — 회차 91) → 첫 지점 인증 알림의 목록 다시 받기로 카드가 생긴다.
- `data` 가 JSON 이 아니거나 모르는 이벤트 이름 → 버린다.
- 연결 중 토큰 만료(3시간) → 서버가 끊거나 다음 연결이 401 → 재발급 후 다시 연결.
- 다시 연결 중에도 화면은 마지막 데이터 그대로 둔다(지우지 않는다). 경과는 계속 센다.
- 되돌린 교대(B-68 · C4)는 `handoverCount 0` 으로 와 `교대` 뱃지가 안 붙는다 — 서버 값 그대로(068 과 같다).
