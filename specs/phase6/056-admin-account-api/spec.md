## User Stories

- **US1.** 본사 관리자가 `/admin/admins` 에서 트리로 고른 그룹의 관리자 목록을 본다(이름 · 권한 · 연락처 · 담당 그룹). 요청 1개로 그린다.
- **US2.** 행을 눌러 상세 모달에서 사번 · 연락처와 담당 그룹을 본다. 마스터는 "전체 그룹" 이다.
- **US3.** 시스템관리자는 마스터를, 마스터는 매니저를 **추가**한다(매니저는 담당 그룹 필수).
- **US4.** 상세 모달에서 **정보 수정 · 비밀번호 변경 · 삭제**한다 — 시스템관리자 = 전원 · 마스터 = 본인 + 매니저 · 본부 매니저 = 본인 + 아래 지사 매니저 · 지사 매니저 = 본인(본인은 삭제 없음).
- **US5.** 시스템관리자 · 마스터가 매니저의 **담당 그룹을 추가 · 해제**한다(`UpdateAdmin`).

본 spec 은 관리자 화면을 그 API 위로 옮기고 막힌 기능을 연다. 담당 관리자 · 비상연락망(사업장 상세)은 057.

## 2. I/O

### 2-1. API (`api-spec.md` §5-1-C)

| API | 요청 | 응답 `data` | 쓰는 곳 |
|---|---|---|---|
| `GET Login/W/sign/AdminSiteSelect` | — | `GroupNode`(그대로) | 좌측 트리 · 그룹 경로 · 사업장 수 · 담당 그룹 고르기 |
| `GET AdminUser/W/sign/GetAdminList` | — | `AdminGroupNode`(루트 하나) | 목록 행 · 그룹 범위 · 트리 수 |
| `GET AdminUser/W/sign/GetAdminDetail` | `?userSeq` | `AdminDetail` | 상세 모달 사번 · 🔴 할당 변경 직전 다시 읽기(캐시 거치지 않음) |
| `POST AdminUser/W/sign/AddAdmin` | `{codeSeq, loginId, loginPw, name, phone, groupSeq?}` | `true` | 추가 |
| `PUT AdminUser/W/sign/UpdateAdmin` | `{userSeq, name?, phone?, groupSeq?}` | `true` | 정보 수정 · 담당 그룹 추가 · 해제 |
| `PUT AdminUser/W/sign/ResetAdminPassword` | `{userSeq, loginPw}` | `true` | 비밀번호 변경 |
| `DELETE AdminUser/W/sign/DeleteAdmin` | `?userSeq` | `true` | 삭제 |

- 타입은 `api-spec.md` §5-1-C 그대로(`AdminListItem` · `AdminGroupNode` · `AdminDetail`). 어댑터 없음.
- 🔴 상세 화면에 쓰던 `UserDetail` 은 **부르지 않는다** — 연락처는 목록 행, 사번은 `GetAdminDetail`.
- 🔴 **생성 · 변경은 ID 를 주지 않는다** → 성공 후 목록 재조회(비옵티미스틱).
- `UpdateAdmin` 은 **보낸 필드만** 바뀐다 · `groupSeq` 는 그 관리자의 할당 **교체**(실측).

### 2-2. 목록 (US1)

- 행 = `GetAdminList` 노드를 훑어 `userSeq` 로 중복 제거 · 🔴 **`codeSeq 2`(시스템관리자) 제외**.
- **그룹 범위**(사용자 결정 2026-10-28):
  - 🔴 **회사(최상위, `parentGroupSeq: null`)를 고르면 전원**(시스템관리자 제외).
  - 🔴 **본부 · 지사는 그 그룹 + 하위 그룹에 할당된 매니저만** — 전체 담당 마스터 · 상위 그룹에 할당된 매니저는 나오지 않는다. 서버 노드 `admins`(상속 기준)는 범위에 쓰지 않는다.
- 트리 옆 수 = 같은 규칙의 인원.
- 열: 이름 · 권한 · **연락처**(`formatPhone`, 2026-10-28) · 담당 그룹. 좁은 폭 카드도 같은 4개. 🔴 담당 그룹 = `allGroupYn` 이면 **`전체`** · 아니면 `groups` 를 트리 노드로 바꿔 045 표기(`본부 › 지사` + `외 N개` / `-`).
- 검색 `?q=` · 권한 `?role=` · 빈 상태 2종 · 총 N명은 045 그대로.

### 2-3. 상세 모달 (US2)

- 머리 · 담당 그룹 묶음(`assignmentSections`)은 045 그대로. 기본 정보 = **사번**(`GetAdminDetail` — 조회 중 스켈레톤 · 실패 시 그 칸만 [다시 시도]) · **연락처**(목록 값). 너비 **520px**.
- 마스터(`allGroupYn`): 담당 그룹 칸에 **"전체 그룹"** 한 줄 · [그룹 추가] · 해제 없음.
- 하단 [삭제] · [비밀번호] · [수정] — **관리 권한이 있을 때만**(§3 규칙 3). 없으면 하단 줄이 없다. 본인은 [삭제] 없이 [비밀번호] · [수정].

### 2-4. 추가 · 수정 · 비밀번호 · 삭제 (US3 · US4)

### 2-5. 담당 그룹 추가 · 해제 (US5)

- 대상: **매니저만**. 할 수 있는 사람: 시스템관리자 · 마스터(045 그대로).
- 고르기 UI는 045 `AssignGroupDialog` · `GroupPicker` 그대로. 해제도 045 모양 그대로.
- 저장: 🔴 **PUT 직전에 `GetAdminDetail` 로 현재 `groupSeq` 를 다시 읽고** `UpdateAdmin {userSeq, groupSeq: 현재 ∪ 고른 것 / 현재 − 해제}`. 읽기가 실패하면 보내지 않는다(045 B-50 원칙 승계 — 화면 캐시로 보내면 그 사이 바뀐 할당을 지운다).
- 여러 그룹 추가는 **요청 1번**(배열 교체)이다 — 045 의 "그룹마다 차례로 · 첫 실패에서 중단" 은 없어진다.
- 🔴 **마지막 담당 그룹은 해제할 수 없다** — 매니저는 담당 그룹 필수(045 결정)인데 서버는 `[]` 를 받는다(실측). 하나 남으면 해제 버튼을 막고 툴팁 "매니저는 담당 그룹이 하나 이상 있어야 합니다".
- 045 의 "마스터 자기 해제 확인창" 은 **없앤다** — 마스터에게는 할당 조작이 없다.

### 비즈니스 규칙

1. **시스템관리자(`codeSeq 2`)는 화면에 없다** — 목록 · 수 · 상세 모두(사용자 결정 2026-10-27).
2. **사번은 표시하지 않는다** — 추가 폼의 사번 입력은 그대로(로그인 ID).
3. 🔴 **권한**(B-60 서버 검사 없음 — 화면이 막는다):
   - **추가**: 시스템관리자 → 마스터 · 마스터 → 매니저 · 매니저 → 없음(사용자 결정 2026-10-27, 2026-10-28 유지).
   - **수정 · 비밀번호 · 삭제**(사용자 결정 2026-10-28 — 처음의 "만들 수 있는 대상과 같다" 를 뒤집음): 시스템관리자 = 마스터 · 매니저 전원 · 마스터 = 본인 + 매니저 전원 · **본부 매니저**(담당에 본부 `layer 1`) = 본인 + 담당 그룹이 **전부** 내 본부 아래 지사인 매니저 · 지사 매니저 = 본인만. 🔴 **본인은 삭제할 수 없다**(수정 · 비밀번호만).
   - **담당 그룹 추가 · 해제**: 시스템관리자 · 마스터가 매니저에게만(그대로 — 2026-10-28 확인).
4. **마스터 = 전체 그룹** — 할당 조작 없음.
5. **매니저 담당 그룹 ≥ 1** — 추가 폼 필수 · 마지막 그룹 해제 막음.
6. **할당 PUT 직전 다시 읽기** — 읽기 실패 시 보내지 않는다.
7. 회사(루트) 그룹은 고르기 선택지에 없다(OQ-045-A 그대로).
