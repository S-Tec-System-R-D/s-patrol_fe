## 🔴 범위

- **바꾸는 것**: 영역 배치 · KPI 모양 · 진행 중 카드 모양 · 최근 기록(회차 단위 미완료 + 종료된 순찰을 한 패널로) · 배치 대기 패널 신설(대시보드에서 승인 · 반려).
- **바꾸지 않는 것**: 실시간 연결 · 새로고침 · `마지막 갱신` · 공지 패널 내용 · 좁은 화면 메뉴 위치(아래 그대로).
- **시안과 다르게 하는 것**(사용자 결정 2026-11-11):
  - KPI **보조 줄 없음**(`오늘 8건 중` · `어제 N건` — 서버에 없는 값).
  - KPI 는 전체 폭 띠가 아니라 **xl 에서 절반 폭 카드 하나**. 같은 줄 오른쪽은 **배치 대기**.
- 대시보드 밖 항목(분석 문서 §1 공통 · §2 다른 화면)은 **범위 밖** — 목록 · 테이블 정리 작업으로 따로 한다.

## User Stories

- US1. 현장관리자가 대시보드 첫 화면에서 **오늘 숫자**(진행 중 · 완료 · 미완료 · 시간초과)와 **처리할 배치 요청**을 한 줄에서 본다.
- US2. 배치 요청 · 복귀 요청을 **배치관리로 가지 않고** 대시보드에서 승인 · 반려한다.
- US3. 진행 중인 순찰을 카드로 보고, 시간초과 · 교대 · 다음 지점을 카드 안에서 바로 안다.
- US4. 최근 미완료 · 시간초과를 **순찰 1건 = 1행**으로 보고, 놓친 지점 이름을 그 행에서 읽는다.
- US5. 최근 종료된 순찰을 미완료 목록 옆에서 함께 보고, 인증 수를 막대로 읽는다.

## 1. 목적

067~070 의 대시보드는 영역이 위아래로 길게 이어지고 넓은 화면에서 값이 흩어진다(분석 문서 §1-1). **"지금 손써야 할 것"** — 진행 중 · 처리 필요 · 배치 대기 — 을 첫 화면에 모으고, 끝난 기록은 한 패널로 줄인다.

## 2. I/O

### 배치 (xl ≥ 1280)

2열 **1 : 1**.

| 왼쪽 열 | 오른쪽 열 |
|---|---|
| KPI 카드 | 배치 대기 패널 |
| 진행 중인 순찰 | 공지사항 |
| 최근 기록 | |

- 진행 중 카드는 열 폭이 절반이라 **1열**(카드 하나 = 열 폭). `2xl`(1536) 이상에서 2열.
- 최근 기록도 같은 이유로 **탭**(미완료 · 시간초과 / 종료된 순찰 + 숫자 뱃지). `2xl` 이상에서 두 목록을 세로선으로 나란히.
- xl 미만: 한 열 — **KPI → 진행 중 → 배치 대기 → 최근 기록 → 공지**.

### 데이터

| 영역 | 출처 | 바뀌는 점 |
|---|---|---|
| KPI 4칸 | 진행 중 = `GetDashboardCourseList` **개수** · 완료 · 미완료 · 시간초과 = `GetTodaySummary` | 배치 숫자 2칸(`pendingAssignmentCount` · `pendingReturnCount`)은 KPI 에서 빼고 배치 대기 패널 제목 숫자로 |
| 진행 중 | `GetDashboardCourseList` + 교대 조회(070) | 모양만 |
| 배치 대기 | `GetAssignmentList` · `GetAssignmentReturnList`(배치관리와 같은 쿼리) | **신규 영역**. 대기 일수 = 오늘 − `createDt`(일) |
| 승인 · 반려 | `AssignmentApprove` · `AssignmentReturnApprove`(`useApproveDeployment`) | 버튼 · 확인 창 · 무효화는 배치관리(`DeploymentRequestActions`) 그대로 — **승인은 즉시 · 반려만 확인 창** |
| 최근 미완료 · 시간초과 | 🔴 **`GetCourseHistory`(최근 종료와 같은 100건 쿼리)에서 `status 2 미완료` 또는 `overtimeYn` 인 회차** | `GetDashboardPointHistory` 2번 호출 → **목록 요청 0건 추가**. 놓친 지점 = 행마다 `CheckDetails(historySeq)` 1번(최대 5건) |
| 종료된 순찰 | 같은 100건 쿼리(069) | `완료` 뱃지 대신 미니 막대 + `checkedCount / pointCount` |
| 공지 | 그대로 | — |

### Output

- 승인 · 반려 성공 → 배치 대기 패널 · 배치관리 쿼리 무효화 + 토스트(배치관리와 같은 문구).
- 행 클릭: 미완료 · 종료 행 → 회차 상세(`/patrol/zones/:historySeq`). 배치 대기 행 → 이동 없음(버튼만). 패널 머리 `배치관리 ›` · `전체 보기 ›` 링크.

## 3. 제약

### 기술

- 재사용: `useApproveDeployment` · `useDeploymentRequests` · `useReturnRequests` · `useCourseHistoryCheckDetails` · `AppBadge` · `AppEmpty` · `AppDialog`.
- 영역마다 쿼리 · 오류 · 다시 시도가 따로다(068 규약 그대로). 배치 대기가 실패해도 KPI 는 그린다.
- 실시간(069): `point-checked` · `course-ended` 때 최근 기록을 다시 받는 대상이 `GetDashboardPointHistory` 에서 **100건 쿼리 하나**로 바뀐다. 놓친 지점 조회도 함께 다시 받는다.
- 배치 요청은 SSE 이벤트가 없다 — **열 때 · 새로고침 · 승인/반려 후**에만 갱신.

### 비즈니스

- KPI 색은 **미완료 · 시간초과 숫자에만**, 값이 0 이면 회색.
- 미완료 행: 시각 · 코스명 · 순찰자를 왼쪽에 붙이고, 뱃지만 오른쪽(분석 §1-1 — 넓은 화면에서 흩어지지 않게).
- 최근 미완료의 기간 = **어제 ~ 오늘**(100건 쿼리와 같다). 지금(지점 이력 최근 N건)보다 짧아진다 — 대시보드는 "오늘 손쓸 것" 이라 받아들인다(🟡 사용자 확인 대기).
- 놓친 지점 = 상세의 지점 상태가 **미인증 · 건너뜀**인 것(순찰제외는 넣지 않는다). 조회 실패 시 그 행은 이름 없이 `미완료 N` 뱃지만.
- 반려는 사유 입력 없음(배치관리와 같다 — 서버에 사유 필드 없음).

---

## 4. 엣지 케이스

공통 규칙 따름. 이 화면 고유 3가지:
- 배치 대기 0건 → 패널은 남기고 빈 상태 한 줄(첫 줄 오른쪽이 비지 않게).
- 진행 중 0건 → 지금과 같은 빈 상태.
- 승인 · 반려 연타 → 진행 중 버튼 잠금(`useApproveDeployment` 의 pending).
