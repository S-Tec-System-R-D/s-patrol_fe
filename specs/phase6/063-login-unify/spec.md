## User Stories

- US1. 현장 로그인 화면은 랜딩(`/`) 하나다. 로그인이 필요한 모든 경로(가드 · 로그아웃 · 토큰 만료 · 403/404 의 홈)가 `/` 로 간다. 예전 주소 `/login` 은 `/` 로 넘어간다.
- US2. 본사 로그인(`/admin/login`)도 랜딩과 **같은 분할 디자인**이다.
- US3. 로그인 화면과 계정 사이트가 다르면 막는다 — 본사 화면의 현장관리자 → 안내 + 현장 로그인 링크, 현장 화면의 본사 계정 → "관리자 계정" 안내만(구현 중 추가 — 사용자 결정 2026-10-30).

---

## 1. 목적

062 로 `/` 가 로그인 겸 소개가 되면서 `/login` 과 화면이 둘이 됐다. 현장 로그인을 `/` 하나로 합치고, 본사 로그인도 같은 모양으로 맞춘다.

---

## 2. I/O

### 결정 (사용자 확정 2026-10-30)

| 항목 | 결정 |
|---|---|
| `/login` | **없앤다.** 들어오면 `/` 로 넘긴다(즐겨찾기 보존) |
| 현장 로그인 경로 | `paths.serviceLogin` = **`/`** — 가드 · 로그아웃 · 401 이동 · 403/404 홈이 한 상수를 쓴다 |
| `/admin/login` | 랜딩과 같은 분할 디자인(xl 좌우 · 미만 왼쪽 반 크기). 제목 **S-Patrol** 굵게 + 옆에 **`관리자` 배지**(구현 중 추가 — 사용자 결정) · 안내 문구는 본사용 |
| 본사 슬라이드 | 현장과 **같은 4장**(서비스 소개) |
| 다른 사이트 계정 | **막는다**(020 의 "착지는 code · 화면 무관" 을 뒤집음). 본사 화면 + 현장관리자 → "현장관리자 계정은 현장 로그인을 이용해주세요" + `/` 링크. 현장 화면 + 본사 계정 → "관리자 계정입니다. 관리자 로그인 주소로 접속해주세요."(링크 없음 — 본사 주소 비노출). 토큰 저장 안 함 |

### Output
- `/` · `/admin/login` 이 같은 틀(분할 카드)을 쓴다 — 차이는 안내 문구뿐.
- 화면 가운데 작은 카드(`LoginForm` 틀)는 쓰는 곳이 없어져 지운다.

---

## 3. 제약

- 로그인 처리 · 착지는 그대로(`LoginPanel`) — 단 화면(`area`)과 계정 사이트가 다르면 막는다(US3). 판정은 `resolveLoginOutcome(code, area)` 한 곳.
- `?redirect=` 는 지금처럼 붙이기만 한다(읽는 곳 없음 — 범위 외).
