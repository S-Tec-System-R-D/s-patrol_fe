## User Stories

- **US1.** 본사 관리자가 사업장 상세에서 이 사업장을 맡은 **매니저**를 본다(조회만).
- **US2.** 본사 관리자가 사업장 상세에서 **요일별 비상연락 담당자**를 보고, 요일마다 담당자를 **추가 · 해제**한다.
- **US3.** 사업장 목록에 값 없는 담당 관리자 열이 없다.

## 1. 목적

044 · 048 은 서버에 사업장 담당 관리자 · 비상연락망이 없어 대신값과 예시 화면을 두었다. 백엔드가 `GetSiteManagerList` · `Emergency` 4종을 열었다(B-57 · B-58 반영). 본 spec 은 두 카드를 실제 API 로 바꾸고 자리만 있던 목록 열을 지운다.

## 2. I/O

### 2-1. API (`api-spec.md` §5-1-C)

| API | 요청 | 응답 `data` | 쓰는 곳 |
|---|---|---|---|
| `GET Site/W/sign/GetSiteManagerList` | `?siteSeq` | `SiteManager[]` | 담당 관리자 카드 |
| `GET Emergency/W/sign/GetEmergency` | `?siteSeq` | `EmergencyDayEntry[]`(항상 7개) | 요일별 담당자 |
| `GET Emergency/W/sign/GetEmergencyUserTree` | — | `EmergencyTreeNode[]` | 담당자 추가 모달(후보) |
| `POST Emergency/W/sign/AddEmergency` | `{siteSeq, userSeq, day}` | `true` | 추가 |
| `DELETE Emergency/W/sign/DeleteEmergency` | `?siteSeq&userSeq&day` | `true` | 해제 |

- 타입은 `api-spec.md` §5-1-C 그대로. 어댑터 없음. 🔴 `assignmentType` 은 무시(백엔드 확인).
- 🔴 등록 · 삭제는 **한 사람 · 한 요일씩**이다. 같은 등록을 반복해도 중복이 생기지 않는다(멱등 — 실측).
- 🔴 후보 트리는 **사업장 · 요일과 무관**하다 — "그 요일에 이미 등록됨" 은 `GetEmergency` 와 대조해 화면이 정한다.

### 2-2. 담당 관리자 카드 (US1)

- 행 = `GetSiteManagerList` 중 🔴 **매니저(`codeSeq 4`)만** — 시스템관리자 · 마스터는 모든 사업장에 똑같이 나와 구분이 안 된다(사용자 결정 2026-10-28, 056 목록과 같은 판단).
- 행 모양은 048 그대로(이름 + 권한 뱃지 · 왼쪽 포인트 바). 뱃지 라벨은 `adminRoleLabel`(매니저).
- 머리 오른쪽 `N명`. 0명 → "지정된 담당 관리자가 없습니다". 실패 → 048 실패 표시 + [다시 시도].
- 🔴 [관리자 지정] · API 미지원 안내는 **없앤다** — 담당은 관리자 메뉴의 담당 그룹으로 정해진다(설명 한 줄: "관리자 메뉴에서 지정한 담당 그룹으로 정해집니다.").

### 2-3. 비상연락망 카드 (US2)

- 설명 줄은 048 그대로("헬스체크 이상 감지 시 요일별로 지정된 담당자에게 알림이 발송됩니다."). 예시 안내 · 담당자 풀은 **없앤다**.
- 요일 7행(월~일, 토 · 일 빨강 — 048 그대로). 행마다 담당자 칩(이름 · 권한 · 연락처) + 칩 [×] 해제 + [추가].
- 머리 오른쪽 = 7요일 중 하루라도 등록된 사람 수 "담당자 N명"(중복 제거).
- 해제: 칩 [×] → `DeleteEmergency` · 확인창 없음(045 할당 해제와 같다) · 처리 중 그 칩 비활성 · 토스트 "비상연락 담당자에서 해제했습니다."

### 2-4. 담당자 추가 모달 (US2)

- [추가] → `AppDialog` 520px "{요일}요일 담당자 추가" / "알림 받을 담당자를 선택합니다."
- 후보 = `GetEmergencyUserTree` 를 트리로(단계 들여쓰기 · 노드 이름 머리) · 사람은 체크박스(이름 · 권한 · 연락처).
  - 🔴 **시스템관리자(`codeSeq 2`) 제외**(사용자 결정 2026-10-27). 사람이 0명인 노드는 숨긴다.
  - `ROOT` = "전체 관리자"(마스터) · `GROUP` = 매니저 · `SITE` = 현장관리자 · 근무자 · `UNASSIGNED` = 담당 그룹 없는 매니저.
  - 🔴 근무자가 배치 중이면(`assignmentYn`) 이름 옆 뱃지 **"배치 중 · {assignedSiteName}"**.
  - 🔴 **그 요일에 이미 등록된 사람은 체크 · 잠금**.
  - 검색: 이름 부분 일치 — 맞은 사람과 그 노드 경로만 남긴다.
- [추가 (N)] → 고른 사람마다 **차례로** `AddEmergency` · 🔴 첫 실패에서 멈춘다(045 와 같다) · 성공 → 닫기 · 토스트 "비상연락 담당자를 추가했습니다." · 실패 → 모달 유지(토스트 전역).
- 한 사람이 트리 여러 곳에 나올 수 있다면(실측은 한 곳) `userSeq` 로 같이 체크된다.

### 2-5. 사업장 목록 (US3)

- 열 `담당 관리자` 삭제 → 사업장명 · 소속 그룹 · 주소 · 꺾쇠.

### 2-6. 무효화

- 추가 · 해제 성공 · 실패 모두 그 사업장 `GetEmergency` 재조회(비옵티미스틱 — ID 를 주지 않는다). 후보 트리는 바뀌지 않아 그대로.
- 관리자 계정 변경(056)이 담당 관리자 카드에 보이게 `GetSiteManagerList` 키를 056 무효화에 더한다.

## 3. 제약

### 기술 제약

- 신설: `features/sites/api/getSiteManagerList.ts` · `features/emergency/`(api 4 · types · queryKeys · hooks · 추가 모달 · 트리 순수 함수).
- 교체: `SiteManagersCard`(출처 · 버튼 · 안내) · `EmergencyContactCard`(목업 → 실제) · `LocationDetailPage`(`useGroupAdminList` → 담당 관리자 조회) · `SiteColumns`.
- 재사용: `AppDetailCard` · `AppDialog` · `AppCheckbox` · `AppInput`(검색) · `AppLinkButton` · `AppBadge` · `adminRoleLabel` · `formatPhone` · 028 `splitByKeyword`(검색 강조, 있으면) · 045 `GroupLayerMark`(노드 아이콘 후보). 대상 확정은 plan-first.
- MSW: `GetSiteManagerList` · `Emergency` 4종 상태 보유. 후보 트리는 그룹 MSW(관리자 · 할당 · 그룹 · 사업장)와 근무자 MSW(현장관리자 · 근무자 · 배치)를 **한 출처**로 만든다.

### 비즈니스 규칙

1. 담당 관리자 = **조회만** · 매니저만(사용자 결정 2026-10-27 · 28).
2. 비상연락망 후보에서 **시스템관리자 제외**.
3. 등록은 요일 하나 · 사람 하나씩 · 여러 명은 차례로 · 첫 실패에서 중단.
4. 이미 등록된 사람은 그 요일 모달에서 잠금(중복 요청을 보내지 않는다 — 서버는 멱등이지만 화면이 막는다).
5. `assignmentType` 무시 · `assignmentYn` · `assignedSite*` 는 근무자 배치 표시에만.
