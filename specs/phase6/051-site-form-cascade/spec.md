- 🔴 **044 결정을 뒤집는다**: 044 spec §0 · §2-3 "추가는 최상위만 · `parentSiteSeq` 칸 없음"(사용자 결정 2026-10-23) → **모 사업장 지정 가능**(사용자 결정 2026-10-26). 044 spec 에 뒤집힘 표기.

---

## User Stories

- US1. 시스템관리자가 사업장을 추가할 때 **본부 → 지사 → 모 사업장(선택)** 순으로 골라, 긴 `본부 › 지사` 목록을 훑지 않고 소속을 정하고 필요하면 하위 사업장으로 만든다.
- US2. 시스템관리자가 사업장을 수정할 때 같은 **본부 → 지사** 2단계로 소속을 바꾸고, 모 사업장은 바꿀 수 없음을 읽기 전용 칸으로 안다.

---

## 1. 목적

지금 소속 그룹은 `본부 › 지사` 를 이어 붙인 선택지 한 줄이라 지사가 늘면 길고 본부 이름이 반복돼 읽기 어렵다(사용자 지적 2026-10-26). 단계를 나눠 고르게 하고, API 가 받는 `parentSiteSeq`(모 사업장)를 같은 흐름 끝에 붙인다 — 지사가 정해져야 모 사업장 후보가 정해지므로(서버 규칙 "같은 그룹") 순서가 자연스럽다.

## 2. I/O

### Input
- 출처: `GetGroupList` 트리(044 그대로 — `LocationsPage` · `LocationDetailPage` 가 이미 받는다). 새 호출 없음.

### 폼 필드 (추가 · 수정 겸용 `SiteForm`)

| 필드 | 규칙 |
|---|---|
| 사업장명 | 그대로 |
| 본부 | 필수(화면). 선택지 = 트리의 `layer 1`. 🔴 **바꾸면 지사 · 모 사업장을 비운다**. 트리에 본부가 없으면(루트가 지사인 계정) **칸을 숨긴다**. 본부가 1개뿐이면 그 본부로 시작 |
| 지사 | 필수. 선택지 = 고른 본부 아래 `layer 2`(라벨 = 지사 이름만). 본부를 고르기 전에는 막는다. 🔴 **바꾸면 모 사업장을 비운다**. 에러 문구 "지사를 선택해주세요." |
| 모 사업장 | 선택. 기본 "없음 (최상위 사업장)". 후보 = **고른 지사의 최상위 사업장만**(`group.sites` — 하위 사업장은 후보가 아니다, 사용자 결정 2026-10-26). 지사를 고르기 전 · 후보 0개면 막는다(0개 안내 "이 지사에 사업장이 없습니다."). 도움말 "추가 후에는 바꿀 수 없습니다." |
| 주소 · 대표 연락처 | 그대로 |

- 기본값(추가): `?group` 이 지사면 그 본부 · 지사로 시작(044 승계).
- 기본값(수정): 현재 그룹의 본부 · 지사. 모 사업장 = 현재 모 사업장 이름 또는 "없음 (최상위 사업장)" — 🔴 **읽기 전용**(도움말 "모 사업장은 바꿀 수 없습니다."). 하위 사업장은 본부 · 지사도 막는다(044 그대로 · `groupHint` 그대로).

### Output
- `AddSite` 바디: `{ groupSeq, siteName, address, tel?, parentSiteSeq? }` — 🔴 모 사업장 "없음" 이면 **싣지 않는다**(생략 = 최상위).
- `UpdateSite` 바디: 변경 없음(`parentSiteSeq` 는 DTO 에 없다).
- 성공 · 409 처리: 044 그대로.

## 3. 제약

### 기술 제약
- 재사용: `AppSelect` · `AppFormField` · `siteList.ts`(`walkListGroups` · `findListGroup` · `findSite`). 새 공용 컴포넌트 없음.
- `SiteForm` 은 선택지 배열 대신 **트리(`GroupListNode`)를 받아** 본부 · 지사 · 모 사업장 후보를 스스로 만든다(단계가 서로 의존하므로).
- 🔴 `AppSelect` 는 빈 문자열 값을 못 쓴다(radix) — "없음" 은 전용 값으로 둔다.
- 044 `groupOptions`(`keepGroupSeq` — 회사·본부 소속 사업장 그대로 저장)는 **없앤다**: 본부에 바로 붙은 사업장은 없고 이후 본부직할 지사로 정리된다(사용자 확인 2026-10-26). 그런 사업장을 수정하면 지사를 다시 골라야 한다.

### 비즈니스 규칙
1. 사업장은 지사에만 놓인다(OQ-043-E 승계 — 서버는 막지 않는다).
2. 모 사업장 = 같은 지사의 **최상위** 사업장만 → 계층은 2단계(모 → 하위)를 넘지 않는다.
3. 모 사업장은 만든 뒤 바꿀 수 없다(서버). 화면은 추가 때 안내하고 수정 때 읽기 전용.
4. 권한별 분기 없음(044 §3 규칙 8 승계) — Manager 의 추가·수정 권한은 OQ-051-A.

## 4. 엣지 케이스

- 본부를 바꿈 → 지사 · 모 사업장 비움 → 지사 미선택으로 제출 시 "지사를 선택해주세요."
- 지사를 바꿈 → 모 사업장 "없음" 으로 되돌림(다른 지사 사업장이 남아 400 이 나지 않게).
- 고른 본부 아래 지사 0개 → 지사 칸 막고 안내 "이 본부에 지사가 없습니다."
- 트리 전체에 지사 0개 → 044 안내 그대로("지사가 없습니다. 관리그룹 편집에서…") · 제출 막음.
- 루트가 지사(본부 없음) → 본부 칸 숨김 · 지사 칸 바로 선택 가능.
- 수정: 현재 그룹이 지사가 아님(실서버에는 없음) → 지사 칸 비어 시작 · 다시 골라야 저장된다.
- 서버 400(모 사업장 불일치) → 전역 토스트(서버 문구) · 모달 유지(043 규약). 화면이 막으므로 정상 흐름에서는 나지 않는다.
