## User Stories

- US1. 개발자가 `npm run e2e` 한 번으로 **모든 화면이 권한별로 열리고**, 콘솔 에러 · 실패한 API 요청이 없으며, **390px 에서 가로로 넘치지 않는지** 확인한다(**화면 열림 확인**).
- US2. 개발자가 같은 명령으로 **핵심 쓰기 흐름 7개**(지점 · 코스 수정, 공지 쓰기, 근무자 추가, 배치 승인, 관리자 추가 · 삭제, 비상연락망 추가 · 해제)가 실제 브라우저에서 **화면을 건너며** 끝까지 되는지 확인한다(**기능 흐름 확인**).
- US3. 기존 캡쳐(`npm run capture`)는 **지금과 같이** 동작한다.

## 1. 목적

vitest 1481건은 컴포넌트를 jsdom 에서 하나씩 본다. **로그인 → 사업장 선택 → 목록 → 상세 → 수정 → 목록 반영**처럼 화면을 건너는 흐름, 가드 · 라우터 · 권한 분기, 실제 레이아웃 폭은 지금까지 사람이 브라우저로 확인했다(M6 = 사용자 확인). 이 흐름을 **mock(MSW) 위에서 자동으로 다시 돌릴 수 있게** 저장소에 남겨, 이후 작업마다 회귀를 기계가 먼저 잡게 한다.

### 저장/외부 효과
- 새 파일: `e2e/` 아래 테스트 · 헬퍼. `playwright.config.ts` 를 **프로젝트 분리**(캡쳐 / e2e 1280 / e2e 390). `package.json` 에 `e2e` 스크립트.
- 앱 코드(`src/`)는 바꾸지 않는다. 테스트가 고를 수 없는 요소가 있으면 **역할 · 이름(접근성 트리)으로 고른다** — `data-testid` 를 새로 박지 않는다.

## 3. 제약

### 기술 제약
- 기존 `@playwright/test` · `playwright.config.ts` · `.env.capture` · `webServer`(포트 5174) 재사용. 새 패키지 없음.
- `testMatch` 는 vitest 와 겹치지 않게 유지한다(`*.pw.ts` — 지금 규칙).
- 🔴 **mock 상태는 페이지 메모리에 있다**(MSW 브라우저 worker). `page.goto` 로 새로 불러오면 쓰기 결과가 사라진다 → **기능 흐름은 쓰기 뒤 화면 이동을 클릭으로** 한다. 테스트끼리는 상태를 공유하지 않는다(각 테스트가 새 페이지 = 깨끗한 시드).
- 캡쳐 전용 설정(애니메이션 멈춤 · ko-KR · Asia/Seoul · 1280×900)은 e2e 도 그대로 쓴다. 캡쳐의 "지금 고정" 은 캡쳐 프로젝트에만 둔다.
- `npm run verify` · `npm run test` 에는 넣지 않는다(브라우저 · dev 서버가 필요해 느리다) — 별도 `npm run e2e`.

### 비즈니스 규칙
- 권한 · 가드 기대값은 CLAUDE.md B1 · `flow.md` §0 을 따른다(테스트가 새 규칙을 만들지 않는다).
- 테스트가 실패하면 **앱 버그인지 테스트 문제인지 가려서 보고**한다. 앱 버그는 이 spec 에서 고치지 않고 Open Question 으로 남긴다(A3 — 범위는 테스트 기반).
