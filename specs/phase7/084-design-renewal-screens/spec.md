## User Stories

- US1. 현장관리자가 대시보드를 종일 띄워 두고 **진행 중인 순찰**(어느 지점까지 갔는지 · 언제 인증했는지 · 다음 지점)을 한눈에 본다. 새 알림이 온 코스는 잠깐 움직여 눈에 띈다.
- US2. 현장관리자가 대시보드에서 **오늘 순찰이 언제 · 어느 코스에 몰렸는지**를 본다.
- US3. 현장관리자가 코스 · 지점 상세에서 카드 상자 없이 **영역 제목 → 내용** 순서로 읽는다.
- US4. 현장관리자가 목록 화면 어디서나 **같은 순서**(제목 → 탭 → 검색 · 필터 → 표 → 페이지 이동)로 쓴다.
- US5. 현장관리자가 순찰 상세 · 근무자 상세 · 공지 상세를 같은 틀(제목 줄 → 요약 → 본문)로 읽고, 다른 화면으로 가는 버튼과 메뉴 버튼을 같은 자리에서 찾는다.
- US6. 현장관리자가 모달에서 유형마다 같은 버튼 자리(입력 폼 = 아래 전체 폭 · 확인 창 = 반반 · 편집 창 = 오른쪽 아래)를 쓴다.

## 3. 제약 (기술 + 비즈니스)

- 🔴 **문구 · 칸 · 필터 · 동작을 바꾸지 않는다.** 목업의 예시 값 · 이름은 가짜다. 목업과 지금 구현이 다르면 **지금 구현이 맞다**(§2 에 🆕 로 적은 것만 예외).
- 🔴 **대시보드의 새 영역 2개는 새 호출 없이** 이미 받는 어제~오늘 기록으로 센다. 코스별의 0회 줄만 코스 목록 조회를 하나 더 쓴다. 100건 상한 문제는 OQ-084-A.
- 🔴 **움직임은 대시보드 진행 중 코스에서만** · 약 4초 뒤 멈춘다 · `prefers-reduced-motion` 을 지킨다. 다른 화면에 움직임을 넣지 않는다.
- 🔴 **React Bits 는 `Counter` 하나만** — 설치 전에 의존성과 그 라이선스를 확인하고, 복사한 파일 머리에 저작권 표시와 허가 문구를 남긴다(MIT + Commons Clause — 실측 2026-11-20).
- 차트는 Recharts(이미 쓰는 패키지). 이름이 붙는 가로 막대(코스별 · 근무자별)는 직접 그린다.
- 지도 · QR · 사진 등 목업이 자리 표시로만 그린 것은 지금 구현을 그대로 둔다.
- 접근 이름을 유지한다 — 탭 두 개를 두 영역으로 바꾸는 대시보드처럼 구조가 바뀌는 곳은 테스트를 같은 태스크에서 고친다.
- 화면 하나를 끝낼 때마다 1920×911 캡처를 목업과 나란히 대조한다.

## 5. 완료 조건 (DoD)

- [ ] 현장 화면 14개가 1920×911 에서 목업과 같은 배치다(예시 값 · 지도 · 사진 제외). 화면별 대조 캡처가 있다.
- [ ] 본문 카드 안에 카드 상자가 남아 있지 않다(예외: 대시보드 진행 중 코스 상자 · 코스 상세 숫자 칸 3개 · 펼친 내용 상자).
- [ ] 대시보드 — 진행 중 경로에 `순찰 시작` 과 지점별 인증 시각이 보이고, 실시간 알림이 온 코스가 약 4초 움직이며, 움직임 줄이기 설정에서는 움직이지 않는다.
- [ ] 대시보드 — 오늘 시간대별 · 코스별 순찰의 숫자가 순찰이력 화면에서 오늘로 걸러 센 값과 같다(100건 이하인 사업장 기준).
- [ ] 대시보드 숫자가 값이 바뀔 때 굴러가고, 복사한 React Bits 파일에 저작권 표시가 있다.
- [ ] 코스 상세의 마지막 순찰 칸이 진행 중 회차에서 순찰자 · 진행 · 경과를 보인다.
- [ ] 표의 칸 · 필터 · 문구가 개편 전과 같다(개편 전 캡처 또는 태그 `design-before-renewal-2026-11` 과 대조).
- [ ] 모달 다섯 유형이 §2-5 의 버튼 자리를 따른다.
- [ ] 주황이 남아 있지 않다. 한 영역 안의 빈 상태는 글자 한 줄이다.
- [ ] `docs/design-system.md` · `layout.md` · `components.md` · `patterns.md` · `screens.md` 가 새 규칙과 어긋나지 않는다.
- [ ] `npm run verify` · `npm run test` · `npm run e2e` 통과.
