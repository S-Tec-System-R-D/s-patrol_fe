## User Stories

- **US1.** 현장관리자가 코스 상세의 편성 편집에서, 사업장 지점 중 **인증수단으로 추려
  검색**해 고르고, **고른 것이 코스의 몇 번째가 되는지 보면서** 한 번에 담는다.
- **US2.** 다음에 이 코드를 읽는 사람이, 편성 후보·지점 사용여부에 대한 **사실**을 읽는다
  (지금은 실측으로 뒤집힌 근거가 주석에 남아 있다).

---

## 1. 목적

코스에 편성할 지점을 고르는 모달을, **고르는 동안 결과를 알 수 있게** 바꾼다.

현재 모달은 체크박스 목록 하나다. 후보가 사업장 전량으로 내려오는데(페이징 없음) 추릴
수단이 **이름 검색뿐**이고, 여러 개를 고르면 **무엇을 골랐는지 목록을 거슬러 올라가며
확인해야** 하며, 고른 지점이 코스의 **몇 번째로 들어가는지** 담아 보기 전에는 알 수 없다.
순서는 이 화면의 핵심 산출물인데(코스 = 순서가 있는 지점의 열) 고르는 단계에서 보이지
않는다.

목업(`코스상세-지점추가.png`)이 이 셋을 모두 해결한다 — 필터 칩 · 선택 목록 · 순번 표시.

## 2. I/O

### Input

| 출처 | 값 |
|---|---|
| `GetClassificationPoint?siteSeq=` | `ClassificationPoint[]` — `pointSeq` · `pointName` · `memo` · `authMethod` · `authMethodName`. **모달이 열릴 때만** 조회(현행 유지) |
| props `assignedPointSeqs` | 편집 중 초안에 이미 있는 `pointSeq` — 후보에서 제외 + **개수가 순번의 시작점** |
| 사용자 입력 | 검색어(이름) · 필터 칩(`전체` \| `QR` \| `NFC`) · 체크 선택 |

### Output

- `onAdd(points: ClassificationPoint[])` — **선택한 순서대로** 호출부에 넘긴다.
  호출부(`CoursePointEditor`)가 초안 배열 **끝에 append** 하고, `orderNo` 는 저장 시
  `coursePointOrder.ts` 가 1..N 으로 재부여한다(현행 그대로).
- **서버 호출 없음. 저장 없음.** 모달이 닫혀도 저장 전까지는 아무것도 바뀌지 않는다.

## 3. 제약

### 기술 제약

- 재사용: `AppDialog` · `AppInput`(`variant="search"`) · `AppCheckbox` · `AppBadge` ·
  `AppButton` · `useClassificationPoints`
- **버튼식 필터**: `AppFilterButton`/`AppFilterPopover` 는 **쓰지 않는다** — 그건 목록
  화면의 팝오버 필터이고, 여기는 **항상 보이는 칩 3개**다(목업). 칩은 이 모달 안에 둔다
  (다른 소비처가 0곳 — 공용으로 뽑지 않는다, A6)
- **검색·필터는 클라이언트에서 한다.** 목록 화면의 "클라이언트 필터 0건" 규칙과 반대로
  보이지만 **성격이 다르다** — `GetClassificationPoint` 에는 검색·필터 파라미터가 **없다**
  (서버가 거를 수단을 주지 않는 경우). 목록은 서버가 거른다는 것을 023 T355 에서 실측했다

### 비즈니스 규칙

1. **이미 편성된 지점은 후보에 보이지 않는다**(현행 유지 — 목업의 `이미 포함` 비활성 행은
   채택하지 않음, 사용자 결정 2026-10-13). 🔴 서버는 **같은 지점의 중복 편성을 막지 않는다**
   (실측 2026-10-12: 각각 다른 `coursePointSeq` 를 준다) — 화면이 막는 규칙이다.
2. **순번 표시** — 행 우측 번호 = `assignedPointSeqs.length + (선택 순서)`.
   기존 3개 + 2개 선택이면 `4`, `5`. **선택을 해제하면 뒤 번호가 당겨진다.**
3. **선택 목록은 모달 하단에** 선택한 순서대로. 개별 해제 가능. "모두 해제" 는 둔다.
4. **"전체 선택" 은 만들지 않는다**(사용자 결정). 하단 **"현재 N개 → 추가 후 M개 ·
   예상 소요"** 도 만들지 않는다 — 🔴 **예상 소요는 계산할 수 없다.** 구간시간(`courseMin`)은
   **담은 뒤에 입력**하는 값이라 선택 시점에는 0 이다(A1).
5. **필터는 `전체` / `QR` / `NFC` 3개뿐.** 🔴 목업의 **`미배정`** 칩은 **만들 수 없다** —
   후보 응답에 "이 지점이 어느 코스에 속하는지" 가 **없다.** 알아내려면 지점마다 상세
   조회(N+1)다. 각 칩에 **해당 건수**를 함께 표시한다(후보 기준).
6. **행에 담는 정보는 `지점명` + `인증수단 뱃지` 까지.** 🔴 목업의 `B1 · 캠프 전담구 ·
   PT-0032`(상세 위치 · 지점 코드)는 **서버에 없는 필드**다(027 에서 placeholder 로 둔 바로
   그 값들). 추측으로 채우지 않는다.
7. **검색어 하이라이트** — 일치 구간만 강조(목업).

### 🔴 실측으로 뒤집힌 전제 (US2 — 주석 정정의 근거)

2026-10-13 실 백엔드(사업장 6)에서 확인했다. **코드가 반대로 적혀 있다.**

| 위치 | 현재 주석 | 사실 |
|---|---|---|
| `getClassificationPoint.ts` · `types/course.ts` · `AddCoursePointDialog.tsx` | "응답에 `useYn` 이 없어 **미사용 지점이 섞여 있는지 알 수 없다**" | 🔴 **서버가 미사용 지점을 후보에서 제외한다.** 지점 19를 `useYn=false` 로 바꾸자 후보가 14건 → **13건**이 되고 그 지점이 사라졌다. 되돌리자 14건으로 복귀 |
| `CoursePointList.tsx` · `coursePointOrder.ts` | "지점별 사용여부는 **표시만 한다 — 바꿀 수단이 서버에 없다**(B-29)" | 🔴 근거가 틀렸다. **코스에서 지점별 사용여부를 바꾸는 개념 자체가 없다**(사용자 확인). 그리고 `GetCourseDetail.points[].useYn` 은 **지점의 실제 값을 따라오지도 않는다** — 지점을 미사용으로 꺼도 코스 3개(65·37·38)에서 모두 `true` 였다. 즉 **항상 `true` 인 상수**이고, 화면의 미사용 분기는 **발동하지 않는다** |

⚠️ 부수 사실: **이미 편성된 지점은 미사용으로 꺼도 코스에 그대로 남는다**(후보에서만
빠진다). 즉 "미사용 지점이 편성된 채 남아 있는 코스" 는 생길 수 있는 상태인데, **코스 상세
응답만으로는 알 수 없다.** 본 spec 에서 해결하지 않는다 → **Open Question** 으로 남긴다.

🔴 **B-29 는 철회한다**(요청 DTO 에 `useYn` 추가 불필요 — 코스에서 바꿀 값이 아니다).
대신 "응답의 `points[].useYn` 이 지점 실제 값을 따라오게 하거나, 아니면 응답에서 빼라" 를
**우선순위 낮음**으로 등재한다.

## 4. 엣지 케이스 (A급 — 풀 작성)

| 상황 | 처리 |
|---|---|
| 후보 조회 **로딩** | 스켈레톤 유지. 🔴 "후보 없음" 으로 보여주지 않는다(지점이 없다고 믿고 나간다) |
| 후보 조회 **실패** | 안내 + 다시 시도. 빈 목록과 구분한다 |
| **0건 3종** | ① 사업장에 지점 없음(→ `/points` 링크) ② 전부 편성됨 ③ 검색·필터 0건 — **문구를 구분한다**(현행 유지, 필터 0건이 새로 추가된다) |
| 검색·필터 조합 결과 0건 | "검색 결과가 없습니다" + **필터 초기화** 수단 |
| 선택 후 필터를 바꿔 **선택 항목이 목록에서 사라짐** | 🔴 **선택은 유지된다.** 하단 선택 목록에 계속 남고 거기서 해제할 수 있다 — 안 그러면 필터를 바꾼 것만으로 고른 것이 조용히 사라진다 |
| 모달을 **취소/닫기** | 검색어·필터·선택 전부 초기화(현행) |
| **연타**(추가 버튼) | 담고 즉시 닫으므로 중복 호출 여지 없음. 선택 0건이면 비활성 |
| 같은 지점이 **코스에 두 번** | 후보에서 제외되므로 모달 경로로는 발생하지 않는다 |
| 담은 직후 **저장하지 않고 이탈** | 저장 전까지 서버 상태는 그대로. 모달의 책임 아님(편성 카드가 처리) |

## Open Questions

- [ ] **OQ-028-A. 미사용 지점이 편성된 채 남아 있는 코스를 알릴 것인가.**
      지점을 미사용으로 꺼도 **기존 편성은 유지된다**(실측). 그런데 `GetCourseDetail.points[].useYn`
      이 항상 `true` 라 코스 상세에서는 **구분할 수 없다.** 알리려면 ① 백엔드가 응답 값을
      실제 값으로 채우거나 ② 지점마다 상세 조회(N+1). **본 spec 범위 외** — 백엔드 답변 후 재검토.
- [ ] **OQ-028-B. 코스 상세의 미사용 분기 코드를 지울 것인가.**
      `CoursePointList` 의 톤다운·`미사용` 뱃지는 현재 **발동하지 않는 코드**다. OQ-028-A 가
      ①로 풀리면 **그대로 살아나므로**, 지우지 않고 주석으로 상태를 적어 둔다(DoD #9).
