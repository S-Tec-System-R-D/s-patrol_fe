## User Stories

- **US1.** 현장관리자가 **분할화면**(브라우저를 좌우로 나눠 쓰는 상황)에서 목록 4화면을
  열어도 컬럼이 찌그러지지 않고, **한 건씩 카드로** 읽고 눌러 들어간다.
- **US2.** 다음에 목록 화면을 만드는 사람이 **같은 방법으로** 카드 대응을 붙인다
  (공용 컴포넌트 + `patterns.md` 규약).

---

## 1. 목적

목록 4화면을 **좁은 폭에서 카드로** 바꾼다.

지금 `AppTable` 은 **가로 스크롤조차 없다**(`overflow-hidden`). 폭이 줄면 컬럼이 그대로
찌그러져 지점이력(8컬럼)은 글자가 세로로 쌓인다. `CLAUDE.md` B4 의 "PC 기준 + **분할화면
대응**" 이 아직 목록에 적용되지 않은 상태다.

🔴 **프로젝트의 첫 반응형 분기다.** `src` 전체에 `xl:hidden`·`md:hidden` 을 쓰는 파일이
**하나도 없다** — 여기서 정하는 방식이 그대로 규약이 된다.

---

## 2. I/O

### Input
- 기존 그대로. **새 API·쿼리·상태가 없다.** `AppTable` 에 넘기던 `data`·`columns` 를
  그대로 쓰고, 카드 렌더 함수를 **추가로** 받는다.

### Output
- `xl` 이상: 지금과 **완전히 동일한 테이블**(바이트 단위로 같아야 한다 — 캡쳐로 확인)
- `xl` 미만: 카드 목록. 행 클릭·톤다운·페이지네이션 **동작 동일**

---

## 3. 제약

### 기술 제약

1. 🔴 **`AppTable` 의 카드 모드는 opt-in 이다.** 소비처가 **6곳**인데 그중 둘은 이번
   대상이 아니다:

   | 소비처 | 이번 대상 | 비고 |
   |---|:-:|---|
   | `/zones` · `/points` · `/patrol/zones` · `/patrol/points` | ✅ | |
   | `/users` | ✗ | 범위 밖(사용자 결정) — 붙이려면 카드 렌더만 넘기면 된다 |
   | `DeploymentHistoryTabs`(배치 이력 탭, 탭마다 1개씩 **2번**) | 🔴 **절대 아님** | **카드 안에 들어 있는 표**다. 자동으로 카드가 되면 카드 안에 카드가 생긴다 |

   🔴 **정정(T443, 2026-10-13)**: `CoursePatrolLog` 은 `AppTable` 을 **쓰지 않는다** —
   주석에서 "쓰지 않았다" 고 언급할 뿐인데 `grep "AppTable"` 이 그 문장을 세어 소비처로 잡혔다.
   실제 사용처는 **6곳**(파일 5개 — `DeploymentHistoryTabs` 가 탭마다 하나씩 2번 쓴다):
   `/zones` · `/points` · `/patrol/zones` · `/patrol/points` · `/users` · `DeploymentHistoryTabs`.
   **비대상은 2곳**(`/users` · `DeploymentHistoryTabs`)이고 둘 다 `renderCard` 를 받지 않는다.

   → prop 을 준 곳만 바뀐다. **기본 동작은 지금 그대로**다.

2. 🔴 **행 목록은 `table.getRowModel()` 에서 가져온다.** `data` 를 직접 돌면 정렬·페이지가
   **카드에서만 안 먹는다** — 테이블과 카드가 **다른 것을 보여주는** 상태가 된다.

3. **분기점은 `xl`**(1280px). `design-system.md` §2-5 가 상세 2열 분기에 쓰는 값과 같다 —
   목록만 다른 숨을 쉴 이유가 없다.

4. 🔴 **둘을 동시에 렌더하고 CSS 로 숨긴다**(`hidden xl:block` / `xl:hidden`). JS 로
   폭을 재서 하나만 그리면 ① 첫 렌더에 깜빡이고 ② SSR·테스트에서 폭이 0이라 **항상
   카드**가 된다. DOM 이 두 벌이 되지만 **행 수는 페이지당 20~100**이라 감당된다.
   ⚠️ **테스트에서는 둘 다 DOM 에 있다** — `getByText` 가 2건을 잡는다. 테스트는 영역을
   좁혀 찾는다(`within`).

### 비즈니스 규칙

5. **카드에 남길 것은 "고르는 데 쓰는 값"** 이다. 좁은 화면에서는 행을 훑어 **비교**하지
   않고 하나를 **찾아서 누른다** — 비교용 수치는 접고 식별·상태만 남긴다.

   | 화면 | 카드 구성 (사용자 확인 2026-10-13) |
   |---|---|
   | `/zones` | **코스명** + 사용·교대 뱃지 / 지점 수 · 총 소요시간 / 최근 순찰 |
   | `/points` | **지점명** + 사용·인증수단 뱃지 / 소속 코스 · 최근 순찰 |
   | `/patrol/zones` | **코스명** + 결과 뱃지 / 시작~종료 일시 |
   | `/patrol/points` | **지점명** + 결과·인증 뱃지 / 코스명 · 순찰일시 · 순찰자 / 기록 건수 |

6. **상태는 카드에서도 글자로 전한다** — 뱃지를 쓰고 색만으로 구분하지 않는다
   (`design-system.md` 접근성 규약). 미사용 톤다운도 **카드 전체**에 건다(테이블 행과 같은 처리).

7. ⚠️ **이력 2화면은 아직 mock 위에 있다**(`PatrolZone` 의 `Date` 타입, 클라이언트 필터).
   `spec 024`·`025` 가 서버로 전환하면 **필드명이 바뀐다** — 카드 **구조는 유지되고 매핑만**
   손본다. 사용자 결정(2026-10-13): 지금 함께 만든다. 024·025 착수 전까지 이력 화면만
   분할화면에서 깨진 채 두지 않는 쪽을 택했고, 만들어 둔 카드가 그때 **"이 필드가 서버에
   있나" 를 점검하는 체크리스트**가 된다.

## 4. 엣지 케이스

> B급 — 공통 규칙을 따르되, **이 spec 고유의 것**만 적는다.

| 상황 | 처리 |
|---|---|
| 0건 · 로딩 · 실패 | **각 페이지가 이미 처리한다**(`AppTable` 바깥에서 분기). 카드 모드가 그 분기를 건드리지 않는다 |
| 행 클릭 | 테이블과 **같은 핸들러**. 카드 전체가 클릭 영역이다 |
| 미사용 톤다운(`rowClassName`) | 카드에도 **같은 함수**를 적용한다 — 두 벌로 갈라지면 한쪽만 고쳐진다 |
| 페이지네이션 | `AppPagination` 은 테이블 **바깥**에 있어 그대로 동작한다 |
| 정렬(헤더 클릭) | 🔴 카드 모드에는 **정렬 UI 가 없다.** 좁은 폭에서 컬럼 헤더를 재현할 자리가 없다 — 테이블에서 정렬한 상태는 **유지되지만**(같은 `rowModel`) 카드에서 바꿀 수단은 두지 않는다 |
