## User Stories

- **US1.** 현장관리자가 **코스 순찰이력 목록**에서 기간·코스·결과로 걸러 **서버 데이터**를
  본다 — 지금은 페이지 안에 박힌 mock 배열(`PatrolZonesPage.tsx:215`)을 보고 있다.
- **US2.** 목록의 한 행을 열어 **코스 순찰 상세**에서 그 회차에 **어느 지점이 인증됐고
  무엇이 빠졌는지**를 본다.
- **US3.** 상세의 **지도**에서 실제 인증 위치와 도는 순서를 보고, **미인증 지점이 어디였는지**도
  함께 본다.
- **US4.** 순찰 중 남긴 **메모**를 그 지점 행에서 펼쳐 읽는다(`spec 023` C단이 남긴 자리).

## 1. 목적

코스 순찰이력을 **mock → 서버**로 전환하고, 목업 2종(`01`·`02`)의 구조로 바꾼다.
그 과정에서 **이력 2화면이 공유할 기반**을 세운다 — 결과 뱃지 · enum SSOT · 필터 바 ·
기간 선택. 037(지점 이력)은 이 기반을 **쓰기만** 한다.

🔴 **코스를 먼저 하는 이유** — 뱃지에 필요한 `status` 전량이 **코스 쪽에서만 관측된다**.
`CheckDetails` 에 `0 대기중`·`1 진행중`·`3 미완료`·`4 완료` 가 다 나오는데 지점이력 응답은
**`3`·`4` 뿐**이다(`api-spec.md` §4 분포표). 지점을 먼저 하면 2종만 보고 만든 뱃지를 코스에서
다시 넓힌다 — **018 이 5종을 2종 위에 설계했다가 막힌 것과 같은 실수다.**

| # | 엔드포인트 | 쓰는 곳 |

### 2-4. 공용 기반 (037 이 쓴다)

1. 🔴 **결과 뱃지 매핑을 "화면 단위" 로 나눈다** — 응답 단위가 아니다. 두 응답이 **내려주는
   범위가 다르다**(§3-1). 코스 상세 = `0`·`1`·`3`·`4` / 지점이력(037) = `3`·`4`.
2. 🔴 **시간초과를 결과 뱃지에 섞지 않는다** — `overtimeYn` 은 **독립 축**이라 **뱃지 2개를
   병기**한다(`완료` + `시간초과`). 실측에 `status 4` + `overtimeYn` + 메모가 **동시에 참인
   행이 실재**한다(`detailSeq 85`) — 하나로 접으면 우선순위를 정해야 하고 정보가 사라진다.
3. **`이상없음` ↔ `순찰기록` 은 `hasMemo` 로 갈린다**(서버 `status` 에 그 구분이 없다).
4. **enum SSOT 일원화** — 지금 **3중 분기**다: `types/enum.ts` 의 `PointResult`(소비처 0개) ·
   feature types(dead) · 페이지 인라인(`PatrolZonesPage.tsx:28` `PATROL_RESULT`). 하나로 모은다.
5. **필터 바** — `AppFilterPopover`(027) + `AppDatePicker`(017, **이미 범위 전용**) 조립.
   🔴 **새 공용 컴포넌트를 만들지 않는다** — 둘 다 있고 `PatrolZonesPage` 가 이미 쓴다.
   바뀌는 것은 **값의 출처**다(클라이언트 필터 → 서버 쿼리).

## 3. 제약

### 3-1. 🔴 두 응답의 범위가 다르다 (실측 2026-10-16)

`GetPointHistory` 는 **`checkDt` 가 있는 행만** 준다. `CheckDetails` 의 미완료 124건 중
`checkDt` 가 있는 것이 **정확히 45건**이고 그것이 지점이력의 미완료 45건이다.
→ **`대기중`·`진행중`·"방문 기록 없는 미완료" 는 코스 상세에만 나온다.**

### 3-2. 🔴 `미완료` 는 두 종류다 — 화면에서 구분한다

| 종류 | 건수 | 판별 | 표기 |
|---|:-:|---|---|
| 방문 기록 없음 | 79 | `checkDt === null` | **미인증** — 목업의 미인증 패널 문구("방문 기록이 없습니다")가 이것 |
| 방문 흔적 있음 | 45 | `checkDt !== null` | **미완료**(인증 실패) |

### 3-3. 🔴 타입을 믿고 null 접근하지 않는다

인증이 찍히지 않은 행은 `checkUserSeq`·`userName`·`overtimeYn` 이 **전부 `null`** 이다
(`api-spec.md` §5-2 17번 교정). `status 0`·`1` 은 **전 필드 null** 이다.
⚠️ **`userList` 가 빈 배열인 이력이 19/54(35%)** 다(OQ-17) — 순찰자 컬럼 폴백이 필수다.

### 3-4. 🔴 "기준 충족" 판정을 하지 않는다

`totalMin` 이 **검증되지 않고**(B-31) 어긋난 데이터가 실재하며(`spec 035`: 전수 18건),
`totalMin: 0` 인 코스도 있다. `courseMin` 은 **전 구간 0 인 코스가 실재**한다(실측 7개 코스).
→ 소요시간 KPI 는 **값을 나란히 보여주고 판정하지 않는다**. 033 반영 후 다시 본다.
🔴 이것은 **`spec 023` 의 "인증률에 색을 입히지 않는다" 와 같은 판단**이다 — 분모·기준을
확신할 수 없을 때 색이나 판정을 입히면 관리자가 **없는 문제**를 찾는다.

### 3-5. 지도 — `spec 032` 규칙을 그대로 승계

범위 밖 좌표 제외(B-33, `lib/courseCoords.ts` 재사용) · 좌표 0개면 지도 비표시 ·
빠진 번호도 자리 유지 · 스크롤 줌 차단 · `map.remove()` 정리 · 타일 URL 은 env.
🔴 **새 좌표 유틸을 만들지 않는다** — 032 의 것을 쓴다.

### 3-6. 🔴 사진은 **빈 칸**이 된다 (B-40)

첨부 URL 이 **404** 다(실측: 순찰 2건·공지 1건 전부, 토큰 무관). 메모 **텍스트는 보이고**
사진만 안 온다. → **`onError` 폴백**을 넣고 "이미지를 불러올 수 없습니다" 를 표시한다.
⚠️ **폴백 없이 두면** 깨진 이미지만 뜨고 **원인을 화면에서 알 수 없다**.

### 3-7. 메모에는 작성자·시각이 없다

`memos` = `{memoSeq, memo, attaches}` 3필드가 전부다(실측 확정). 목업의 "박지우 10:25" 는
**행의 `userName`·`checkDt` 로 대체**한다. 🔴 **"처리 상태"(시설팀 접수 등) 필드는 없다** — 뺀다.

### 3-8. 그 외 범위에서 빼는 것 (사용자 결정 2026-10-16)

이력번호 · 사업장 동 · 교대조 · 좌표 오차 · 층/위치 컬럼 · 태그ID · 단말 · 처리담당자 ·
예정 시각 · **"코스 동선과 비교"** · 확인 처리 · 사유 등록 · 보고서 내보내기

## 4. 엣지 케이스

> B급이라 공통 규칙(`CLAUDE.md` 층 A · `design-system.md`)을 따른다. **실측에서 나온 것만** 적는다.

1. **진행 중 회차**(`endDt === null`) — 종료 일시는 **`—`** 다. 🔴 **`spec 030` 의 규칙을
   뒤집었다**(사용자 브라우저 확인 2026-10-16): 030 은 `—` 가 값 누락으로 읽힌다며 "진행 중"
   을 적게 했지만 그 판단은 **결과 컬럼이 없던 4컬럼 시절**의 것이다. 지금은 같은 행·같은
   카드에 **`진행중` 결과 뱃지**가 있어 맥락이 이미 있고, 같은 말을 두 칸에서 하면 **종료
   일시 칸이 상태 칸처럼** 읽힌다. 종료 일시는 **아직 값이 없는 것이 사실**이다.
   ⚠️ `status 0` 은 테스트 DB 에 **0건**이라 화면 확인이 불가능하다 → mock 에 시드를 둔다.
2. **완료인데 인증 0건** — 실재한다(`status 1` + `checkedCount: 0`). 상태와 인증률은
   **독립**이다. "완료 = 전 지점 인증" 으로 묶지 않는다.
3. **순찰자 0명 / 2명** — 빈 배열 19건, 2명 6건(교대). 둘 다 처리한다.
4. **완료인데 인증수단·좌표·순찰자가 null** — 3건 실재(OQ-16). 인증수단 칸을 비우고 터지지 않는다.
5. **좌표가 없는 지점** — 실측 코스 7개의 보유율이 `5/5 · 3/4 · 3/3 · 2/3 · 1/2 · 0/0 · 1/1`.
   "좌표 없음 N개" 를 명시한다(032 선례).
6. **`pageSize > 100` 은 400** 이다 — 요청 어디에도 100 초과를 넣지 않는다(`spec 027` 이
   200 을 보내 **장애가 빈 상태로 읽혔던** 선례).
