## User Stories

- **US1.** 현장관리자가 코스 상세에서 **지점들이 실제로 어디에 있는지**와 **도는 순서**를
  지도 위에서 한눈에 본다 — 지금은 이름 목록과 다이어그램뿐이라 **위치 감각이 없다**.

---

## 1. 목적

코스의 **순찰 동선을 지도에 그린다**(`spec 023` D단).

지금 코스 상세에는 **경로 다이어그램**(`CourseDiagramCard`)이 있어 **순서**는 보이지만,
그 지점들이 **건물 어느 쪽인지**는 알 수 없다. 이 솔루션의 순찰은 **건물 외곽 구역**을
도는 것이라(사용자 확인 2026-10-14) 위치 관계가 곧 동선의 의미다.

---

## 2. I/O

### Input
- `GetCourseDetail.points[]` 의 `gpsLat` · `gpsLng` · `pointName` · `orderNo`
  — **이미 받아 둔 응답**이다. 🔴 **조회가 늘지 않는다.**
- V-World 타일(외부) · 인증키(`.env`)

### Output
- 코스 상세 좌측 열에 **지도 카드**. 마커(순번) + 경로선 + 자동 영역 맞춤.
- **서버로 나가는 요청 없음.**

---

## 3. 제약

### 기술 선택 — **Leaflet + V-World**(사용자 결정 2026-10-14)

| 비교 | 결론 |
|---|---|
| vs 네이버 지도 | **비용이 발생하면 안 되고**(네이버는 무료 한도 초과 시 과금 + NCP 결제수단), **건물 내부 표현이 불필요**하다(외곽 구역 순찰) → V-World 로 충분 |
| vs MapLibre GL | 🔴 MapLibre 는 **WebGL 필수**라 구형 PC·원격 데스크톱에서 **아예 안 뜰 위험**이 있다. 우리가 쓰는 것은 **래스터 타일 + 마커 + 선**뿐이라 벡터·3D 강점을 하나도 안 쓴다. Leaflet 은 DOM/Canvas 라 그 위험이 없고 번들도 **1/5**(~40KB) |

- **라이브러리**: `leaflet` + `@types/leaflet`. 🔴 **`react-leaflet` 을 쓰지 않는다** —
  React 19 호환을 또 하나 떠안고, 우리가 쓰는 API 는 **지도 생성·마커·폴리라인·fitBounds**
  네 개뿐이다. `useEffect` 안에서 직접 다루고 **정리(`remove()`)를 명시**하는 편이 작다.
- **키**: `VITE_VWORLD_KEY`. 🔴 **키가 없으면 지도를 그리지 않고 안내를 띄운다** —
  키 없이도 나머지 화면이 멀쩡히 개발되어야 한다(팀원·CI).
- ⚠️ **도메인 등록이 필요하다** — 운영 도메인과 **`localhost`** 둘 다. 등록 전에는
  타일이 막힌다(키가 있어도).

### 비즈니스 규칙

1. 🔴 **좌표 없는 지점은 건너뛰고 "좌표 없음 N개" 를 명시한다**(A안, 사용자 결정).
   실측상 코스 3개에서 각각 1개씩 `null` 이다 — **조용히 빼면 핀이 빠진 지도**가 되고
   어느 지점이 빠졌는지 알 수 없다. 지도는 "대략 어디를 도는가" 를 보는 용도라 일부만
   있어도 쓸모가 있지만, **빠진 사실은 말해야** 거짓이 되지 않는다.
2. 🔴 **범위 밖 좌표는 "좌표 없음" 과 같이 다룬다**(B-33). 서버에 **`gpsLat: 123`** 이
   저장돼 있다(사업장 3, 실측) — 위도는 -90~90, 경도는 -180~180 이다. 그대로 넘기면
   **핀이 엉뚱한 곳으로 날아가고** 자동 영역 맞춤이 지구 반대편까지 벌어진다.
3. **마커에 순번을 쓴다** — 지도의 값어치는 "어디" 와 **"어느 순서로"** 가 함께 보일 때다.
   순번은 `orderNo` 가 아니라 **편성 순서**(배열 위치)를 쓴다(`spec 023` 과 같은 규칙 —
   서버가 중복 `orderNo` 를 그대로 저장한다).
4. **경로선은 좌표가 있는 지점만 잇는다.** 중간 지점의 좌표가 없으면 **그 구간을 건너뛴
   직선**이 된다 — 실제 동선과 다르므로 **선을 점선으로** 그려 "추정" 임을 보인다.
5. 🔴 **다이어그램 카드를 없애지 않는다.** 둘은 다른 질문에 답한다 — 다이어그램은
   **순서**(구간시간 포함), 지도는 **위치**다. 좌표가 하나도 없는 코스에서는 **지도만
   무용지물**이 되므로 다이어그램이 유일한 경로 표현이 된다.
6. **타일 로드 실패·키 없음·좌표 0개**는 모두 **지도 자리를 비우고 사유를 적는다** —
   깨진 회색 박스를 남기지 않는다.

---

## 4. 엣지 케이스

| 상황 | 처리 |
|---|---|
| **키 없음**(`.env` 미설정) | 지도 대신 안내 — "지도 키가 설정되지 않았습니다". 🔴 개발·CI 가 막히지 않는다 |
| **좌표가 하나도 없음** | 지도를 그리지 않고 안내. 다이어그램이 경로를 보여준다 |
| **좌표가 1개뿐** | 마커 하나 + 기본 줌(선 없음). `fitBounds` 는 점 하나에 쓸 수 없다 |
| **일부만 없음** | 있는 것만 잇고 **"좌표 없음 N개"** 를 카드 머리에 적는다 |
| **범위 밖 값** | 없는 것과 **같이** 센다(규칙 2) |
| **타일 로드 실패** | 지도 영역에 안내. 🔴 **현장 PC 가 외부에 나갈 수 있어야 한다**(확인 완료 2026-10-14) |
| 좁은 폭 | 지도 높이 고정, 가로는 꽉 채운다 |

## 5. 완료 조건 (DoD)

- [ ] 1. 코스 상세에 **지도 카드**가 있고 마커·경로선·자동 영역 맞춤이 동작한다
- [ ] 2. 🔴 마커에 **편성 순번**이 보인다(`orderNo` 가 아니라 배열 위치)
- [ ] 3. 🔴 **좌표 없는 지점 수를 명시**한다(A안) — 조용히 빼지 않는다
- [ ] 4. 🔴 **범위 밖 좌표를 없는 것과 같이** 다룬다(B-33) — 단위 테스트로 고정
- [ ] 5. **키가 없으면** 지도 대신 안내가 뜨고, 나머지 화면은 멀쩡하다
- [ ] 6. 좌표 0개·1개 분기가 각각 동작한다
- [ ] 7. 🔴 **다이어그램 카드가 그대로 있다** — 지도가 그것을 대체하지 않는다
- [ ] 8. `leaflet` CSS 가 전역을 오염시키지 않는다(지도 영역 밖 스타일 무변화)
- [ ] 9. `npm run verify` 0 errors + `npm run test` green (865 → 증가)
- [ ] 10. 브라우저 확인 — 좌표 전부 있는 코스 · 일부 없는 코스 · 하나도 없는 코스
- [ ] 11. 캡쳐 `zones--상세` 재촬영. 🔴 **외부 타일이 캡쳐를 불안정하게 만들지 확인**
      (타일이 매번 다르게 찍히면 baseline 으로 못 쓴다 → 그 경우 **캡쳐에서 지도를 가린다**)
