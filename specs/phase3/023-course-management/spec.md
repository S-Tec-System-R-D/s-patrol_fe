## User Stories

- **US1.** 현장관리자는 `/zones` 에서 코스 목록을 보고(상태·지점 수·총 소요시간·최근 순찰), 검색·필터로 좁히고, 행을 눌러 상세로 간다.
- **US2.** 현장관리자는 `/zones/:courseSeq` 에서 **경로 다이어그램**과 **지점 순서**를 보고, 기본정보를 수정하고 코스를 삭제한다.
- **US3.** 현장관리자는 코스를 **생성**한다(명칭·설명).
- **US4.** 현장관리자는 상세에서 **지점을 편성**한다 — 추가·제거·**순서 변경(드래그)**·구간시간 설정·지점별 활성.
- **US5.** 현장관리자는 **교대 허용·코스 활성화**를 확인 모달을 거쳐 바꾼다.

## 1. 목적

`/zones` 는 **011 에서 셸만 만들고 mock 위에 있다.** 022 가 지점에 한 일(실 API 전환)을 코스에 하고, 027 이 지점에 한 일(화면 재구성)을 **같이** 한다.

**왜 함께 하는가** — 지점 상세는 `012`(셸) → `022`(API) → `027`(재구성)로 **두 번 갈아엎었다.** 코스를 API 만 전환하면 **똑같이 두 번** 한다. 그리고 027 이 "셸 승격은 023 에서 검토" 로 미뤄 뒀는데, 코스가 옛 구조로 남으면 **또 미룬다.**

**하지 않는 것**
- **QR·공지·본사 영역** — 범위 밖
- **코스 순찰이력**(`/patrol/zones`) — `spec 025`
- 🔴 **지점 0개 코스에 대한 자동 조치** — 0-2 #3

| 용도 | 엔드포인트 | 비고 |
|---|---|---|

**URL 쿼리**: `search` · `useYn` · `switchYn` · `status` · `page`

## 3. 제약

### 기술 제약

1. **027 의 화면 패턴을 승계한다** — 라우트 빌더(`paths.ts` + `pathPatterns`) · 브레드크럼 + 제목 + 헤더 액션 · 섹션 카드 · `AppFilterPopover` · `AppTable` + 외부 `AppPagination` · `rowClassName`.
2. **`queryKey` 는 `data-model.md` §8 규약을 따른다** — 루트 `'courses'`/`'course'`, 스코프(`siteSeq`) 포함, 파라미터 객체 마지막.
3. 🔴 **`UpdateCourse` 는 항상 `points` 를 전량 전송한다.** 전체 교체이므로(B-25) 부분 전송은 **나머지를 삭제**한다. 편성 UI 가 들고 있는 **현재 전체 목록**을 그대로 보낸다 — "변경분만 보내기" 를 만들지 않는다.
4. 🔴 **`courseSeq` 를 타입으로 강제한다.** 누락 시 서버가 **401** 을 주고(B-28) 인터셉터가 **토큰 만료로 오해**해 재발급·로그아웃을 탄다. 요청 DTO 에서 `courseSeq` 를 **required** 로 선언한다.
5. **`DeleteCourse` 는 `courseId`** 다. api 파일 주석에 못 박는다 — 다른 엔드포인트는 전부 `~Seq`라 틀리기 쉽다(B-12).
6. 🔴 **지점의 교훈을 그대로 옮기지 않는다.** `UpdatePoint` 는 `null` 을 무시하지만(B-15) **`UpdateCourse` 는 반영한다**(실측). 엔드포인트마다 다르므로 **코스는 코스대로 확인된 동작**을 쓴다.
7. **드래그 정렬은 `dnd-kit`** 을 쓴다(`roadmap.md` §7 기재 · `patterns.md` §5). 새 라이브러리를 들이지 않는다.
8. **클라이언트 필터 함수를 만들지 않는다** — 서버가 `searchKey`·`useYn`·`switchYn`·`courseStatus` 를 제공한다. ⚠️ **실제로 걸리는지는 Phase 1 에서 확인**한다(지점은 Phase 8 R2 에서 확인했고 전부 걸렸다).

### 비즈니스 규칙

9. **생성은 명칭·설명만.** 🔴 `AddCourse` 에 `points` 를 보내지 않는다 — 보내도 무시되고(B-27) **성공 응답이 와서 조용히 반쪽**이 된다.
10. **지점 편성은 상세에서** 한다(목업 `코스수정.png`·`코스관리-신규.png`).
11. 🔴 **교대 허용·코스 활성화는 확인 모달을 거친다.** 둘 다 모달이되 **문구를 다르게**:
    - **코스 활성화 OFF** — "비활성화하면 근무자 앱에서 이 코스의 순찰이 더 이상 배정되지 않습니다."
    - **교대 허용** — 담백한 확인
    ⚠️ **옵티미스틱을 쓰지 않는다** — 모달로 의도를 확인했으므로 응답을 기다려도 된다. 둘은 같이 쓸 수 없다(`patterns.md` §10 갱신 대상).
12. 🔴 **지점 0개 코스에 자동 조치를 하지 않는다**(0-2 #3). 비활성화도, 경고 배너도, 저장 차단도 없다.
13. **삭제 성공 → 목록 복귀 / 실패 → 머문다**(027 승계).

## 4. 엣지 케이스

| 상황 | 처리 |
|---|---|
| 🔴 **생성 직후 상세로 보내고 싶다** | `AddCourse` 가 **`courseSeq` 를 주지 않는다.** → **목록으로 돌아가 재조회**한다. 이름으로 찾아 이동하는 것은 **하지 않는다** — 같은 이름이 있으면 **엉뚱한 코스로** 간다 |
| 🔴 **편성 중 저장이 실패** | `points` 전량 전송이라 실패하면 **아무것도 안 바뀐다**(부분 반영 없음). 화면 상태를 유지하고 재시도하게 한다 |
| **편성된 지점이 다른 곳에서 삭제됨** | 🔴 `DeletePoint` 는 코스 편성을 **무시하고 삭제**한다(OQ-10 실측). 코스 상세를 열면 그 지점이 **이미 빠져 있다** — 우리가 할 일은 없고, 재조회로 수렴 |
| 없는 `courseSeq` 로 직접 접근 | 400 + 래퍼. **안내 + 목록 복귀 수단**(`/404` 아님 — 027 승계) |
| 지점 0개 코스의 상세 | 다이어그램 자리에 **빈 상태** + "지점 추가" 유도. ⚠️ **"준비 중" 이 아니다**(기능은 있고 데이터가 없다 — 027 placeholder 규약) |
| 필터 결과 0건 | "조건에 맞는 코스가 없습니다" + **필터 초기화**(027 승계). 조회 실패·로딩과 **셋을 구분** |
| 드래그 중 저장 실패 | 순서를 **원복**한다. 화면만 바뀌고 서버가 안 바뀌면 다음 조회에서 되돌아가 혼란스럽다 |

| OQ-023-D | **공용 셸 승격**(027 규칙 4 이월). 코스 상세는 다이어그램·드래그가 있어 지점 상세와 **모양이 꽤 다르다** — 뽑지 않는 결론도 정당하다. Phase 5 에서 판단 |
| OQ-023-E | **`UpdateCourse` 가 PATCH 로 바뀌면**(B-24 요청) `points` 의미도 함께 정해져야 한다(B-25). 바뀌면 규칙 3 을 재검토 |
| OQ-023-F | **코스 활성화 ↔ 순찰 배정의 실제 관계** 미확인. 규칙 11 의 모달 문구("순찰이 배정되지 않습니다")가 **사실인지** 업무 확인 필요 — 틀리면 **틀린 경고**다 |
