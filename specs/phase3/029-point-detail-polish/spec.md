## User Stories

- **US1.** 현장관리자가 지점 상세에서 **값을 보여 주는 카드에서 바로** 수정에 들어간다
  (코스 상세와 같은 규칙).
- **US2.** 현장관리자가 **인증수단을 지점 상세에서 직접 바꾼다** — QR↔NFC 를 고르고,
  NFC 로 바꿀 때는 TAG ID 를 함께 등록한다.
- **US3.** 현장관리자가 그 지점의 **QR 을 실제로 본다** — 아이콘이 아니라 근무자 단말이
  읽는 그 코드다.

---

## 1. 목적

지점 상세를 **읽기 전용 카드 모음**에서 **그 지점을 실제로 다루는 화면**으로 바꾼다.

027 이 화면을 만들 때는 인증수단이 조회값뿐이었고(폼에서만 바꿀 수 있었다), QR 은 서버에
식별자가 없다고 보아 placeholder 였으며, 변경 이력은 API 가 없어 빈 자리였다. 그 전제 중
**둘이 틀렸다** — `qrCode` 는 서버에 있었고, 인증수단은 `UpdatePoint` 로 바꿀 수 있다.
남은 하나(변경 이력)는 여전히 없고, 앞으로도 언제 생길지 모른다 → **치운다.**

## 2. I/O

### Input

| 출처 | 값 |
|---|---|
| `DetailPoint?pointSeq=` | `authMethod` · `authMethodName` · **`qrCode`** · `nfcTagId` · `useYn` · `memo` · `courseList` … |
| 사용자 입력 | 인증수단 선택(QR/NFC) · **NFC TAG ID 14자리 HEX** |

### Output

| 동작 | 호출 |
|---|---|
| 인증수단 전환 | `PATCH UpdatePoint` — `{ pointSeq, authMethod, nfcTagId? , reissueQrYn: false }` |
| 성공 후 | `pointKeys.detail` 무효화 → 카드가 새 값으로 다시 그려진다 |
| QR 표시 | **호출 없음** — `qrCode` 문자열을 클라이언트에서 이미지로 그린다 |

## 3. 제약

### 🔴 실측이 바꾼 것 (WF-1-0, 2026-10-13)

| 실측 | 설계에 미친 영향 |
|---|---|
| `authMethod: 10` 인데 `nfcTagId` 가 없으면 **400 `"NFC 값을 입력해주세요."`** | 🔴🔴 **스위치만으로는 NFC 로 바꿀 수 없다.** "클릭 → 확인 모달 → 저장" 이 **QR 방향에서만** 성립한다. **전환 방향이 비대칭**인 것이 이 spec 의 핵심 설계다 |
| NFC→QR 후 **`nfcTagId` 가 남는다**. `null`·`''` 로도 **못 지운다**(200인데 무시, B-15) | QR 지점에 쓰이지 않는 TAG ID 가 남는다 → **화면에서 보여 주지 않는다**(수단이 QR 이면 TAG ID 섹션 자체가 없다). 서버 값 정리는 백엔드 몫 |
| QR→NFC 후 **`qrCode` 가 남는다** | 같은 규칙 — **지금 쓰는 수단의 자격증명만** 그린다 |
| 🔴 **`reissueQrYn: true` 가 동작하지 않는다**(200인데 `qrCode` 그대로, **B-37**) | **QR 재발행 버튼을 만들지 않는다.** 누르면 성공 토스트가 뜨는데 코드는 그대로인, 가장 나쁜 종류의 버튼이 된다(A1) |
| 전환 실패 메시지가 **사유를 말해 준다**(B-17 의 예외) | 전역 토스트에 **서버 문구를 그대로** 노출한다 — 우리가 다시 쓰지 않는다 |

### 기술 제약

- 재사용: `AppDialog` · `AppAlertDialog` · `AppBadge` · `AppDetailRow` · `AppIconButton` ·
  `EditPointForm` · `usePointDetail` · `pointKeys`
- **NFC TAG ID 검증은 기존 zod 스키마를 쓴다**(`features/points/form/schema.ts` — 14자리
  HEX). 전환 모달용으로 **새 검증을 만들지 않는다**
- QR 이미지: **패키지 1건 추가**(`qrcode` 계열). `components.md` 에 컨벤션 등재.
  🔴 **인코딩 대상은 서버가 준 `qrCode` 문자열 그대로** — 우리가 조합하지 않는다
  (앱이 읽는 값이라 한 글자만 달라도 인증이 안 된다)

### 비즈니스 규칙

1. **수정 버튼은 기본정보 카드로.** 헤더에는 **삭제만** 남는다 — 코스 상세와 같은 규칙
   (고치려는 값을 보여 주는 카드에 수단을 둔다 / 삭제는 지점 전체에 대한 동작이라 어느
   카드에도 속하지 않는다).
2. 🔴 **인증수단 전환은 방향에 따라 다르다.**

   | 방향 | 흐름 | 이유 |
   |---|---|---|
   | **NFC → QR** | 확인 모달 → `UpdatePoint` | 추가로 받을 값이 없다 |
   | **QR → NFC** | **TAG ID 입력 모달**(14자리 HEX) → `UpdatePoint` | TAG ID 없이 보내면 **400** 이다 |

3. **옵티미스틱이 아니다**(코스 토글과 같은 규약, `patterns.md` §10-B). 확인받은 변경을
   먼저 반영했다 되돌리면, 사용자는 방금 확인한 일이 취소된 것을 토스트로만 알게 된다.
   🔴 **스위치는 저장이 성공해야 움직인다** — 서버에 "TAG ID 없이 NFC 로 바꾸는" 경로가
   아예 없으므로(400), 눌린 즉시 바뀌는 스위치는 **거짓말이 될 수밖에 없다**.

2-1. 🔴 **인증수단을 수정 모달에서 뺀다**(사용자 결정 2026-10-13). 전환 수단이 두 곳이면
   같은 일을 하는 길이 둘이 되고, 그중 하나(폼)는 **TAG ID 를 비워도 저장되는 것처럼**
   보인다. 전환은 **상세 카드의 스위치 한 곳**에서만 한다.
   ⚠️ **단 TAG ID 필드는 남긴다** — 수단은 그대로 두고 **태그만 교체**하는 경우(물리
   태그 분실·파손)가 있다. 🔴 **NFC 지점일 때만** 보인다(QR 지점에는 쓰이지 않는 값이
   남아 있을 수 있는데, 그걸 폼에 띄우면 바꿀 수 있는 값처럼 보인다 — §3 실측표).
   검증(14자리 HEX)은 **기존 zod 스키마 한 곳**을 전환 모달과 공유한다.
4. **자격증명 카드는 현재 수단 것만 그린다** — QR 이면 QR 이미지+식별자, NFC 면 TAG ID.
   남아 있는 반대쪽 값은 **보여 주지 않는다**(위 실측표).
5. **QR 다운로드는 범위 안으로 들어왔다**(사용자 결정 2026-10-13, 브라우저 확인 중 변경) —
   화면에 그리지 않기로 하면서 **내려받기가 유일한 사용 경로**가 됐다. 인쇄·재발행은
   여전히 범위 밖이다(재발행은 **B-37** 이 풀려야 하고, 인쇄 산출물 형태는 OQ-029-A).
6. **변경 이력 섹션을 제거한다**(OQ-027-E 종결). 🔴 027 은 "지우면 설계에 없던 것이 되어
   다시 논의해야 한다" 는 이유로 남겼는데, **그 논의를 지금 했다** — API(B-22)가 없고
   생길 일정도 없다. 자리만 차지하는 빈 카드가 더 나쁘다.
7. 우측 칸이 자격증명 카드 하나가 되므로 **2열 비율을 재검토**한다(QR 카드가 커진다).

## 4. 엣지 케이스 (A급 — 풀 작성)

| 상황 | 처리 |
|---|---|
| QR→NFC 모달에서 **TAG ID 형식 오류** | 제출 전 zod 가 막는다. 🔴 **022 선례**: 에러 바인딩을 틀리면 메시지가 뜰 자리가 없다 — 테스트로 고정 |
| TAG ID 를 맞게 넣었는데 **서버가 400** | 전역 토스트가 **서버 문구 그대로**(`"NFC 값을 입력해주세요."` 등). 모달은 **닫지 않는다** — 닫으면 입력값이 사라진다 |
| 전환 **성공** | 모달 닫기 → `detail` 무효화. 자격증명 카드가 **반대쪽으로 교체**된다 |
| 전환 중 **연타** | 저장 중 스위치·제출 버튼을 잠근다(코스 토글과 같은 처리) |
| `qrCode` 가 **`null`** | QR 수단인데 코드가 없는 상태. 🔴 "준비 중" 이 아니라 **"QR 코드가 발급되지 않았습니다"** — 생성 시 서버가 발급하므로 이건 **이상 상태**다 |
| `nfcTagId` 가 **`null`** 인 NFC 지점 | 기존 문구 유지(B-13 — 서버가 강제하지 않는다). ⚠️ 단 **우리 화면을 통해서는 만들 수 없다**(400) |
| 네트워크 실패 | 019 정규화 → 전역 토스트. 모달 유지 |
| 권한 | 현장관리자 기준. `RequireRole` 은 기존 화면 규칙을 따른다 |

      **식별자 문자열도 숨긴다**(그게 곧 QR 의 내용이다). 아이콘을 누르면 **PNG 로 내려받는다**
