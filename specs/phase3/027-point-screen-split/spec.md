# 027-point-screen-split spec

> 순찰지점 화면 재구성 — 좌/우 마스터-디테일을 **목록 페이지 + 상세 페이지**로 분리하고,
> `spec 022`에서 이월된 검색·필터·페이지 이동을 새 구조 안에서 수행한다.
>
> **위험도 B** (`screens.md` §1-3 `/points` 행 승계). 3축 + 필요한 엣지만.
>
> 🔴 **번호 주의** — 실행 순서는 `022 → 027 → 023`이고 **번호 순서와 다르다.**
> `023~026`이 여러 문서에서 이미 참조돼 밀 수 없어 맨 뒤 번호를 썼다
> (`roadmap.md` §7-1, 사용자 결정 2026-10-08).

## User Stories

- **US1.** 현장관리자는 `/points`에서 **전체 폭 테이블**로 지점 목록을 보고, 행을 눌러 상세로 이동한다.
- **US2.** 현장관리자는 `/points/:pointSeq` **상세 페이지**에서 지점 정보를 보고 수정·삭제한다(편집은 **모달 유지**).
- **US3.** 현장관리자는 목록에서 **검색·인증수단·사용여부**로 거르고 페이지를 넘기며, 그 상태가 **URL에 보존**된다.

---

## 1. 목적

좌측 340px 목록 + 우측 상세 패널 구조를 걷어낸다. 세 가지가 동시에 걸려 있다.

1. **필터가 들어갈 자리가 없다.** 340px에 인증수단·사용여부 필터 + 페이지 이동을 넣으면 지점 이름이 잘린다. `OQ-022-E`가 이미 이 이유로 배치 확정을 미뤘다(2026-10-07).
2. **분할화면에서 가장 먼저 깨지는 패턴이다.** `CLAUDE.md` B4는 "PC 기준 + 모바일은 **분할화면 대응 UI만**"인데, 좌우 2단은 폭이 줄면 둘 다 못 쓴다.
3. **상세가 URL에 없다.** 선택 상태가 `useState`라 **새로고침하면 날아가고** 딥링크·뒤로가기가 없다. `CLAUDE.md` B4의 "상태는 URL에 저장" 방향과도 어긋난다.

**하지 않는 것**: 코스 화면(`/zones`) 재구성은 **범위 밖**이다. 코스는 아직 mock 위에 있고 API 전환이 `spec 023`이라, 같은 파일을 두 spec이 연속으로 만지게 된다. 027은 **지점으로 패턴을 확립**하고 023이 그 패턴을 적용한다(사용자 결정 2026-10-08).

## 2. I/O

### Input

- **목록**: `GetPointList` — `siteSeq`(필수, `getSiteSeq()`) + `searchKey` · `authMethod` · `useYn` · `pageNumber`(1-based) · `pageSize`
- **상세**: `DetailPoint(pointSeq)` — URL 파라미터에서 온다
- **URL 쿼리**: `search` · `authMethod` · `useYn` · `page`
- 🔴 `siteSeq`는 **URL에 노출하지 않는다**(`spec 021` DoD #13 승계)

### Output

| 라우트 | 화면 |
|---|---|
| `/points` | 코스/지점 탭 + 필터 바 + **전체 폭 테이블** + 하단 `AppPagination` + 추가 버튼 |
| `/points/:pointSeq` | 뒤로가기 + 지점명 헤더 + 기본정보·소속 코스·인증수단 + **수정/삭제 액션**(모달) |

**목록 컬럼** (`PointRow` 9필드 기준)

| 컬럼 | 필드 | 비고 |
|---|---|---|
| 지점명 | `pointName` | 미사용이면 **행 전체 톤다운** |
| 설명 | `memo` | `null` → `-` |
| 인증수단 | `authMethod`·`authMethodName` | 뱃지. 미실측 코드면 뱃지를 숨긴다(022 규칙 승계) |
| TAG ID | `nfcTagId` | `null` → `-`. ⚠️ **NFC인데 null인 실 데이터가 있다**(B-13) |
| 소속 코스 | `usedCount` | 숫자 |
| 최근 순찰 | `lastPatrolDt` | 없으면 "기록 없음" |
| 사용여부 | `useYn` | **뱃지**(사용/미사용) |

## 3. 제약

### 기술 제약

1. **라우트는 기존 관례를 따른다** — `paths.ts`에 빌더 + `pathPatterns`에 패턴. `noticeDetail`(`/notice/:id`) 선례와 동일한 모양으로 `pointDetail(pointSeq)` / `/points/:pointSeq`. 새 관례를 만들지 않는다.
2. **목록 시각은 `/patrol/points`를 따른다** — `AppTable` + 컬럼 팩토리 + `hidePagination` + 외부 `AppPagination`. 목업 기준은 `docs/ui-mock/현장/순찰이력/지점순찰이력-신규.png`.
3. 🔴 **`AppFilterPopover`를 신설한다.** `AppFilterButton`은 **시각 트리거만** 있고 조립 사례가 **0건**이다(주석: "콘텐츠 조립은 소비 측 책임"). `/patrol/points` 5개·`/users` 2개가 **죽은 버튼**으로 대기 중이다. 027이 처음 동작하게 만들고, 그 컴포넌트를 공용으로 둔다.
4. 🔴 **공용 셸은 뽑지 않는다.** 목록 페이지 셸 · 상세 페이지 셸 · `useListQueryParams`는 **`spec 023`에서 승격 검토**한다. 027 하나로는 패턴인지 알 수 없고, 코스 상세는 경로 다이어그램 + 드래그 편집이 들어가 모양이 다를 수 있다(`screens.md:71`) — 섣불리 뽑으면 틀린 추상화가 된다(`CLAUDE.md` A6 + global 승격 정책 "두 번째 반복에서 승격").
5. **필터 규약은 018을 승계한다** — `ALL_VALUE`("전체"는 URL에 남기지 않음) + `setParams(..., { replace: true })` + **필터 변경 시 첫 페이지 복귀**.
6. **검색은 300ms 디바운스.** 없으면 글자 수만큼 요청이 나간다.
7. **클라이언트 필터 함수를 만들지 않는다.** 전부 서버 파라미터로 보낸다(022 규칙 8 승계, Phase 8 R2에서 서버 동작 실측 완료).
8. `pageNumber`(1-based) ↔ `pageIndex`(0-based) 변환은 **`lib/pointListParams.ts` 한 자리**에만 둔다(022 승계).
9. **`queryKey` 규약을 바꾸지 않는다** — `data-model.md` §8 그대로. 상세가 라우트가 되어도 키는 `['point', pointSeq]`다.

### 비즈니스 규칙

10. **편집은 모달 유지.** `screens.md:75`가 "리디자인 후에도 편집은 모달, 상세는 조회용 카드"로 이미 정해 뒀다. 상세 **페이지 안의** 모달이 된다.
11. 🔴 **`pointSeq` 고정 장치가 불필요해진다.** 022 T266은 "모달이 열린 채 뒤쪽 목록에서 다른 지점을 고르면 저장이 엉뚱한 지점에 간다"를 `useState` 초기값으로 막았다. 상세가 페이지면 **뒤에 목록이 없어** 그 경로가 사라진다. 다만 **고정 자체를 제거하지는 않는다**(해가 없고, 제거하면 테스트도 함께 지워야 한다 — A3).
12. **미사용 지점은 컬럼 + 행 톤다운 둘 다.** 전체 폭이라 뱃지 자리가 생겼다. `design-system.md` §3("색만으로 상태 전달 금지")을 뱃지가 정식으로 충족하므로, 022에서 넣은 `sr-only`는 **뱃지로 대체**한다(중복 낭독 방지).
13. **삭제 성공 후 목록으로 돌아간다.** 상세가 페이지라 그 자리에 머물 수 없다. 🔴 **실패하면 머문다**(022 규칙 승계 — 거부인데 화면이 바뀌면 삭제된 것처럼 보인다).
14. **`CourseTabs`의 활성 판정을 고친다.** 현재 `end`가 붙어 있어 **`/points/49`에서 "지점" 탭이 꺼진다.** 상세 페이지에서 탭이 둘 다 꺼진 상태가 된다.

## 4. 엣지 케이스

| 상황 | 처리 |
|---|---|
| 없는 `pointSeq`로 직접 접근 (`/points/999999`) | 서버가 **400 + `"잘못된 요청입니다."`**(실측). 목록으로 돌아가는 수단과 함께 안내. 🔴 **`/404`로 보내지 않는다** — 사업장이 다르거나 삭제된 경우라 "경로 없음"이 아니다 |
| 다른 사업장의 `pointSeq`로 직접 접근 | 🔴 **서버가 막지 않는다**(B-9 — `siteSeq` 권한 미검사, 실측). 상세는 열린다. 프론트가 할 수 있는 것은 없고 **백엔드 요청 대기**. 본 spec에서 추측 방어를 넣지 않는다(A1) |
| 상세에서 삭제 → 뒤로가기 | 목록으로 돌아간 뒤 뒤로가기를 누르면 없는 상세로 간다. 위 "없는 `pointSeq`" 처리로 수렴 |
| 필터 결과가 0건 | `AppEmpty`로 "조건에 맞는 지점이 없습니다". 🔴 **조회 실패와 다르게 그린다**(022 승계 — 둘 다 "아무것도 없음"이면 장애를 데이터 없음으로 오해한다) |
| 사업장 미선택(`siteSeq === null`) | 조회하지 않는다(022 승계). `AuthGuard`가 이미 현장 영역을 차단한다 |
| 마지막 페이지에서 마지막 항목 삭제 | 목록 복귀 시 현재 `page`가 범위를 벗어난다. 서버는 **에러가 아니라 빈 items + 요청값 에코**(실측)이므로 빈 화면이 된다 → **첫 페이지로 되돌린다** |

## 5. 완료 조건 (DoD)

WF-4에서 증거(`파일:라인`) 명시 필요.

- [ ] 1. `/points`가 **전체 폭 테이블**이고 좌/우 2단 구조가 **남아 있지 않다** (US1)
- [ ] 2. 행 클릭 → `/points/:pointSeq`로 이동하고, **새로고침해도 그 상세가 유지된다** (US2)
- [ ] 3. `paths.ts`에 빌더 + `pathPatterns`에 패턴이 `noticeDetail`과 **같은 모양**으로 있다 (규칙 1)
- [ ] 4. 상세 페이지에서 수정·삭제가 동작하고 **편집은 모달**이다 (US2, 규칙 10)
- [ ] 5. 삭제 **성공** 시 목록으로 복귀, **실패** 시 상세에 머문다 (규칙 13)
- [ ] 6. `/points/:pointSeq`에서 **"지점" 탭이 활성화**된다 (규칙 14)
- [ ] 7. 검색(디바운스 300ms)·인증수단·사용여부가 **서버 파라미터로** 나가고 URL에 보존된다. **클라이언트 필터 함수 0건** (US3, 규칙 5~7)
- [ ] 8. 필터 변경 시 **첫 페이지로 복귀**하고, "전체"는 URL에 남지 않는다 (규칙 5)
- [ ] 9. `AppPagination` **전체 부착**(행수 셀렉트 + 범위 + 이전/다음)이 동작한다 — OQ-022-E 해소
- [ ] 10. 🔴 `AppFilterPopover`가 **공용 컴포넌트로** 신설되고, `/points`가 그것을 쓴다 (규칙 3)
- [ ] 11. 목록 셸·상세 셸·URL 훅을 **공용으로 뽑지 않았다** (규칙 4 — 023에서 승격 검토)
- [ ] 12. 미사용 지점이 **사용여부 컬럼 + 행 톤다운** 둘 다로 구분되고, 022의 `sr-only`는 제거됐다 (규칙 12)
- [ ] 13. 없는 `pointSeq` 직접 접근이 **안내 + 목록 복귀 수단**으로 처리된다 (`/404` 아님)
- [ ] 14. 필터 0건과 조회 실패가 **다르게** 그려진다
- [ ] 15. `npm run verify` 0 errors + `npm run test` green
- [ ] 16. 🔴 `npm run capture` baseline 재촬영 — `points--목록+상세` → **새 구조 2장**(목록·상세)으로 교체되고 **나머지가 깨지지 않았다**
- [ ] 17. 브라우저 확인(MSW 모드) — 목록·상세·추가·수정·삭제·검색·필터·페이지 이동 + **분할화면 폭**
- [ ] 18. 문서 동기화: `screens.md` §1-3·§4 라우트 매핑 / `flow.md` §0 / `patterns.md`(`AppFilterPopover` 등재) / `roadmap.md` §7-1·§12
