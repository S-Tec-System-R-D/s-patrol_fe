## User Stories

- **US1.** 본사 관리자가 `/admin/admins` 에서 트리로 고른 그룹에 할당된 **관리자 목록**을 본다(이름 · 권한 · 담당 그룹). 이름으로 찾고 권한으로 거른다.
- **US2.** 본사 관리자가 행을 눌러 **관리자 상세 모달**에서 사번 · 연락처와 담당 그룹 목록을 본다.
- **US3.** 관리자 계정 **추가 · 정보 수정 · 비밀번호 변경 · 삭제**는 자리만 있고 막혀 있다(관리자 API 없음 — B-59).
- **US4.** 시스템관리자 · Master 가 상세 모달에서 관리자의 **담당 그룹을 추가하고 해제**한다.

---

## 1. 목적

`/admin/admins` 는 043 의 placeholder 다. 본 spec 은 **본사 관리자가 누가 있고 어느 그룹을 맡는지 보고, 맡는 그룹을 바꾸는 것**을 서버 위에서
동작시킨다. 🔴 원칙(`roadmap.md` §9-0): **서버에 있는 것만 동작시킨다.** 관리자 계정 생성 · 수정 · 삭제는 관리자 전용 API 가 없다 —
`AddUser`·`UpdateUser`·`RemoveUser` 는 현장용이고(사용자 전달 2026-10-23), `AddUser` 로 만든 관리자는 **사업장에 묶여 사업장과 함께 지워진다**(B-59).
그래서 계정 관리는 **자리만 두고 막는다**(사용자 결정 2026-10-23). 실제로 동작하는 쓰기는 **담당 그룹 할당**(`UpdateGroup`) 하나다.

## 2. I/O

### 2-1. API (실측 확정 — `api-spec.md` §5-1-B "관리그룹 3종" · "본사 관리자" · §5-2)

| API | 요청 | 응답 `data` | 쓰는 곳 |
|---|---|---|---|
| `GET Login/W/sign/AdminSiteSelect` | — | `GroupNode`(043 그대로) | 좌측 트리 · 그룹 목록(할당 조회 대상) · 그룹 경로 |
| `GET Group/W/sign/GetGroupAdminList` | `?groupSeq` | `GroupAdminRow[]` | 🔴 **트리의 그룹마다** 호출 → 관리자 행 + 관리자별 담당 그룹 |
| `GET User/W/sign/UserDetail` | `?userId` | `UserDetail`(038 타입 그대로) | 상세 모달의 사번 · 연락처 |
| `PUT Group/W/sign/UpdateGroup` | `{ groupSeq, parentGroupSeq, groupName, userSeq[] }` | `true` | 담당 그룹 추가 · 해제 |

```ts
// api-spec.md §5-2 그대로 — 043 `features/groups/types` 에 이미 있다. 어댑터 없음
interface GroupAdminRow { userSeq: number; codeSeq: number; codeName: string; userName: string; isInclude: boolean }
```

- 🔴 **관리자 목록 API 는 없다**(B-61). `GetGroupAdminList` 는 어느 그룹으로 불러도 **본사 관리자 전원**(`codeSeq` 2·3·4)을 같은 행 집합으로 주고 `isInclude` 만 다르다.
  → **관리자 행** = 아무 그룹 응답의 행(트리 루트 것을 쓴다) / **담당 그룹** = `isInclude: true` 인 그룹들(사용자 결정 2026-10-23 — 그룹마다 조회).
- 🔴 **그룹 범위는 트리가 정한다** — Master · Manager 의 `AdminSiteSelect` 는 **할당된 그룹만** 준다(실측). 그 밖의 그룹 할당은 조회하지 않으니 보이지 않는다.
- 🔴 `UserDetail` 은 관리자에게 `siteSeq: 0` · `siteName: null` 이다 — 쓰지 않는다.

### 2-2. 화면 — 관리자 목록 (US1)

목업 `ManagersPage`. 043 의 패널/시트 · `?group` 은 그대로.

- 머리: `AppPageHeader` "관리자" + 부제 "본사 직원 계정과 담당 그룹을 관리합니다" + 오른쪽 **[관리자 추가] disabled**(US3).
- 좌측 트리: `unitLabel="관리자"` · 그룹 옆 수 = 그 그룹 + 자손 그룹에 **할당된 관리자 수**(중복 제거). [편집] 링크는 043 그대로(MANAGER 없음).
- 필터 줄: (XL 미만) 경로 버튼 · **검색**(이름, 클라이언트) · **권한 세그먼트** 전체 / 마스터 / 매니저.
  - URL: `?q=` · `?role=master|manager`(B4). 잘못된 `role` 값은 전체로 본다.
  - 목업의 연락처 검색 · 상태 세그먼트는 **없다**.
- 범위: 선택 그룹이 **최상위(`parentGroupSeq === null`)면 전원**(미할당 포함) · 그 외는 선택 그룹 + 자손 그룹에 할당된 관리자. 순서는 응답 순서.
- 표 열: **이름** · **권한**(`AppBadge` — 시스템관리자 / 마스터 / 매니저, `codeSeq` 2·3·4) · **담당 그룹**(첫 그룹 경로 `본부 › 지사` + `외 N개`, 없으면 `—`).
  - 목업의 소속 그룹 · 연락처 · 상태 열은 **없다**. 담당 사업장 수 → 담당 그룹으로 바뀐다.
  - 권한 표시는 `codeName` 이 아니라 `codeSeq` 로 정한다(`codeName` 은 `관리자` 라 목업 용어 "마스터" 와 다르다).
- 행 클릭 → 상세 모달(US2). 표 아래 "총 N명".
- 빈 상태: 범위에 관리자 0 → "이 그룹에 할당된 관리자가 없습니다." / 검색 · 필터 결과 0 → "검색 결과가 없습니다."
- 🔴 **페이지네이션 없음** — 관리자는 수 명이다(실데이터 5명).

### 2-3. 화면 — 관리자 상세 모달 (US2)

목업 `ManagerModal`(680px). 모달 열림 상태는 URL 에 두지 않는다(검색 · 필터가 아니다).

- 머리: **이름** + 권한 뱃지. 목업의 상태 뱃지 · 소속 그룹 경로 부제는 없다.
- 좌: **기본 정보** — 사번(`loginId`) · 연락처(`phone`, 038 표시 규칙). `UserDetail` 조회 중 스켈레톤 · 실패 시 이 칸에만 "정보를 불러오지 못했습니다." + [다시 시도].
  - 목업의 소속 그룹 · 사용자 상태 · 등록일 행은 **없다**.
- 우: **담당 그룹 N** — 행마다 그룹 경로 + [해제](US4) · 아래 [+ 그룹 추가](US4). 없으면 "지정된 담당 그룹이 없습니다."
- 하단:
  - 시스템관리자가 아닌 관리자: [삭제] · [비밀번호] · [수정] — **모두 disabled**(US3). 목업의 [활성화/비활성화] 는 **없다**.
  - 시스템관리자(`codeSeq 2`): [닫기]만 + 잠금 안내 "시스템관리자는 시스템 구축 시 생성된 계정으로 수정·삭제할 수 없습니다. 담당 그룹은 변경할 수 있습니다."

### 2-4. 계정 관리 자리 (US3)

- [관리자 추가] · [수정] · [비밀번호] · [삭제] 는 **disabled + 툴팁 "관리자 계정 관리는 아직 지원되지 않습니다"**.
- 🔴 **폼 · 모달은 만들지 않는다**(A6) — API(B-59)가 오면 그 계약으로 만든다. 그때 쓸 규칙만 남긴다:
  생성 권한 시스템관리자 → 마스터 · 마스터 → 매니저(목업 `CREATABLE_ROLE`) · 시스템관리자 계정 수정 · 삭제 불가 · 비밀번호는 041 `PasswordForm` 재사용 후보.
- 🔴 서버는 이 규칙을 검사하지 않는다(B-60) — 열 때 화면이 막아야 한다.

### 2-5. 담당 그룹 추가 · 해제 (US4)

**누가** — 시스템관리자 · Master. 🔴 **MANAGER 에게는 [+ 그룹 추가] · [해제] 를 그리지 않는다**(실측 403). Master 는 트리가 이미 자기 할당 그룹으로 좁혀져 있어 선택지도 그 안이다(서버도 할당 밖 그룹은 403).

**추가**(목업 `AssignSiteModal` → 그룹 선택, `AppDialog` 520px "담당 그룹 추가" / "{이름} 관리자가 맡을 그룹을 선택합니다.")
- 선택지: 트리의 그룹을 단계 들여쓰기로(`본부` → `지사`) · 다중 선택(`AppCheckbox`) · **이미 할당된 그룹과 최상위 그룹은 빼고**(OQ-045-A).
- 선택지 0 → "추가할 수 있는 그룹이 없습니다." · [추가 (N)] 은 1개 이상일 때만.
- 저장: 고른 그룹마다 **차례로** `GetGroupAdminList(g)` → `UpdateGroup({ groupSeq, parentGroupSeq, groupName, userSeq: 현재 isInclude ∪ {대상} })`.
  - 🔴 **현재 할당을 PUT 직전에 다시 읽는다**(043 `useRenameGroup` 과 같다) — 화면의 캐시로 보내면 그 사이 바뀐 할당을 지운다(B-50). 읽기가 실패하면 그 그룹은 **보내지 않는다**.
  - 🔴 첫 실패에서 멈춘다(나머지는 보내지 않는다). 실패 토스트는 전역(서버 문구) · 모달 유지 · 재조회로 어디까지 됐는지 보인다.
  - 전부 성공 → 모달 닫기 · 토스트 "담당 그룹을 추가했습니다."
- `groupName` · `parentGroupSeq` 는 트리 노드 값 그대로(이름 · 위치는 바꾸지 않는다).

**해제**
- 행의 [해제] → 그 그룹만 `GetGroupAdminList(g)` → `UpdateGroup(..., userSeq: 현재 isInclude − {대상})`. 확인창 없음(목업) · 처리 중 그 행 비활성 · 토스트 "담당 그룹에서 해제했습니다."
- 🔴 **최상위 그룹 행에는 [해제] 가 없다**(OQ-045-A).
- 🔴 **Master 가 자기 자신을 해제**하면 그 그룹 권한을 잃는다 → 이 경우만 `AppAlertDialog` "'{그룹}' 에서 해제하면 이 그룹을 더 이상 관리할 수 없습니다." 확인 후 진행.

**무효화** — 성공 · 실패 모두 관리자 할당 조회 전체(`GetGroupAdminList` 키 전부) + 트리(`AdminSiteSelect`, 자기 해제 시 범위가 바뀐다). 비옵티미스틱.

## 3. 제약

### 기술 제약

- 신설: `features/admins/` — `lib/`(관리자 행 · 담당 그룹 맵 · 범위 필터 · 검색 · 권한 필터 · 트리 수 — 순수 함수) · `hooks/`(그룹별 할당 조회 묶음 · 추가 · 해제) · `components/`(표 열 · 상세 모달 · 그룹 선택 모달).
- 교체: 라우트 `paths.admin.admins` 의 `AdminPlaceholderPage` → 관리자 목록 페이지. `AdminPlaceholderPage` 는 다른 사용처가 없으면 삭제.
- 재사용: 043 `GroupFilterPanel`/`Button` · `useGroupTree` · `useGroupParam` · `groupTree` · `getGroupAdminList` · `updateGroup` · `groupKeys` / 038 `getUserDetail` · `userFormat` / `AppPageHeader` · `AppDialog` · `AppAlertDialog` · `AppBadge` · `AppButton` · `AppIconButton` · `AppCheckbox` · `AppEmpty` · `AppDetailRow` · `AppTable` · `useQueryParams`. 대상 확정은 plan-first.
- 🔴 그룹별 조회는 `useQueries` 로 병렬 — 키는 043 의 `GetGroupAdminList` 키를 그대로 써서 043 이름 변경 직전 읽기와 캐시를 공유한다.
- MSW: 043 그룹 MSW 의 `GetGroupAdminList` 를 **상태 보유**로(그룹별 `isInclude` · `UpdateGroup.userSeq` 교체 반영) · 관리자 `UserDetail`(`siteSeq: 0`) · Manager `UpdateGroup` 403 래퍼 재현. 043 · 044 와 **한 출처**.
- 🔴 **비옵티미스틱** — 할당 변경은 성공 후 재조회로 그린다(서버가 ID · 결과를 주지 않는다).

### 비즈니스 규칙

1. **담당 = 그룹 할당** — 소속 그룹 · 담당 사업장 개념은 없다(사용자 결정 2026-10-23).
2. **계정 관리(추가 · 수정 · 비밀번호 · 삭제)는 막는다** — 관리자 API 대기(B-59). `UpdateUser`·`RemoveUser` 는 관리자에게도 동작하지만 쓰지 않는다(사용자 결정 2026-10-23).
3. **활성화 · 상태 · 등록일 · 목록 연락처는 넣지 않는다**(자리도 없다).
4. **할당 변경은 시스템관리자 · Master** — MANAGER 에게 조작 UI 없음.
5. **PUT 직전에 현재 할당을 다시 읽는다** — 읽기 실패 시 보내지 않는다(B-50).
6. **최상위 그룹 할당은 표시만** — 추가 선택지 · [해제] 없음(OQ-045-A).
7. **권한 표시는 `codeSeq`** — 2 시스템관리자 · 3 마스터 · 4 매니저.
8. 서버에 없는 권한 규칙(B-60)은 계정 관리가 열릴 때 화면이 건다 — 지금은 막혀 있어 걸 곳이 없다.

| 트리 또는 그룹별 할당 조회 로딩 | 표 스켈레톤 — 🔴 **전부 끝날 때까지** 그리지 않는다(일부만 받은 담당 그룹은 틀린 값이다) |
| 그룹별 할당 조회 중 하나라도 실패 | 표 자리에 실패 표시 + [다시 시도](실패한 것만 재요청). 좌측 패널은 별개 |
| `?group` 잘못됨 | 043 규칙 — 루트로 본다 |
| `?role` 잘못됨 | 전체로 본다 |
| 할당 0개인 Master(`AdminSiteSelect` 400) | 043 트리 실패 처리 그대로 — 관리자 목록도 그릴 수 없다(그룹이 없다). 실데이터상 드묾 |
| 상세 `UserDetail` 실패 · 그 사이 지워진 관리자(404) | 기본 정보 칸만 실패 표시 — 담당 그룹 칸은 목록 데이터로 그대로 |
| 추가 중 일부 그룹 실패 | 첫 실패에서 중단 · 전역 토스트 · 모달 유지 · 재조회로 성공분 반영(다시 열면 성공한 그룹은 선택지에서 빠져 있다) |
| 추가 직전 읽기 실패 | 그 그룹 PUT 0건 · 중단 |
| 남이 그룹을 지움(400 "관리그룹이 존재하지 않습니다.") | 토스트 · 재조회(그룹이 트리에서 사라진다) |
| 남이 관리자를 지움(`UpdateGroup` 없는 `userSeq` → 500, B-50) | 전역 토스트(일반 문구) · 재조회 — 관리자 행이 사라진다 · 모달 닫힘 |
| Master 가 자기 자신 해제 | 확인창 → 해제 후 트리 재조회로 그 그룹이 사라진다. 선택 중 `?group` 이 사라진 그룹이면 043 규칙(루트) |
| 해제 · 추가 연타 | 처리 중 버튼 비활성 — 요청 1회 |
| 선택 그룹에 관리자 0 + 검색어 있음 | "이 그룹에 할당된 관리자가 없습니다." 가 우선(검색 결과 문구 아님) |
