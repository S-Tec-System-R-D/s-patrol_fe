## User Stories

- **US1.** 본사 관리자가 `/admin/locations` 에서 트리로 고른 그룹 아래 **사업장 목록**을 본다(하위 그룹 포함 · 하위 사업장은 들여쓰기). 사업장명·주소로 찾고, 행을 누르면 상세로 간다.
- **US2.** 본사 관리자가 **사업장을 추가**한다(이름 · 소속 지사 · 주소 · 대표 연락처). 헬스체크는 추가할 때 받지 않는다 — 상세에서 켠다.
- **US3.** 본사 관리자가 **사업장 상세**에서 기본 정보(소속 그룹 · 주소 · 연락처 · 코스·지점 수 · 하위 사업장 수)를 보고, **정보를 수정**하고, **삭제**한다. 담당 관리자 카드에서 이 사업장 그룹에 할당된 관리자를 본다(조회만).
- **US4.** 본사 관리자가 상세의 **헬스체크 카드**에서 헬스체크를 켜고 끄며, 사용 시간 · 체크 주기 · 타임아웃 · 반복 횟수 · **예외 시간(여러 개)** 을 설정한다.
- **US5.** 화면이 서버의 **문자열 에러 body**((D), §3)를 서버 문구 그대로 보여 준다.

## 1. 목적

`/admin/locations` 는 043 에서 트리만 있고 본문이 비어 있다. 본 spec 은 **사업장 하나를 만들고 · 고치고 · 지우고 · 헬스체크를
설정하는 전 과정**을 서버 위에서 동작시킨다. 🔴 원칙(`roadmap.md` §9-0, 사용자 재확인 2026-10-23): **서버에 있는 것만
동작시킨다. 없는 것 중 필요한 것(비상연락망 · 담당 관리자)은 목업 자리를 두고 막아 두며
백엔드에 요청한다.** 필요 없는 것(운영상태 · 계약기간 · 목록 코스·지점 열)은 자리도 두지 않는다(사용자 재결정 2026-10-23). MSW 가정 계약은 쓰지 않는다(039 방식 아님).

## 2. I/O

### 2-1. API (실측 확정 — `api-spec.md` §5-1-B 사업장 3종 · §5-2)

| API | 요청 | 응답 `data` | 쓰는 곳 |
|---|---|---|---|
| `GET Group/W/sign/GetGroupList` | — (파라미터 없음) | `GroupListNode`(루트 1개) | 목록 · 상세의 소속 그룹 경로 · 하위 사업장 수 |
| `GET Site/W/sign/GetSiteDetail` | `?siteSeq` | `SiteDetail` | 상세 · 수정 폼 초기값 · 헬스체크 카드 |
| `POST Site/W/sign/AddSite` | `{ groupSeq, siteName, address, tel }` | `true`(ID 미반환) | 추가 |
| `PUT Site/W/sign/UpdateSite` | 아래 2-4 · 2-6 | `true` | 정보 수정 · 헬스체크 |
| `DELETE Site/W/sign/DeleteSite` | `?siteSeq` | `true` | 삭제 |
| `GET Group/W/sign/GetGroupAdminList` | `?groupSeq` | `GroupAdminRow[]` | 담당 관리자 카드(`isInclude: true` 만) |

```ts
// api-spec.md §5-2 그대로 — 응답 전량 선언(B4). 어댑터 없음
interface GroupListSite {
  siteSeq: number; siteName: string; siteGroupSeq: number; siteGroupName: string
  address: string | null; tel: string | null
  healthCheckYn: boolean   // 🔴 항상 false(B-55) — 선언만 하고 쓰지 않는다
  userCount: number; count: number; parentSiteSeq: number | null; children: GroupListSite[]
}
interface GroupListNode {
  groupSeq: number; groupName: string; parentGroupSeq: number | null
  layer: number; depth: number   // 🔴 depth 는 layer 와 어긋난다(B-55) — 단계는 layer 로만
  count: number; sites: GroupListSite[]; children: GroupListNode[]
}
interface SiteDetail {
  siteSeq: number; siteName: string; tel: string | null; address: string | null
  healthCheckYn: boolean; healthCheckInterval: number; healthCheckTimeout: number
  healthCheckRetry: number | null                                   // 최소 생성 시 null(실측)
  healthCheckStartTime: string | null; healthCheckEndTime: string | null  // 'HH:mm:ss' · 최소 생성 시 null
  exceptionTime: { detailSeq: number; exceptionStartTime: string; exceptionEndTime: string }[]
  userCount: number; courseCount: number; pointCount: number
}
```

- 🔴 `api-spec.md` §5-2 의 `SiteDetail` 은 `healthCheckRetry`·`StartTime`·`EndTime` 을 non-null 로 적었었다 — 최소 생성 사업장은 **`null`** 이다(실측 2026-10-23, WF-1 에서 문서 정정함).
- 🔴 **`GetSiteDetail` 에는 소속 그룹·모 사업장이 없다** — `GetGroupList` 에서 그 `siteSeq` 노드를 찾아 읽는다.
- 🔴 **ID 미반환** — 변경 후 재조회로 그린다(비옵티미스틱, 043 과 같다).
- 🔴 **트리 2개** — 좌측 관리그룹 패널은 043 그대로 `AdminSiteSelect`, 목록은 `GetGroupList`. 사업장 변경은 **둘 다** 무효화하고, 043 의 그룹 변경(특히 연쇄 삭제 B-51)도 `GetGroupList` 를 무효화하도록 넓힌다. 패널을 `GetGroupList` 로 바꿀지는 WF-3 plan-first 에서 판단한다(바꾸면 043 회귀 범위가 생긴다).

### 2-2. 화면 — 사업장 목록 (US1)

목업 `SitesPage`. 043 의 패널/시트 · `?group` 은 그대로.

- 머리: `AppPageHeader` "사업장" + 부제 "**{그룹명} 하위 사업장 N개**" + 오른쪽 **[사업장 추가]**(primary).
- 필터 줄: (XL 미만) 경로 버튼 · **검색**(사업장명 또는 주소, 클라이언트). 목업의 운영 상태 세그먼트는 **없다**(재결정 2026-10-23).
- 검색어는 URL `?q=` (B4 — URL 쿼리스트링).
- 표 열: **사업장명** · **소속 그룹**(경로 `본부 › 지사`) · **주소**(XL 이상) · **담당 관리자** `—`. 목업의 코스·지점 · 운영 상태 열은 **없다**.
  - XL 미만: 주소를 사업장명 아래 보조 줄로(목업).
  - 🔴 담당 관리자 `—` 는 **값이 없음을 뜻하는 고정 표기**다 — 툴팁 등 추가 장치는 두지 않는다(백엔드 반영 시 채운다).
- 🔴 **하위 사업장**: 모 사업장 바로 아래 행, 이름 앞 들여쓰기 + `└`. 검색에 하위만 걸리면 **모 사업장 행도 함께** 보인다(맥락 유지).
- 범위 = 선택 그룹 + 자손 그룹의 사업장(`children` 포함). 순서는 응답 순서.
- 행 클릭 → `/admin/locations/:siteSeq`. 표 아래 "총 N개".
- 빈 상태: 그룹에 사업장 0 → "이 그룹에 등록된 사업장이 없습니다." / 검색 결과 0 → "검색 결과가 없습니다."
- 🔴 **페이지네이션 없음** — 응답이 전체 트리이고 지사당 사업장이 적다(사용자 판단 2026-10-23).

### 2-3. 화면 — 사업장 추가 (US2)

목업 `SiteFormModal`(520px, "사업장 추가" / "새 사업장을 등록합니다.", [취소] [등록]).

| 필드 | 규칙 |
|---|---|
| 사업장명 | 필수 · 앞뒤 공백 제거 |

- 409 "동일한 위치에 같은 이름의 사업장이 이미 존재합니다." → 전역 토스트(서버 문구) · **모달 유지**(043 규약).

### 2-4. 화면 — 사업장 상세 (US3)

목업 `SiteDetail`. 라우트 `/admin/locations/:id`. 🔄 **재결정(사용자 2026-10-23)**: 목업의 KPI형 요약 · 탭을 쓰지 않고
**근무자 · 지점 상세와 같은 좌우 구조**로 한 화면에 둔다(탭이 없으니 `?tab` 도 없다).

- 머리: 뒤로(→ 목록, 이 사업장의 지사 `?group`) · 소속 그룹 경로 · **사업장명**. 액션은 머리에 두지 않는다.
- 좌 1/3: **기본정보 카드**(`AppDetailCard` + `AppDetailRow`) — 소속 그룹 · 주소 · 대표 연락처 · 순찰 코스 · 지점(`courseCount`개 · `pointCount`개) · 하위 사업장 N개(있을 때만). 카드 바로 아래 **[정보 수정] · [삭제]**(근무자 상세와 같다). 목업의 [운영 중지] · 계약 기간은 없다.
- 우 2/3: **담당 관리자 카드** → **헬스체크 카드**(제목 옆 `사용 · N분` / `미사용` 뱃지) → **비상연락망 카드**(US4).

**담당 관리자 카드(조회)**
- `GetGroupAdminList?groupSeq={소속 그룹}` 의 `isInclude: true` 행. 열: 이름 · 권한(`codeName`).
- 목업의 소속 그룹 · 연락처 열은 **없다**(행에 없음 — 045 판정 대상 "관리자 연락처"). 
- **[관리자 지정] disabled** — 할당은 그룹 단위이고 045 가 만든다(툴팁 "관리자 메뉴에서 그룹 단위로 지정합니다"). 행의 [지정 해제] 도 그리지 않는다.
- 빈 상태: "지정된 담당 관리자가 없습니다."
- ⚠️ 상위 그룹(본부·회사)에 할당된 관리자를 포함할지는 **OQ-044-A** — 기본은 소속 그룹 할당만.

**정보 수정**(같은 `SiteFormModal`, "사업장 정보 수정" / [저장])
- 초기값: 상세(`siteName` · `address` · `tel`) + 소속 그룹(`GetGroupList` 노드의 `siteGroupSeq`).
- 바디: `{ siteSeq, siteName, groupSeq, address, tel }` — 🔴 **연락처를 지우면 `""` 를 보낸다**(생략·`null` 은 유지로 처리된다, 실측). 주소는 필수라 비울 수 없다.
- 🔴 **하위 사업장이면 소속 그룹 disabled** — 서버가 400 "하위 사업장은 관리그룹을 변경할 수 없습니다…" 로 막는다(문구는 필드 도움말로 미리 보여 준다).
- 🔴 소속 그룹 변경은 **하위 사업장도 함께 옮긴다**(서버 동작) — 하위가 있으면 필드 도움말 "하위 사업장 N개도 함께 이동합니다."
- 🔴 현재 소속이 **지사가 아닌** 기존 사업장(실데이터: G1·G2·G4·G6 소속) — 선택지에 **현재 그룹을 1개 추가**해 그대로 저장할 수 있게 한다(바꾸면 지사만).

**삭제**(`AppAlertDialog`)
- 문구: "'{사업장명}' 사업장을 삭제합니다. **{하위 사업장 N개와 }순찰 코스 N개 · 지점 N개 · 근무자 N명 정보에 영향이 있습니다.** 삭제된 데이터는 복구할 수 없습니다." — 0인 항목은 뺀다. 수는 상세(`courseCount`·`pointCount`·`userCount`) + 목록 노드(`count`).
- 🔴 근무자·코스에 실제로 무슨 일이 생기는지는 **미실측**(B-54) — 문구는 "영향이 있습니다" 로만 쓰고 "삭제됩니다" 라고 단정하지 않는다. 하위 사업장과 지점은 **실측으로 함께 지워짐**을 확인했으나 같은 문장으로 묶는다.
- 성공 → 토스트 "사업장을 삭제했습니다." · 목록으로(`?group` 보존) · 두 트리 무효화.

### 2-5. 화면 — 헬스체크 · 비상연락망 카드 (US4, 상세 우측)

목업 `SiteDetail` 헬스체크 카드 + `HealthModal` + `Emergency`.

**헬스체크 카드**
- 머리: "헬스체크" + 오른쪽 `사용/미사용` 토글 + **[수정]**(미사용이면 disabled).
- 설명: "근무자 단말의 정상 동작 여부를 주기적으로 확인합니다. 설정 시간대에 응답이 없으면 비상연락망으로 알림이 발송됩니다."
- 값 칸: **사용 시간** `08:00 – 20:00` · **예외 시간**(여러 줄, 없으면 `없음`) · **체크 주기** `N분` · **타임아웃** `N` · **반복 횟수** `N회`. 미사용이면 흐리게(값은 남아 있다 — 서버가 유지).
  - 목업은 4칸(타임아웃 없음 · 예외 1개). 🔴 **타임아웃은 서버 필수**라 칸을 더한다. 단위는 **OQ-044-B**(미확인) — 표시는 숫자만.
- 표시 시각은 `HH:mm`(초 버림).

**토글**
- 🔴 **OFF → ON**: 저장된 값이 **비어 있으면**(`healthCheckInterval` 0 또는 시각 `null` — 최소 생성 사업장) 바로 저장하지 않고 **설정 모달을 연다**. 모달 저장이 곧 켜기다. 값이 있으면 `{ siteSeq, healthCheckYn: true }` 만 보낸다(서버가 저장된 값으로 검사한다, 실측).
- **ON → OFF**: `{ siteSeq, healthCheckYn: false }` — 값은 남는다.
- 토글은 처리 중 비활성 · 실패 시 원래 상태(비옵티미스틱).

**설정 모달**(500px, "헬스체크 설정 수정" / "단말 정상 동작 확인 시간과 주기를 설정합니다.")

| 필드 | 입력 · 화면 검증 |
|---|---|
| 사용 시작 · 사용 종료 | 시각(`HH:mm`) · 필수 · **같으면 안 된다**(서버 400과 같은 규칙). 시작 > 종료 허용(자정 넘김 — 서버도 받는다) |
| 체크 주기(분) | 정수 · 필수 · **1 이상** |
| 타임아웃 | 정수 · 필수 · **1 이상** |
| 반복 횟수 | 정수 · 필수 · **0 이상**(서버 0 허용 · 실데이터 있음) |
| 예외 시간 | 0개 이상 · 행마다 시작 · 종료(`HH:mm`) · [삭제] · 아래 [+ 예외 시간 추가]. 행 규칙은 **시작 ≠ 종료** 만(나머지는 OQ-044-C) |

- 바디: `{ siteSeq, healthCheckYn: true, healthCheckInterval, healthCheckTimeout, healthCheckRetry, healthCheckStartTime: 'HH:mm:00', healthCheckEndTime: 'HH:mm:00', exceptionTime: [...] }`
- 🔴 **예외 시간은 매번 전체 목록을 보낸다**(통째 교체, 실측) — 기존 행은 **자기 `detailSeq`**, 새 행은 **`detailSeq: 0`**. 지운 행은 목록에서 빠지면 서버가 지운다. 모두 지우면 `[]`.
- 🔴 시각은 `<input type="time">` 으로만 받는다 — 서버가 `25:00:00` 을 25일로 저장한다(B-53).
- 실패: 래퍼 문구("생체확인 간격을 정확히 입력해주세요." 등) · (D) 문자열 문구 모두 전역 토스트 · 모달 유지.

**비상연락망 카드** — 🔴 **자리만, 전부 disabled**(B-57)
- 목업 구조 그대로: 머리 "비상연락망" + 설명 "헬스체크 이상 감지 시 요일별로 지정된 담당자에게 알림이 발송됩니다." · 요일 7행(월~일, 주말 구분) 각각 `미지정` + [지정] disabled · 오른쪽 담당자 풀 빈 상태 + [+] disabled.
- 카드 머리 오른쪽 안내: "비상연락망은 아직 지원되지 않습니다".

### 2-6. 에러 형태 (D) (US5)

- `normalizeError` 에 **문자열 body** 분기를 더한다 — body 가 비지 않은 `string` 이면 그 문자열을 `message` 로(`kind: 'text'`). 순서: 빈 body → 래퍼 → ProblemDetails → **문자열** → unknown.
- 🔴 빈 문자열(`""`)은 지금처럼 (C) 빈 body 다 — 문자열 분기가 가로채지 않는다.
- `CLAUDE.md` B4 "에러 응답은 3종" → **4종**으로 갱신(사용자 결정 2026-10-23).

### 비즈니스 규칙

1. **소속 그룹은 지사만**(OQ-043-E) — 서버가 막지 않으므로 화면이 막는다. 예외: 이미 지사가 아닌 곳에 있는 사업장의 **현재 그룹 유지**.
2. **최상위 사업장만 추가** — 하위 사업장은 표시·수정·삭제만.
3. **하위 사업장은 그룹을 바꿀 수 없다** — 서버 규칙을 화면이 미리 막는다.
4. **헬스체크는 추가 시 받지 않는다** — 최소 생성 → 상세에서 켜고 값·예외시간을 `UpdateSite` 1번으로(실측 확인 2026-10-23, B-52 회피).
5. **예외시간은 전체 교체로 보낸다**(`detailSeq` 유지 · 새 행 0).
6. **연락처 지우기 = `""`** — 생략·`null` 은 유지된다.
7. **삭제 확인에 영향 범위를 쓴다**(B-54 회신 전까지) · 비밀번호 재확인 없음.
8. 권한별 분기 없음 — 사업장 CRUD 를 Master·Manager 가 할 수 있는지는 미실측(OQ-043-A). 목업도 사업장 화면에 권한 분기가 없다. 현장관리자는 본사에 못 들어온다(가드).
9. **서버에 없는 것 중 필요한 것만 자리**: 담당 관리자 열 · 관리자 지정 · 비상연락망 — disabled 또는 `—`. 운영 상태 · 계약 기간 · 목록 코스·지점 열은 **넣지 않는다**(재결정 2026-10-23). 상세의 코스·지점 수는 `GetSiteDetail` 이 주므로 쓴다.
10. 목록의 `healthCheckYn` 은 쓰지 않는다(B-55) — 목업 목록에도 헬스체크 열은 없다.
