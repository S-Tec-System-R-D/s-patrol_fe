# 코스 목록 `/zones`

## 총 소요시간 — **P1**

**API** `GET GetCourseList` · `GET GetCourseDetail` · `PUT UpdateCourse`

**문제** — `totalMin` 이 **구간시간(`courseMin`) 합과 다릅니다.** 재실측(2026-10-14) **7개 중 5개**:

```
코스                    totalMin   구간합   지점수
nfc인증 가능 코스              10       0      3   ✗
qwe                          0       0      4   O
순찰 인증 가능한 지점           25      25      3   O
2호선 지옥철 코스              30      25      3   ✗
강남 우체국 계단코스            60      25      2   ✗
주간 순찰 B코스               60       0      0   ✗  ← 지점이 없는데 60분
야간 순찰 A코스               45       5      1   ✗
```

원인은 **저장 시 검증이 없는 것**입니다. `totalMin: 99` + 구간합 25 로 보내면 **99 가 그대로
저장**됩니다. (`null` 로 보낼 때만 서버가 합으로 채워 줍니다.)

**영향** — 목록·상세가 **틀린 수**를 보여주고, 사용자가 구간시간을 고쳐도 **총합이 안 바뀝니다.**

**요청**
1. 저장 시 **항상 구간시간 합으로 계산** (또는 합과 다르면 400)
2. **기존 데이터 일괄 정정** — 웹에는 총 소요시간 입력란이 **없고 만들 계획도 없어**(파생값) 우리가 고칠 수 없습니다
3. 가능하면 **요청 DTO 에서 `totalMin` 제거** — 보낼 수 없으면 틀릴 수도 없습니다

# 코스 상세 `/zones/:courseSeq`

## 지도(순찰 동선) — 좌표 범위 검증 **P2**

**API** `GET GetCourseDetail` → `points[].gpsLat` / `gpsLng`

**문제** — 범위 밖 값이 저장돼 있습니다. **사업장 3 에 `gpsLat: 123`**(위도는 -90~90).
`AddPoint`/`UpdatePoint` 가 범위를 보지 않습니다.

**영향** — 그대로 지도에 넘기면 **핀이 엉뚱한 곳으로 날아가고**, 자동 영역 맞춤이 지구
반대편까지 벌어져 지도가 쓸모없어집니다.

**요청** — 범위 밖 값을 **400 으로 거부**. ⚠️ **이미 저장된 값도 정정이 필요**합니다.

**현재 대응** — 프론트가 범위 검사를 떠안아 **"좌표 없음" 과 같이** 처리 중.

## 지점 순서 — `useYn` 이 항상 `true` **P2**

**API** `GET GetCourseDetail` → `points[].useYn`

**문제** — **지점의 실제 사용여부를 따라오지 않습니다.** 실측: 지점(`pointSeq 19`)을
`useYn=false` 로 바꿔도 그 지점이 편성된 **코스 3개 모두 `true`** 로 내려왔습니다.
즉 **항상 `true` 인 상수**라 아무 정보도 주지 않습니다.

**영향** — 코스 상세에서 **"미사용 지점이 편성된 채 남아 있는 코스"** 를 구분할 수 없습니다.
(미사용 지점은 편성 후보에서는 제외되지만, **이미 편성된 것은 그대로 남습니다.**)

**요청** — ① 응답 값을 **지점의 실제 `useYn`** 으로 채우거나 ② 반영이 어려우면 **응답에서 제거**.
⚠️ **요청 DTO 에 `useYn` 을 추가할 필요는 없습니다** — 코스에서 바꿀 값이 아닙니다.

## 지점 순서 — 편성 `memo` 가 쓰기 전용 **P2**

**API** `PUT UpdateCourse` → `points[].memo`

**문제** — `UpdateCoursePointDto` 는 `memo` 를 **받고 200 을 주는데**, `GetCourseDetail` 의
`points[]` 에는 **그 필드가 없습니다.** 저장해도 **다시 읽을 수 없습니다.**

**영향** — 구간 메모 UI 를 만들 수 없습니다. 🔴 더 나쁜 것은 `points` **전량 전송 규약**과
겹치는 지점입니다 — 읽을 수 없으니 매 저장마다 `memo: null` 을 보내게 되고, **다른 경로(앱 등)로
들어간 메모가 조용히 지워집니다.**

**요청** — `GetCourseDetail.points[]` 에 **`memo` 추가**, 또는 받지 않을 거면 **요청 DTO 에서 제거**.

## 편성 모달 — 후보에 코스 소속 정보 없음 **P3**

**API** `GET GetClassificationPoint?siteSeq=`

**문제** — 후보 응답에 **"이 지점이 어느 코스에 속하는지"** 가 없습니다.

**영향** — 기획의 **`미배정` 필터**(아직 어느 코스에도 안 들어간 지점만 보기)를 **만들 수
없습니다.** 알아내려면 지점마다 상세 조회(N+1)가 필요합니다.

**요청** — 후보 응답에 **`usedCount`**(소속 코스 수) 같은 값 추가.

**참고** — ⚠️ 이 API 는 **페이징이 없어** 사업장 지점이 전량 내려옵니다. 지점이 수백 개가
되면 느려집니다(지금은 문제 없음).

## 변경계 — `AddCourse` · `UpdateCourse` **P1 / P2**

**API** `POST AddCourse` · `PUT UpdateCourse`

| 항목 | 문제 |
|---|---|
| **P1** `AddCourse` 의 `points` | **무시됩니다.** 지점을 실어 보내도 `pointCount: 0` 으로 생성되는데 응답은 **200 + `data: true`** 입니다. 성공으로 믿으면 **지점 없는 코스**가 남습니다 |
| **P1** `UpdateCourse` 의 `points` | **전량 교체**입니다. 생략·빈 배열·일부 전송 **모두 나머지를 삭제**하고 **200** 이 옵니다 — **코스명만 바꾸려다 지점을 전부 날릴 수 있습니다** |
| **P2** `courseSeq` 누락 | **401** 이 옵니다(유효성 오류인데). 프론트 인터셉터가 **토큰 만료로 오해**해 재발급·로그아웃 경로를 탑니다 → **400** 이어야 합니다 |
| **P3** 메서드·필수값 | `UpdateCourse` 만 **`PUT`** 입니다(지점은 `PATCH`). `UpdateCourseDto` 에 **required 가 하나도 없습니다** — 최소 `courseSeq`·`siteSeq` 는 필수로 |
| **P3** 파라미터명 | `DeleteCourse` 만 **`courseId`** 입니다(나머지는 `courseSeq`) |

**요청** — 최소한 ① `AddCourse` 가 `points` 를 처리하거나 **받지 않도록**(무시하면서 200 은
가장 나쁩니다) ② `UpdateCourse` 의 전량 교체 동작을 **문서화**하거나 **부분 갱신**으로

**현재 대응** — 생성은 명칭·설명만 보내고, 편성은 **편집 모드 + 전량 전송**으로 우회 중.

## 이력 — 필드명·타입·상태값 불일치 **P3**

**API** `GET GetCourseHistory` · `GET GetPointHistory`

| 항목 | 문제 |
|---|---|
| 필드명 | 목록은 `overtimeYn`, 상세·지점이력은 **`overTimeYn`**(대문자 T) |
| 타입 | `pauseTime` 이 목록은 `'HH:mm:ss'` 문자열, 상세는 **숫자** |
| 상태 사전 | 코스는 `0 진행·1 완료·2 미완료`, 지점은 `3 미완료·4 완료` — **값이 겹치는데 뜻이 다릅니다**(`2` = 코스 미완료 / 지점 **순찰제외**) |
| 소요시간 | `actualElapsedTime` 에 **시 단위**가 옵니다(`"02:17:40"`) — 분으로 가정하면 깨집니다 |
| 메모 | 목록에 **내용이 없어** 행마다 상세 조회(N+1)가 필요합니다. 지금은 **뱃지만** 표시 중 |
| 집계 | **집계 엔드포인트가 없어** 30일치 행을 받아 프론트가 셉니다. 기간을 넓히면 `pageSize` 상한(100)에 걸려 **총계가 조용히 적게** 나옵니다 |

**요청** — 표기 통일(P3). 🔴 **기간별 집계 API** 가 생기면 KPI 조회가 가벼워집니다.

# 지점 상세 `/points/:pointSeq`

## QR 재발행이 동작하지 않음 — **P1**

**API** `PATCH UpdatePoint` → `reissueQrYn: true`

**문제** — **200 을 주면서 `qrCode` 가 바뀌지 않습니다.** 실측(지점 생성 → 재발행 요청 →
재조회)에서 코드가 그대로였습니다.

**영향** — 🔴 **현장에서 QR 이 훼손·유출돼도 갈아끼울 수단이 없습니다.** 그래서 화면에
**재발행 버튼을 만들지 못했습니다** — 만들면 눌러도 아무 일이 없는데 성공 토스트가 뜹니다.

**요청** — ① 재발행을 구현하고 **새 `qrCode` 발급**, 또는 ② 미구현이면 **요청 DTO 에서 제거**.

**덧** — 발행 메타(발행일·버전)가 없어 "언제 발행된 코드인지" 도 표시하지 못합니다.

## TAG ID 중복이 500 · 삭제 지점이 태그 점유 — **P1**

**API** `POST AddPoint` · `PATCH UpdatePoint` → `nfcTagId`

**문제** — 다른 지점이 쓰는 TAG ID 로 보내면 **500 + ProblemDetails** 가 옵니다.
⚠️ **삭제한 지점도 태그를 계속 점유**합니다(지운 지점의 태그를 새 지점에 붙이면 500).

**영향** — 유효성 오류가 500 으로 새어 **사용자에게 사유를 보여줄 수 없습니다.**
화면에는 "처리하지 못하였습니다. 잠시 후 다시 시도해주세요" 가 뜨는데, **다시 해도 안 됩니다.**

**요청** — ① 중복은 **400 + 사유 문구**(`"이미 사용 중인 TAG ID 입니다."` 류)
② **삭제된 지점의 태그는 해제**

## 값 비우기 불가 — **P2**

**API** `PATCH UpdatePoint`

**문제** — `null` 과 `''` 를 **"변경하지 않음"** 으로 보고 **무시**하면서 **200 을 줍니다.**
- 설명(`memo`)을 **비울 수 없습니다**(공백 한 칸으로만 지워집니다)
- `nfcTagId` 는 **지울 방법이 없습니다** — NFC→QR 로 바꿔도 TAG ID 가 남습니다

**영향** — 사용자가 지웠다고 생각하는데 **조용히 실패**합니다.

**요청** — `null` 을 **"비우기"** 로 처리(또는 비우기 전용 규약 안내).

**현재 대응** — QR 지점에 남은 TAG ID 는 **화면에서 숨기는 중**.

## 범위 밖 `authMethod` 의 오류 문구 — **P3**

**문제** — `authMethod: 99` 를 보내면 400 + **`"NFC 값을 입력해주세요."`** 가 옵니다.
**9 가 아니면 전부 NFC 로 보는** 분기로 보입니다. 값이 사전에 없다는 것과 NFC 입력이
빠졌다는 것은 다른 문제입니다.

**참고 — 이건 잘 되어 있습니다** ✅ `authMethod: 10` 인데 TAG ID 가 없으면
**400 + `"NFC 값을 입력해주세요."`** 로 **사유를 말해 줍니다.** 화면이 그 문구를 **그대로
노출**하고 있습니다. **다른 오류도 이렇게 해 주시면 좋겠습니다.**

# 공통

## 오류 응답 — **P3**

| 항목 | 문제 |
|---|---|
| 메시지 | 변경계 실패가 **전부 `"잘못된 요청입니다."`** 입니다 — 사유를 구분·안내할 수 없습니다 |
| 형태 | 유효성 실패가 **400 래퍼 / 400 ProblemDetails / 500** 로 **일관되지 않습니다** |

**요청** — 사유를 담은 메시지 + 유효성 실패는 **400 으로 통일**.

## `pageSize` 상한 100 — **P3**

**문제** — 상한이 **문서에 없습니다.** 저희가 200 을 보냈다가 **지점 상세의 순찰 기록 조회가
통째로 400** 이었고, 화면에는 "순찰 기록이 없습니다" 가 떴습니다(장애가 빈 상태로 보였습니다).

**요청** — 상한 **문서화**. (저희는 100 으로 고쳤습니다.)

## 테스트 환경 CORS — **P3**

**문제** — 브라우저에서 직접 호출하면 **전부 차단**됩니다(`Access-Control-Allow-Origin` 없음).
운영은 same-origin 이라 문제 없지만, 개발 중에는 **dev 프록시로 우회**하고 있습니다.

**요청** — 테스트 서버에 CORS 설정이 있으면 개발이 수월합니다.
