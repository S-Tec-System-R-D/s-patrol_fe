# 상호작용 패턴 (patterns.md)

> 화면 전반에서 반복되는 **사용자 동선·상호작용 패턴**을 정리한다.
> 디자인 토큰은 [`design-system.md`](./design-system.md), 컴포넌트 사용법은 [`components.md`](./components.md), 레이아웃은 [`layout.md`](./layout.md) 참조.
>
> **원칙**
> - 새 화면을 만들 때 본 패턴 중 맞는 것을 먼저 찾는다. 패턴이 없으면 화면 개발 후 본 문서에 추가.
> - 동일 의도의 인터랙션은 동일 컴포넌트·동일 동선으로 구현(일관성 우선).

---

## 0. 패턴 인덱스

| # | 패턴 | 대표 사용처 |
|---|---|---|
| 1 | 마스터-디테일 | 현장 대부분 화면 |
| 2 | CRUD 모달 (Create/Update) | 지점·코스·근무자·공지·사업장 |
| 3 | 위험 액션 확인 (AlertDialog) | 삭제·운영중지 |
| 4 | 패스워드 재확인 모달 | 사업장 삭제 |
| 5 | 드래그 정렬 | 코스 내 지점 순서 |
| 6 | URL 쿼리스트링 필터·검색 | 모든 목록 |
| 7 | 빈 상태 | 미선택·미존재 |
| 8 | 사이드 패널 (Sheet) | 알림·우측 상세 슬라이드 |
| 9 | 탭 라우팅 | 구역/지점, 코스 이력/지점 이력, 사업장 상세 기본정보/헬스체크 |
| 10 | 인라인 토글 (Switch) | 코스 활성화·교대 허용·헬스체크 사용 |
| 11 | 마스터-디테일 안의 액션 풋터 | 우측 상세 패널 하단 비밀번호/수정/삭제 |
| 12 | 트리 네비게이션 + 컨텍스트 메뉴 | 관리그룹 트리 |

## 1. 마스터-디테일

### 동선

```
좌측 목록 → 행 선택 → 우측 패널에 상세 표시
                  ↓
       미선택 상태 → AppEmpty
```

### 규칙

- 좌측 목록은 자체 스크롤. 우측은 컨텐츠 길이에 따라.
- 행 선택 상태는 컴포넌트 state(useState) — 페이지 단위. URL에 안 박는다(상세 단위 라우트가 따로 있는 경우 제외, 예: 사업장 상세 `/:id`).
- 첫 진입 시 첫 행 자동 선택(데이터 있을 때).
- 빈 상태는 `AppEmpty`를 카드 컨테이너(`rounded-lg border border-border bg-card p-4`, `AppDetailCard` 외곽과 동일 톤)로 감싸 표시 — 선택 상태든 아니든 우측 영역의 카드 경계가 유지되도록(010에서 결정, 콘텐츠 톤은 §4-3 따름).

### 사용 화면

- `/zones`, `/points`, `/patrol/zones`, `/users`, `/notice`, `/admin/admins`, `/admin/locations`

## 2. CRUD 모달 (Create/Update)

### 동선

```
[등록/지점추가/근무자추가] 버튼
    ↓ 클릭
AppDialog 열림 (폼 children)
    ↓ 등록/수정
성공 → toast(or 인라인 안내) + 목록 갱신 + 모달 닫힘
실패 → 폼 필드 에러 표시 + 모달 유지
취소 → 모달 닫힘 (변경 사항 폐기)
```

### 규칙

- 모달 컴포넌트: `AppDialog` (`components.md` §5).
- 폼: react-hook-form + zod 스키마. 스키마 위치 `features/{도메인}/form/schema.ts`.
- 풋터: 우측 정렬, `취소` (variant=sub) + `등록/저장` (variant=default).
- 폼 컴포넌트는 도메인 디렉터리(`AddPointForm.tsx`, `EditCourseForm.tsx`).
- `Create*Request` / `Update*Request` DTO는 `data-model.md` §5 참조.

### 사용 화면

- 모든 등록/수정 동선. (사업장 삭제 같은 위험 동작은 §3·§4)

---

## 3. 위험 액션 확인 (AlertDialog)

### 동선

```
[삭제] 버튼 클릭
    ↓
AppAlertDialog(variant=destructive) 열림
    ↓ 확인
액션 실행 → 목록 갱신
취소 → 모달 닫힘
```

### 규칙

- 컴포넌트: `AppAlertDialog` (`components.md` §6).
- 메시지: "{대상}을(를) 삭제하시겠습니까?" + "삭제된 데이터는 복구할 수 없습니다." (콘텐츠 톤 §4-2).
- 아이콘: `Trash2Icon` 또는 액션 의미에 맞는 lucide.
- 확인 버튼 라벨: 액션 이름 그대로("삭제", "운영중지").

### 사용 화면

- 지점 삭제, 코스 삭제, 공지 삭제, 근무자 삭제, 관리자 삭제, 그룹 삭제, 사업장 운영중지(재개).
- **사업장 삭제만 별도 패턴(§4) — 패스워드 재확인**.

---

## 4. 패스워드 재확인 모달

### 동선

```
[사업장 삭제] 버튼
    ↓
모달 열림 (패스워드 인풋 + 사업장명 안내)
    ↓ 입력 후 확인
서버 검증
    ↓ 일치
삭제 실행 → /admin/locations 목록으로 이동
    ↓ 불일치
모달 유지 + 에러 표시
```

### 규칙

- 위험도 가장 높은 액션 전용(현재 사업장 삭제 1건).
- 폼: `AppInput variant="password" label="비밀번호" required`.
- 풋터: `취소` + `삭제`(variant=destructive).
- 서버 응답에 `code !== 200` → 인풋 에러("비밀번호가 일치하지 않습니다. 다시 입력해주세요.").

### 사용 화면

- 사업장 삭제 (`/admin/locations/:id` → 삭제 버튼).

## 5. 드래그 정렬

### 동선

```
코스 상세에서 지점 카드 리스트
   ↓ 좌측 드래그 핸들 잡고 위/아래로
순서 변경 → ReorderCoursePointsRequest 전송
   ↓
서버 OK → 목록 순서 확정
```

### 규칙

- 드래그 핸들은 카드 좌측 점 6개 아이콘(`GripVerticalIcon`).
- **라이브러리: `@dnd-kit/sortable` (확정)**.
- 정렬 결과는 일괄 갱신(`orderedPointIds: string[]`)으로 한 번에 서버 전송(`data-model.md` §5-3).
- 드래그 중 시각 피드백: 카드 그림자 + 반투명.
- 키보드 정렬 지원 여부는 dnd-kit 기본을 따른다(필요 시 별도 설계).

### 사용 화면

- 코스 상세(`/zones`)의 지점 카드 리스트.

---

## 6. URL 쿼리스트링 필터·검색

### 동선

```
필터·검색 입력 변경
   ↓
URL 쿼리스트링 갱신 (예: ?from=...&to=...&result=COMPLETE)
   ↓
react-query refetch
   ↓
목록 갱신
```

### 규칙

- **모든 목록 화면의 필터·검색·정렬·페이지 번호는 URL에 저장**한다.
- 새로고침 / 뒤로가기 / 공유 링크 모두 동일 결과를 재현해야 함.
- 쿼리스트링 키는 `data-model.md`의 `*Query` 인터페이스와 일치 (`from`/`to`/`page`/`pageSize`/`result`/...).
- 헬퍼: `useQueryParams` 패턴 재사용(명세서에 명시).

### 사용 화면

- 순찰이력(코스/지점), 근무자 목록, 관리자 목록, 사업장 목록, 공지 목록.

---

## 7. 빈 상태

### 동선

```
데이터 없음 / 선택 없음
   ↓
AppEmpty 표시 (icon + title + description + (선택) action)
```

### 규칙

- 컴포넌트: `AppEmpty` (`components.md` §7).
- 메시지 패턴: 상태 한 줄 + 다음 행동 한 줄 (콘텐츠 톤 §4-3).
- 페이지 전체 빈 상태와 사이드 패널 빈 상태 모두 동일 컴포넌트.
- **마스터-디테일 우측 미선택**은 `AppEmpty`를 카드 컨테이너로 감싼다(§1 참조) — 페이지 전체 빈 상태(404/403/목록 0건)는 카드 없이 그대로 사용.
- 아이콘: 화면 의미에 맞는 lucide(`MapIcon`·`LayersIcon`·`InboxIcon` 등).

### 사용 화면

- 마스터-디테일 우측 미선택, 검색 결과 0건, 목록 0건 등.

## 8. 사이드 패널 (Sheet) — 반응형 분기

### 동선

**`xl` 이상 (>= 1280px)**

```
좌측 목록 → 행 선택 → 우측 상세 패널이 같은 화면에 항상 표시 (마스터-디테일 §1)
```

**`xl` 미만 (< 1280px)** — 1차 안

```
좌측 목록 → 행 선택 → 우측 상세를 ui/sheet 로 표시
                  ↓
        바깥 클릭 또는 X → 닫힘
```

### 규칙

- 우측 상세 패널은 화면 폭에 따라 **표시 방식이 바뀐다**:
  - `xl` 이상: 마스터-디테일의 우측 컬럼에 영구 표시.
  - `xl` 미만: `ui/sheet` 로 슬라이드(상태는 동일 컴포넌트 사용, 컨테이너만 다름).
- 모바일 사이드바(`lg` 미만)와 breakpoint가 다른 이유: 우측 상세 패널은 컬럼이 두 개라 좀 더 일찍 압박이 시작됨.
- TopNav 알림 시트는 폭과 무관하게 항상 `ui/sheet`.
- 영구 표시 vs Sheet 모드 전환은 페이지 단에서 `useMediaQuery` 등으로 분기.

### 사용 화면

- 우측 상세 패널이 있는 모든 마스터-디테일 화면 (지점·코스·근무자·관리자·공지 등).
- TopNav 알림 시트(폭 무관 Sheet).

> **1차 안 표시**: `xl` breakpoint 값은 화면별 실제 사용성을 보고 미세 조정 여지 있음.

## 9. 탭 라우팅

### 동선

```
페이지가 직접 탭 컴포넌트 렌더 (PatrolHistoryTabs / CourseTabs)
   ↓ 클릭 (NavLink)
라우트 이동 (/zones ↔ /points 등)
   ↓
해당 라우트의 페이지 컴포넌트가 자신의 탭을 다시 렌더(활성 강조만 갱신)
```

### 규칙

- 컴포넌트: 도메인별 로컬 컴포넌트(`PatrolHistoryTabs`, `CourseTabs` 등) — `NavLink` + `border-point` 활성 강조. 라우터 레벨 공용 레이아웃(구 `LocationLayout`/`PatrolLayout` + `AppTabs`)은 **009·011에서 폐기**(`components.md` §8).
- 두 탭이 동일 도메인의 두 관점일 때 사용(코스/지점, 코스 이력/지점 이력).
- 탭은 URL 라우트로 표현 → 뒤로가기 보존.
- **사유**: 라우터 레벨 레이아웃이 탭을 감싸면 페이지가 헤더→탭→컨텐츠 순서를 통제할 수 없어 리디자인 목업과 어긋남. 페이지 로컬 컴포넌트로 각 페이지가 순서를 직접 조립.
- 사업장 상세는 `?tab=health` 같은 쿼리 모드도 사용 가능(`ui/tabs` 직접 사용, `components.md` 참조).

### 사용 화면

- `/zones` ↔ `/points`(`CourseTabs`, 011~), `/patrol/zones` ↔ `/patrol/points`(`PatrolHistoryTabs`, 009~), `/admin/locations/:id`(기본정보/헬스체크).

## 10. 인라인 토글 (Switch) — 옵티미스틱

### 동선

```
[ON/OFF 토글] 클릭
   ↓ 즉시 UI 반영 (옵티미스틱)
   ↓ 서버 PATCH
성공 → 그대로 유지
실패 → 원상 복귀 + sonner toast 안내
```

### 규칙

- 컴포넌트: `ui/switch` (radix).
- 단일 boolean을 즉시 반영하는 액션에 사용.
- **옵티미스틱 업데이트 적용**(tanstack-query `onMutate` + 롤백). 디자인 시스템 D8과 일치.
- 단, **운영 중지**(사업장)나 위험한 활성/비활성은 §3의 AlertDialog로 한 번 확인 후 진행.

### 사용 화면

- 코스 활성화 / 교대 허용 / 헬스체크 사용 / 지점 사용 등.

> **옵티미스틱 정책**: 토글류에만 옵티미스틱을 적용한다. CRUD·삭제·이동 같은 다른 mutation은 §2·§3 패턴(응답 대기 + sonner toast)을 따른다. 정책 근거는 [`design-system.md`](./design-system.md) D8 참조.

### 사용 화면

- 코스 활성화 / 교대 허용 / 헬스체크 사용 / 지점 활성 / 사업장 운영중지(이건 확인 필요).

## 11. 마스터-디테일의 액션 풋터

### 동선

```
좌측 목록 → 행 선택 → 우측 상세 패널
                                 ↓
                  상단: 기본정보 / 부가 섹션
                  하단: [비밀번호] [수정] [삭제]
```

### 규칙

- 위치: 우측 패널 하단 고정.
- 1행에 2개 또는 2행에 2x2. 위험 액션(삭제)은 빨강 강조.
- 액션 클릭은 §2~§4 패턴으로 분기.

### 사용 화면

- 근무자 상세, 관리자 상세, 지점 상세, 공지 상세.

## 12. 트리 네비게이션 + 컨텍스트 메뉴

### 동선

```
좌측 트리 (관리그룹 Level 1~3)
   ↓ 노드 클릭
우측 사업장 목록 필터링
   ↓ 노드의 [+] 클릭
하위 그룹 추가 모달
   ↓ 노드의 [⋯] 클릭
컨텍스트 메뉴 (수정 / 삭제)
```

### 규칙

- 라이브러리: 자체 트리 (`zone-tree` 패턴 참고) 또는 radix 메뉴.
- 활성 노드: bg 강조 + 좌측 보더.
- 노드 옆 카운트 노출(예: `에스텍시스템 5`, `강동지사 2`).
- 컨텍스트 메뉴: `ui/dropdown-menu` 사용. "그룹 수정" / "그룹 삭제" 2 옵션.

### 사용 화면

- `/admin/locations` 좌측 트리.

---

## 13. 새 패턴 추가 기준

새 패턴을 본 문서에 추가할 때:

1. 동일 의도의 인터랙션이 **3개 이상 화면**에서 반복된다.
2. 이름·동선·구성 요소(컴포넌트)가 명확하다.
3. 기존 패턴과 의미가 겹치지 않는다(겹치면 해당 패턴에 변형으로 추가).

> 만족 안 하면 특정 화면 안 일회성 디테일로 두고, 화면이 늘면 다시 검토.
