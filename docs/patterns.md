# 상호작용 패턴 (patterns.md)

> 화면 전반에서 반복되는 **사용자 동선·상호작용 패턴**을 정리한다.
> 디자인 토큰은 [`design-system.md`](./design-system.md), 컴포넌트 사용법은 [`components.md`](./components.md), 레이아웃은 [`layout.md`](./layout.md) 참조.
>
> **원칙**
> - 새 화면을 만들 때 본 패턴 중 맞는 것을 먼저 찾는다. 패턴이 없으면 화면 개발 후 본 문서에 추가.
> - 동일 의도의 인터랙션은 동일 컴포넌트·동일 동선으로 구현(일관성 우선).

---

## 0. 패턴 인덱스

| # | 패턴 | 대표 사용처 |
|---|---|---|
| 1 | 마스터-디테일 | 현장 대부분 화면 |
| 2 | CRUD 모달 (Create/Update) | 지점·코스·근무자·공지·사업장 |
| 3 | 위험 액션 확인 (AlertDialog) | 삭제·운영중지 |
| 4 | 패스워드 재확인 모달 | 사업장 삭제 |
| 5 | 드래그 정렬 — 편집 모드 + 명시적 저장 | 코스 내 지점 순서 |
| 6 | URL 쿼리스트링 필터·검색 | 모든 목록 |
| 7 | 빈 상태 | 미선택·미존재 |
| 8 | 사이드 패널 (Sheet) | 알림·우측 상세 슬라이드 |
| 9 | 탭 라우팅 | 구역/지점, 코스 이력/지점 이력, 사업장 상세 기본정보/헬스체크 |
| 10 | 인라인 토글 (Switch) — 즉시 반영 / 확인 모달 | 코스 활성화·교대 허용·헬스체크 사용 |
| 11 | 마스터-디테일 안의 액션 풋터 | 우측 상세 패널 하단 비밀번호/수정/삭제 |
| 12 | 트리 네비게이션 + 컨텍스트 메뉴 | 관리그룹 트리 |
| 13 | 컴팩트 필터 팝오버 | 목록 화면의 단일 선택 필터 |

## 1. 마스터-디테일

### 동선

```
좌측 목록 → 행 선택 → 우측 패널에 상세 표시
                  ↓
       미선택 상태 → AppEmpty
```

### 규칙

- 좌측 목록은 자체 스크롤. 우측은 컨텐츠 길이에 따라.
- 행 선택 상태는 컴포넌트 state(useState) — 페이지 단위. URL에 안 박는다(상세 단위 라우트가 따로 있는 경우 제외, 예: 사업장 상세 `/:id`, 공지사항 상세 `/notice/:id` — 015에서 콘텐츠 소비형 화면 특성상 우측 패널 대신 별도 라우트로 결정).
- 첫 진입 시 첫 행 자동 선택(데이터 있을 때).
- 빈 상태는 `AppEmpty`를 카드 컨테이너(`rounded-lg border border-border bg-card p-4`, `AppDetailCard` 외곽과 동일 톤)로 감싸 표시 — 선택 상태든 아니든 우측 영역의 카드 경계가 유지되도록(010에서 결정, 콘텐츠 톤은 §4-3 따름).

### 사용 화면

- `/zones`, `/points`, `/patrol/zones`, `/users`, `/admin/admins`, `/admin/locations`
- `/notice`는 좌측 목록+우측 패널이 아니라 **목록(리스트) + 별도 상세 페이지(`/notice/:id`)** 변형(015, 위 규칙의 상세 단위 라우트 예외 참조).

## 2. CRUD 모달 (Create/Update)

### 동선

```
[등록/지점추가/근무자추가] 버튼
    ↓ 클릭
AppDialog 열림 (폼 children)
    ↓ 등록/수정
성공 → toast(or 인라인 안내) + 목록 갱신 + 모달 닫힘
실패 → 폼 필드 에러 표시 + 모달 유지
취소 → 모달 닫힘 (변경 사항 폐기)
```

### 규칙

- 모달 컴포넌트: `AppDialog` (`components.md` §5).
- 폼: react-hook-form + zod 스키마. 스키마 위치 `features/{도메인}/form/schema.ts`.
- 풋터: 우측 정렬, `취소` (variant=sub) + `등록/저장` (variant=default).
- 폼 컴포넌트는 도메인 디렉터리(`AddPointForm.tsx`, `EditCourseForm.tsx`).
- `Create*Request` / `Update*Request` DTO는 `data-model.md` §5 참조.

### 사용 화면

- 모든 등록/수정 동선. (사업장 삭제 같은 위험 동작은 §3·§4)

---

## 3. 위험 액션 확인 (AlertDialog)

### 동선

```
[삭제] 버튼 클릭
    ↓
AppAlertDialog(variant=destructive) 열림
    ↓ 확인
액션 실행 → 목록 갱신
취소 → 모달 닫힘
```

### 규칙

- 컴포넌트: `AppAlertDialog` (`components.md` §6).
- 메시지: "{대상}을(를) 삭제하시겠습니까?" + "삭제된 데이터는 복구할 수 없습니다." (콘텐츠 톤 §4-2).
- 아이콘: `Trash2Icon` 또는 액션 의미에 맞는 lucide.
- 확인 버튼 라벨: 액션 이름 그대로("삭제", "운영중지").

### 사용 화면

- 지점 삭제, 코스 삭제, 공지 삭제, 근무자 삭제, 관리자 삭제, 그룹 삭제, 사업장 운영중지(재개).
- **사업장 삭제만 별도 패턴(§4) — 패스워드 재확인**.

## 4. 패스워드 재확인 모달

### 동선

```
[사업장 삭제] 버튼
    ↓
모달 열림 (패스워드 인풋 + 사업장명 안내)
    ↓ 입력 후 확인
서버 검증
    ↓ 일치
삭제 실행 → /admin/locations 목록으로 이동
    ↓ 불일치
모달 유지 + 에러 표시
```

### 규칙

- 위험도 가장 높은 액션 전용(현재 사업장 삭제 1건).
- 폼: `AppInput variant="password" label="비밀번호" required`.
- 풋터: `취소` + `삭제`(variant=destructive).
- 서버 응답에 `code !== 200` → 인풋 에러("비밀번호가 일치하지 않습니다. 다시 입력해주세요.").

### 사용 화면

- 사업장 삭제 (`/admin/locations/:id` → 삭제 버튼).

## 5. 드래그 정렬 — **편집 모드 + 명시적 저장** (023에서 정정)

### 동선

```
코스 상세 · 지점 순서 카드 → [편집]
   ↓ 편집 모드 진입 (초안 상태)
   ↓ 드래그 핸들로 재배치 · 지점 추가/삭제 · 구간시간 입력
   ↓ 여기까지 **서버 요청 없음**
[저장] → UpdateCourse (코스 전체 전량 전송)
   ↓
성공 → 재조회 후 읽기 모드  /  실패 → 초안 유지 + "저장되지 않음" 명시
[취소] → 초안 폐기 = 서버 순서로 원복
```

### 규칙

- 드래그 핸들은 카드 좌측 점 6개 아이콘(`GripVerticalIcon`).
- **라이브러리: `@dnd-kit/sortable` (확정)**.
- 🔴 **드래그마다 저장하지 않는다.** 전용 정렬 엔드포인트는 **없다** — 순서는 `UpdateCourse` 의
  `points` **전량 전송**으로만 바뀐다(B-25). 드래그 한 번마다 PUT 하면 지점 5개를 재배치하는
  동안 코스 전체가 네 번 교체되고, 실패하면 "화면만 바뀐 상태" 가 남는다. 구간시간이 **타이핑**
  이라 자동 저장과 맞지 않는 것도 같은 이유.
- 🔴 **`orderNo` 는 저장 시 1..N 으로 다시 매긴다.** 서버는 중복 `orderNo` 도 그대로 저장한다
  (실측 2026-10-12) — 재부여는 **우리 책임**이다. 화면의 번호 뱃지도 서버가 준 `orderNo` 가
  아니라 **배열 순서**로 그린다(안 그러면 드래그해도 번호가 안 바뀐다).
- 🔴 **실패 시 초안을 말없이 되돌리지 않는다.** 저장 실패는 화면에 **남겨서** 알리고(토스트는
  사라진다), 되돌리는 수단은 **취소 버튼**이다. 전량 전송이라 **부분 반영이 없다**는 점이 근거.
- 드래그 중 시각 피드백: 카드 그림자 + 반투명.
- **키보드 정렬을 지원한다** — `dnd-kit` 의 `KeyboardSensor` + `sortableKeyboardCoordinates`.

### 사용 화면

- 코스 상세(`/zones/:courseSeq`)의 **지점 순서** 카드(`CoursePointEditor`).

> ⚠️ **옛 설계는 틀렸다 (2026-10-13 정정).** 이 절은 `ReorderCoursePointsRequest` 전송 ·
> `orderedPointIds: string[]` 일괄 갱신 · 드래그 즉시 반영으로 적혀 있었다. **그런 엔드포인트는
> 존재하지 않는다**(`api-spec.md`). 023 구현 전의 설계안이 실측 없이 남아 있던 것이며, 024·025가
> 이 절을 보고 같은 설계를 하는 것을 막기 위해 사유를 남긴다.

## 6. URL 쿼리스트링 필터·검색

### 동선

```
필터·검색 입력 변경
   ↓
URL 쿼리스트링 갱신 (예: ?from=...&to=...&result=COMPLETE)
   ↓
react-query refetch
   ↓
목록 갱신
```

### 규칙

- **모든 목록 화면의 필터·검색·정렬·페이지 번호는 URL에 저장**한다.
- 새로고침 / 뒤로가기 / 공유 링크 모두 동일 결과를 재현해야 함.
- 쿼리스트링 키는 `data-model.md`의 `*Query` 인터페이스와 일치 (`from`/`to`/`page`/`pageSize`/`result`/...).
- 헬퍼: `useQueryParams` 패턴 재사용(명세서에 명시).

### 사용 화면

- 순찰이력(코스/지점), 근무자 목록, 관리자 목록, 사업장 목록, 공지 목록.

## 7. 빈 상태

### 동선

```
데이터 없음 / 선택 없음
   ↓
AppEmpty 표시 (icon + title + description + (선택) action)
```

### 규칙

- 컴포넌트: `AppEmpty` (`components.md` §7).
- 메시지 패턴: 상태 한 줄 + 다음 행동 한 줄 (콘텐츠 톤 §4-3).
- 페이지 전체 빈 상태와 사이드 패널 빈 상태 모두 동일 컴포넌트.
- **마스터-디테일 우측 미선택**은 `AppEmpty`를 카드 컨테이너로 감싼다(§1 참조) — 페이지 전체 빈 상태(404/403/목록 0건)는 카드 없이 그대로 사용.
- 아이콘: 화면 의미에 맞는 lucide(`MapIcon`·`LayersIcon`·`InboxIcon` 등).

### 사용 화면

- 마스터-디테일 우측 미선택, 검색 결과 0건, 목록 0건 등.

## 8. 사이드 패널 (Sheet) — 반응형 분기

> ✅ 본 패턴의 `xl` 기준은 2026-10-08 확정된 **단일 breakpoint 규칙**과 일치한다
> (`design-system.md` §2-5 — 단계는 `xl` 하나, 좁은 쪽은 덜어내기만).

### 동선

**`xl` 이상 (>= 1280px)**

```
좌측 목록 → 행 선택 → 우측 상세 패널이 같은 화면에 항상 표시 (마스터-디테일 §1)
```

**`xl` 미만 (< 1280px)** — 1차 안

```
좌측 목록 → 행 선택 → 우측 상세를 ui/sheet 로 표시
                  ↓
        바깥 클릭 또는 X → 닫힘
```

### 규칙

- 우측 상세 패널은 화면 폭에 따라 **표시 방식이 바뀐다**:
  - `xl` 이상: 마스터-디테일의 우측 컬럼에 영구 표시.
  - `xl` 미만: `ui/sheet` 로 슬라이드(상태는 동일 컴포넌트 사용, 컨테이너만 다름).
- 모바일 사이드바(`lg` 미만)와 breakpoint가 다른 이유: 우측 상세 패널은 컬럼이 두 개라 좀 더 일찍 압박이 시작됨.
- TopNav 알림 시트는 폭과 무관하게 항상 `ui/sheet`.
- 영구 표시 vs Sheet 모드 전환은 페이지 단에서 `useMediaQuery` 등으로 분기.

### 사용 화면

- 우측 상세 패널이 있는 모든 마스터-디테일 화면 (지점·코스·근무자·관리자·공지 등).
- TopNav 알림 시트(폭 무관 Sheet).

> **1차 안 표시**: `xl` breakpoint 값은 화면별 실제 사용성을 보고 미세 조정 여지 있음.

## 9. 탭 라우팅

### 동선

```
페이지가 직접 탭 컴포넌트 렌더 (PatrolHistoryTabs / CourseTabs)
   ↓ 클릭 (NavLink)
라우트 이동 (/zones ↔ /points 등)
   ↓
해당 라우트의 페이지 컴포넌트가 자신의 탭을 다시 렌더(활성 강조만 갱신)
```

### 규칙

- 컴포넌트: 도메인별 로컬 컴포넌트(`PatrolHistoryTabs`, `CourseTabs` 등) — `NavLink` + `border-point` 활성 강조. 라우터 레벨 공용 레이아웃(구 `LocationLayout`/`PatrolLayout` + `AppTabs`)은 **009·011에서 폐기**(`components.md` §8).
- 두 탭이 동일 도메인의 두 관점일 때 사용(코스/지점, 코스 이력/지점 이력).
- 탭은 URL 라우트로 표현 → 뒤로가기 보존.
- **사유**: 라우터 레벨 레이아웃이 탭을 감싸면 페이지가 헤더→탭→컨텐츠 순서를 통제할 수 없어 리디자인 목업과 어긋남. 페이지 로컬 컴포넌트로 각 페이지가 순서를 직접 조립.
- 사업장 상세는 `?tab=health` 같은 쿼리 모드도 사용 가능(`ui/tabs` 직접 사용, `components.md` 참조).

### 사용 화면

- `/zones` ↔ `/points`(`CourseTabs`, 011~), `/patrol/zones` ↔ `/patrol/points`(`PatrolHistoryTabs`, 009~), `/admin/locations/:id`(기본정보/헬스체크).

## 10. 인라인 토글 (Switch) — **즉시 반영 / 확인 모달 두 갈래** (023에서 분기)

토글이라고 다 같지 않다. **되돌리는 비용**으로 갈린다.

| | (A) 즉시 반영 | (B) 확인 모달 |
|---|---|---|
| 동작 | 클릭 → 옵티미스틱 → 서버 | 클릭 → **AlertDialog** → 확인 후 서버 |
| 스위치 | 바로 움직임, 실패 시 롤백 | **움직이지 않음**(서버 값만 따름) |
| 쓰는 곳 | 화면 안에서만 의미 있는 표시 토글 | **다른 사용자에게 보이는 상태**가 바뀌는 것 |
| 근거 | `design-system.md` D8 | §3 위험 액션 확인 |

### (A) 즉시 반영 — 동선

```
[ON/OFF 토글] 클릭
   ↓ 즉시 UI 반영 (옵티미스틱, tanstack-query onMutate)
   ↓ 서버 요청
성공 → 유지  /  실패 → 원상 복귀 + sonner toast
```

### (B) 확인 모달 — 동선 (코스 활성화 / 교대 허용)

```
[ON/OFF 토글] 클릭
   ↓ 🔴 값을 바꾸지 않는다 — 모달을 **요청**만 한다
AlertDialog: 바뀌는 결과를 문장으로 설명
   ↓ 확인
서버 요청(UpdateCourse 전량 전송) → 재조회 → 그때 스위치가 움직인다
   ↓ 취소 → 아무 일도 없음
```

### 규칙

- 컴포넌트: `ui/switch` (radix).
- 🔴 **스위치 위치만으로 상태를 전하지 않는다.** 옆에 `사용 중 / 미사용` 같은 **글자**를 함께
  둔다(색·명도만으로 의미를 전하지 않는 접근성 규약).
- 🔴 **(B)에 옵티미스틱을 쓰지 않는다.** 모달로 의도를 확인받은 변경을 화면에 먼저 반영했다가
  실패로 되돌리면, 사용자는 **자기가 방금 확인한 변경이 조용히 취소된 것**을 토스트로만 알게
  된다. 재조회 전까지 스위치가 **이전 위치에 남아 있는 것이 정상**이다.
- 🔴 **(B)의 모달 문구는 "결과" 를 적는다.** "활성화하시겠습니까?" 가 아니라 *"비활성화하면
  근무자 앱의 코스 목록에서 숨겨져, 더 이상 이 코스로 순찰을 시작할 수 없습니다"* — 근무자가
  **앱에서 직접 코스를 고르는** 방식이기 때문(OQ-023-F, 2026-10-12 확인).
- 🔴 **카드가 직접 저장하지 않는다.** 토글을 가진 카드는 `onRequestToggle` 으로 **요청만**
  올리고, 모달과 mutation 은 **페이지**가 든다. 코스는 토글 하나를 바꾸는 데도 `UpdateCourse`
  **전량 전송**(B-25)이 필요해서, 카드가 들면 그 규약이 카드 안으로 샌다.
- 저장 중에는 스위치를 잠근다 — 연타가 전량 전송을 중복으로 만들지 않게.

### 사용 화면

| 토글 | 갈래 | 비고 |
|---|---|---|
| 코스 활성화 (`useYn`) | **(B)** | 근무자 앱 노출이 바뀐다 |
| 교대 허용 (`switchYn`) | **(B)** | 같은 모달 체계. ⚠️ 효과 문구는 **미확인이라 비워 둠**(A1) |
| **지점 인증수단 (QR↔NFC)** | **(B) — 🔴 방향에 따라 비대칭** | `spec 029`. **아래 별도 항목** |
| 헬스체크 사용 | (A) 예정 | 미구현 |
| 지점 사용 | (A) 예정 | 미구현 |

### 🔴 2값 전환은 **방향마다 받을 것이 다를 수 있다** (`spec 029`, 2026-10-13)

지점 인증수단은 QR↔NFC 두 값을 오가는 스위치인데, **한 방향에만 추가 입력이 필요하다.**

| 방향 | 흐름 | 왜 |
|---|---|---|
| NFC → QR | **확인 모달** | 받을 값이 없다 |
| QR → NFC | **입력 모달**(TAG ID 14자리 HEX) | 🔴 서버가 `authMethod: 10` 을 `nfcTagId` 없이 받으면 **400** 이다(실측). "TAG ID 없이 NFC 로 바꾸기" 는 **존재하지 않는 경로** |

- 🔴 **스위치는 저장이 성공해야 움직인다.** 입력 모달을 취소하면 아무 일도 없어야 하는데,
  눌린 즉시 바뀌는 스위치는 **취소한 변경을 화면에 남긴다.** (B)의 비옵티미스틱 규칙이
  여기서는 **선택이 아니라 필수**다.
- 🔴 **코드에 "없는 경로" 를 만들지 않는다.** zod 스키마가 1차로 막고 서버 400 은 마지막
  방어선이다 — 전환 훅의 타입도 NFC 방향에서 `nfcTagId` 를 **필수로 받게** 해 호출부가
  깜빡하면 컴파일이 안 되게 했다.
- **전환 전후로 반대쪽 자격증명이 서버에 남는다**(B-15: `null`·`''` 로 못 지운다). 지우지
  못하므로 **화면에서 보여주지 않는 것**으로 다룬다 — 쓰이지 않는 값이 화면에 있으면
  "둘 다 되는 지점" 으로 읽힌다.

> **옵티미스틱 정책**: (A)에만 옵티미스틱을 적용한다. CRUD·삭제·이동 같은 다른 mutation 은
> §2·§3 패턴(응답 대기 + sonner toast)을 따른다. 정책 근거는
> [`design-system.md`](./design-system.md) D8.

> ⚠️ **옛 설계는 틀렸다 (2026-10-13 정정).** 이 절은 토글 전체를 **옵티미스틱**으로 규정하고
> 사용 화면에 "코스 활성화 / 교대 허용" 을 올려 두었다. 023 구현은 두 토글 모두 **확인 모달 +
> 비옵티미스틱**이며, 위 표의 (B)가 실제 동작이다.

## 11. 마스터-디테일의 액션 풋터

### 동선

```
좌측 목록 → 행 선택 → 우측 상세 패널
                                 ↓
                  상단: 기본정보 / 부가 섹션
                  하단: [비밀번호] [수정] [삭제]
```

### 규칙

- 위치: 우측 패널 하단 고정.
- 1행에 2개 또는 2행에 2x2. 위험 액션(삭제)은 빨강 강조.
- 액션 클릭은 §2~§4 패턴으로 분기.

### 사용 화면

- 근무자 상세, 관리자 상세, 공지 상세.

### ⚠️ 변형 — 상세가 **페이지**일 때는 액션을 헤더 우측에 둔다 (2026-10-08)

**지점 상세(`/points/:pointSeq`)는 본 패턴을 쓰지 않는다.** `spec 027` 에서 우측 패널이
**전체 폭 페이지**가 되면서 전제가 깨졌다:

- 전체 폭에서 하단 full-width 버튼 2개는 폭에 비해 **과하다**(패널 340px 이라 성립했던 모양)
- 본문이 길면 액션이 **스크롤 아래로 밀려 보이지 않는다**. 패널은 높이가 고정이라 괜찮았다

→ **헤더 우측**(`ml-auto`)에 `수정`·`삭제` 를 둔다. 제목·상태 뱃지와 한 줄이고 본문 위에
항상 남는다. 분기 자체(§2~§4 패턴)는 그대로다.

🔴 **`spec 023`(코스 상세)도 페이지가 되면 이쪽을 따른다.** 둘 다 페이지가 된 뒤에도
모양이 같으면 그때 패턴으로 승격한다(지금은 사례 1건).

## 14. 반응형 목록 — 테이블 ↔ 카드 (2026-10-13, `spec 030`)

> 구현: `components/AppTable.tsx` 의 `renderCard` · 사용처 4곳
> (`/zones` · `/points` · `/patrol/zones` · `/patrol/points`)

### 왜 생겼나

`CLAUDE.md` B4 는 "PC 기준 + **분할화면 대응**" 인데, 목록에는 적용된 적이 없었다.
`AppTable` 에는 **가로 스크롤조차 없어**(`overflow-hidden`) 폭이 줄면 컬럼이 그대로
찌그러졌다 — 지점이력(8컬럼)은 글자가 세로로 쌓였다. 🔴 **프로젝트의 첫 반응형 분기**라
여기서 정한 방식이 규약이 된다.

### 규칙

1. 🔴 **opt-in 이다.** `renderCard` 를 준 소비처만 바뀐다. **카드 안에 들어 있는 표**
   (`DeploymentHistoryTabs`)에 붙이면 **카드 안에 카드**가 생긴다.
2. 🔴 **분기는 CSS**(`hidden xl:block` / `xl:hidden`). JS 로 폭을 재면 ① 첫 렌더에
   깜빡이고 ② **테스트·SSR 에서 폭이 0이라 항상 카드**가 된다. 기준 폭은 `xl`(1280px) —
   상세 2열 분기와 같은 값을 쓴다(`design-system.md` §2-5).
3. 🔴 **행은 `table.getRowModel()` 에서 가져온다.** `data` 를 직접 돌면 정렬·페이지가
   **카드에서만 안 먹어** 테이블과 카드가 서로 다른 것을 보여준다.
4. 🔴 **클릭·행 강조는 테이블과 같은 함수**(`onRowClick`·`rowClassName`)를 쓴다. 두 벌로
   갈리면 한쪽만 고쳐진다 — 특히 **미사용 톤다운이 카드에 없으면 좁은 폭에서 미사용
   항목이 정상처럼 보인다.**
5. **카드에는 "고르는 데 쓰는 값" 만 남긴다.** 좁은 화면에서는 행을 훑어 **비교**하지 않고
   하나를 **찾아서 누른다** — 식별(이름)과 상태(뱃지)를 앞에 두고, 비교용 수치는 한 줄로
   묶거나 접는다. 컬럼을 그대로 세로로 쌓지 않는다.
6. **셸(테두리·배경·hover·클릭)은 `AppTable` 이 그리고, 카드 컴포넌트는 내용만 반환한다.**
   카드마다 셸을 들면 화면마다 모양이 서서히 갈라진다.
7. 🔴 **빈 값 표기가 테이블과 달라질 수 있다.** 테이블의 `—` 는 같은 열의 다른 행과
   비교돼 읽히지만, 카드에서는 그 줄 하나만 보여 **값이 빠진 것처럼** 읽힌다 —
   `종료 —` 대신 **`종료 진행 중`** 처럼 **사실을 적는다**.
8. **행 클릭이 있으면 카드는 `button` 이다**(키보드로 눌려야 한다). ⚠️ 그러면 **접근성
   이름에 카드 내용이 전부 들어가** 다른 버튼과 이름이 겹칠 수 있다 — 필터 영역처럼
   헷갈리는 자리에는 `role="group" aria-label` 로 경계를 준다(030 에서 실제로 겪었다).
   ⚠️ **카드 안에 버튼을 둘 수 없다**(중첩 금지). 지점이력의 "기록 N건" 버튼은 그 화면에
   행 클릭이 **없어서** 가능했다 — 행 클릭이 생기면 그 버튼을 밖으로 빼야 한다.
9. ⚠️ **테스트에서는 DOM 에 두 벌이 있다**(jsdom 에 Tailwind 가 없어 둘 다 조회된다).
   `within(screen.getByRole('table'))` 로 영역을 좁힌다. "테이블 1 + 카드 1 = 2" 가 **정상**이다.

### 하지 않은 것

- **공용 카드 셸을 뽑지 않았다**(`spec 030` T449). 네 벌의 **제목 줄은 같지만** 메타 줄이
  가로/세로로 갈리고, 3번째 줄·꼬리 버튼의 유무가 제각각이라 prop 5개짜리 추상화가 된다.
  시각적으로 갈라질 위험이 큰 **셸은 이미 `AppTable` 이 공유**한다(023 DoD #17 과 같은 판단).
- **좁은 폭 baseline 캡쳐를 남기지 않는다**(OQ-030-B). 폭별로 찍으면 장수도 노이즈도 두
  배다 — baseline 의 목적은 **PC 화면의 퇴행 감시**다.
- **`/users` 는 제외**(OQ-030-A). 좁은 폭에서 깨지는 주범이 테이블이 아니라 **400px 고정
  패널**이라, 카드만 붙이면 카드가 들어갈 폭이 안 남는다. Phase 4 재구성 때 함께 붙인다.

### 사용 화면

| 화면 | 컬럼 | 카드 |
|---|:-:|---|
| `/zones` | 6 | 코스명 + 사용·교대 / 지점 수 · 소요시간 / 최근 순찰 |
| `/points` | 5 | 지점명 + 사용·인증수단 / 소속 코스 / 최근 순찰 |
| `/patrol/zones` | 4 | 코스명 + 결과 / 시작 · 종료 |
| `/patrol/points` | 8 | 지점명 + 결과·인증 / 코스 · 일시 · 순찰자 / 기록 |

## 13. 컴팩트 필터 팝오버 (2026-10-10)

> 구현: `components/app/AppFilterPopover.tsx` · 첫 사용처: `/points`(`spec 027`)

### 왜 생겼나

`AppFilterButton`(트리거 **시각**)은 010·017 때부터 있었지만 **조립 사례가 0건**이었다 —
주석에 "콘텐츠 조립은 소비 측 책임" 이라 적힌 채 `/patrol/points` 5개·`/users` 2개가
**눌러도 아무 일 없는 죽은 버튼**으로 남아 있었다. 027 이 그 조립을 처음 채웠다.

### 규칙

1. **트리거 = `AppFilterButton`** 그대로 쓴다. 시각을 다시 만들지 않는다.
2. 🔴 **"전체" 는 값이 아니라 해제다** — `onChange(undefined)`. `ALL` 같은 센티넬을 URL·서버로
   흘리지 않는다(018 규약 / `spec 022` 규칙 8).
3. 🔴 **선택값을 버튼 라벨에 붙인다**(`인증수단: QR`). 열지 않고도 무엇이 걸렸는지 알아야 한다.
4. **선택 표시는 체크 아이콘 + 굵기** 둘 다 — 색만으로 전달하지 않는다(`design-system.md` §3).
5. **단일 선택 전용이다.** 날짜 범위·다중 선택은 **소비처가 생길 때** 넓힌다(A6).
   `/patrol/points` 의 기간·순찰자 필터는 `spec 024` 몫이다.
6. 필터 변경은 **URL 에 쓰고 첫 페이지로 되돌린다**(§6과 함께 쓴다).

### 사용 화면

- `/points` (027) — 인증수단 · 사용여부
- 대기 중: `/patrol/points` 5종 · `/users` 2종 (`spec 024` 이후)
