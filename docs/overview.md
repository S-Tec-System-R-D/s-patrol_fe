# 모바일순찰 — Overview

> 이 문서는 프로젝트가 **무엇을 만드는지** 한눈에 잡기 위한 요약본이다.
> 입력: [`docs/functional-spec.md`](./functional-spec.md) (회사 기능정의서 가공본)
> 상세 화면/권한/데이터모델은 별도 문서(`screens.md`, `data-model.md`)에서 다룬다.

---

## 1. 한 줄 정의

에스텍시스템의 **사업장 순찰 업무를 디지털화**하는 솔루션의 **WEB 파트**.
순찰 수행 자체는 근무자가 APP으로 하고, WEB은 그 위에서 **관리·설정·조회**(순찰코스/순찰지점/순찰이력 관리, 본사 운영 도구)를 담당한다.

## 2. 시스템 구성

도메인: **s-patrol.co.kr**

```
┌──────────────────────────────────────────────────────────────────┐
│  /                  ← 랜딩 (정적 소개, 공개)                       │
│  /login             ← 현장 로그인                                  │
│  /admin/login       ← 본사 로그인 (URL 직접 접근)                  │
│                                                                  │
│  WEB-Service  (/*)        ← 현장 운영 사이트 (담당)                │
│  WEB-Admin    (/admin/*)  ← 본사 운영 사이트 (담당)                │
│  APP                      ← 근무자 순찰 수행 (별도 팀)              │
│  Backend                  ← 별도 팀                                │
└──────────────────────────────────────────────────────────────────┘
```

**내 담당 = 랜딩 + 두 로그인 + WEB-Service + WEB-Admin.**
두 로그인 화면은 별도 URL이며 메뉴로 연결되지 않는다(본사는 URL 직접 접근).

## 3. 대상 사용자

WEB은 두 영역으로 갈리며, 각 영역의 **기준 사용자**가 다르다.

### 3-1. `/*` (WEB-Service) — 기준: **현장관리자**

- 사업장 팀장. 본인이 맡은 사업장의 근무자/순찰지점/순찰코스/순찰이력을 관리한다.
- 명세서상 "여기에 가장 공들임"이라 명시된 1차 타겟.
- 화면·UX는 이 사람 기준으로 설계한다.

### 3-2. `/admin/*` (WEB-Admin) — 기준: **시스템관리자**

- 에스텍시스템 운영진(개발부서). 솔루션 전체를 운영하는 최상위 권한.
- 관리그룹·사업장·헬스체크 같은 회사 운영 측 설정을 담당한다.
- 화면·UX는 이 사람 기준으로 설계한다.

### 3-3. 전체 권한 체계 (참고)

| Role          | 영역              | 비고                              |
| ------------- | ----------------- | --------------------------------- |
| 시스템관리자  | `/admin/*` + `/*` | 에스텍 운영진. Master 생성        |
| Master        | `/admin/*` + `/*` | 고객사 총괄. Manager 생성         |
| Manager       | `/admin/*` + `/*` | 본부/지사 관리. 할당 사업장만     |
| 현장관리자    | `/*` 만           | 사업장 팀장. 근무자 생성          |
| 근무자        | **WEB 접근 불가** | APP 전용 (순찰 수행)              |

→ 권한별 화면 매트릭스는 `screens.md`에서 상세.

## 4. 핵심 가치 (왜 만드는가)

- **종이/구두 보고 → 디지털화**: 사업장 순찰을 QR/NFC 인증 기반으로 기록해 누락·허위 보고를 줄인다.
- **현장–본사 분리**: 현장 운영(`/*`)과 본사 운영(`/admin/*`)을 한 시스템에서 권한으로 분리 운영.
- **이력 추적**: 순찰코스 단위 이력 + 순찰지점 단위 이력 두 관점으로 조회·검색·Export(Excel/PDF).
- **알림 연계**: 공지사항은 APP 알림 트리거, 비상연락망은 별도 수신 대상 설정.

## 5. 핵심 도메인 (한눈에)

| 도메인       | 한 줄 설명                                                  |
| ------------ | ----------------------------------------------------------- |
| 관리그룹     | Level 3 트리. Level1 = "에스텍시스템" 고정                  |
| 사업장       | 관리그룹 하위. 헬스체크/비상연락망 설정 보유                |
| 근무자       | 사업장 소속. 배치 이력 보유(배치는 APP 요청 → 목적지 관리자 승인)  |
| 순찰지점     | 인증수단 = QR 또는 NFC(14자리 HEX)                          |
| 순찰코스     | 순찰지점들의 **순서 있는** 묶음. 드래그 정렬, 지점별 소요시간 |
| 순찰이력     | "코스 이력" / "지점 이력" 두 관점. 조회 전용                |
| 부가         | 공지사항, 키워드(환경설정), 헬스체크 설정                   |

> **용어 주의**: 명세서의 "순찰코스" = 현재 코드의 `Zone`/`ZoneType`. 본 문서는 명세서 용어("순찰코스/순찰지점")를 표준으로 쓴다. 코드 식별자는 추후 리네이밍 대상.

## 6. 범위 (Scope)

### 할 것

- 공개: `/` 랜딩(정적 소개, 현장 로그인 진입 링크) / `/login` 현장 로그인 / `/admin/login` 본사 로그인
- `/*` (WEB-Service) 전체: 근무자 / 순찰지점 / 순찰코스 / 순찰이력 / 공지사항 / 환경설정(키워드)
- `/admin/*` (WEB-Admin) 전체: 관리자 목록 / 관리그룹 / 사업장(목록·추가·변경·삭제) / 헬스체크 설정 / 비상연락망 수신대상 설정
- 모든 화면 반응형(PC 기준 + 모바일 분할화면 대응)
- 라우트 가드 + 화면 내 액션 권한 가드

### 안 할 것

- APP 기능 일체 (순찰 수행 UX)
- Backend 전부
- 헬스체크 응답 수신 UX (APP 영역)
- 비상연락 전화 발신 (APP 영역, WEB은 수신대상 등록만)

## 7. 제약

- **스택**: React 19 + Vite + TypeScript + Tailwind v4
- **도메인**: `s-patrol.co.kr`
- **라우트 구조**: 공개 영역(`/` 랜딩 · `/login` · `/admin/login`) + 인증 영역(`/*` 현장 · `/admin/*` 본사). 두 로그인은 별도 URL이며 서로 메뉴로 연결되지 않음
- **인증**: JWT(role 포함) + 로그인 시 본인 계정정보 조회로 가드
- **반응형**: PC 기준 + 모바일은 분할화면 대응 UI만. **모바일 전용 기능 없음**
- **검색 상태 저장**: URL 쿼리스트링 (기존 `useQueryParams` 패턴 재사용)
- **공통 UX**: 에러/로딩/빈 상태는 공통 컴포넌트 사용 (전역 규칙)
