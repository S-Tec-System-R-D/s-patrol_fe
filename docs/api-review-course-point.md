## 0. 우선순위 요약 — **이것부터**

| 순위 | 항목 | 어느 화면이 막히나 | 번호 |
|:-:|---|---|---|
| **1** | **`totalMin` 을 검증 없이 저장한다** — `null` 로 보내면 **서버가 구간합을 계산하는데**, 값이 오면 합과 달라도 그대로 저장한다(99 보내면 99). 사업장 6 의 **7개 중 5개** 어긋남 | 코스 목록·상세 **둘 다 틀린 수**를 보여준다. ⚠️ 웹 화면 조작으로는 안 생긴다(프론트가 항상 `null` 을 보내 서버가 계산하게 한다) — **과거·외부 경로로 들어간 값**이다 | B-31 |
| **2** | **`AddCourse` 가 `points` 를 버리면서 200 + `data: true`** — 편성은 저장되지 않고(`pointCount: 0`) **`totalMin` 만 그 지점들의 구간합으로 채워진다** | 코스 생성. 실패를 알 수 없고 **"지점 0개인데 시간이 있는 코스"** 가 남는다(순위 1 의 발생 경로) | B-27 |
| **3** | **TAG ID 중복이 500** + **삭제한 지점이 태그를 계속 점유** | 지점 추가·수정. 사용자에게 **사유를 못 보여준다**("다시 시도" 해도 안 됨) | B-39 |
| **4** | **좌표에 범위 검증이 없다** — `gpsLat: 123` 이 저장돼 있다 | 코스 상세 지도. 프론트가 검사를 떠안는 중 | B-33 |
| 5 | `UpdateCourse` 의 `points` 가 **전량 교체**다 | 코스 편성. 동작은 받아들이고 **문서화만** 요청한다(프론트는 전량 전송으로 맞춰 두었다) | B-25 |
| **6** | **`points[].useYn` 이 항상 `true`** — 같은 지점을 `GetPointList`·`DetailPoint` 는 `false`, 편성 후보 목록은 **제외**하는데 **코스 상세만 `true`**(재현 2026-10-15, 사업장 7 / 코스 78) | 코스 상세. **미사용 지점이 편성된 채 남은 코스**를 구분 못 한다 → 꺼진 지점을 계속 순찰 대상으로 본다 | B-36 |
| 7 | 편성 지점 `memo` 가 **쓰기 전용** | 구간 메모 UI 를 만들 수 없다 | B-30 |
| 8 | 값 비우기 불가(`null`·`''` 무시) | 설명을 비울 수 없다 | B-15 |
| 9 | 오류 메시지가 전부 `"잘못된 요청입니다."` | 사유를 안내할 수 없다 | B-17 |

❓ **함께 묻고 싶은 것**: **지점 좌표는 누가 채웁니까?** 모바일 앱이 등록 시 채우는지,
별도 관리 화면이 있어야 하는지 모릅니다. 현재 웹에는 **입력 수단이 없습니다**.

`siteSeq`(필수) · `searchKey` · `useYn` · `switchYn` · `courseStatus` · `pageNumber` · `pageSize`

| 화면 요소 | 쓰는 필드 | 상태 |
|---|---|---|
| 코스명 | `courseName` | ✅ |
| 지점 수 | `pointCount` | ✅ |
| **총 소요시간** | `totalMin` | 🔴 **구간시간 합과 어긋남**(B-31) — 아래 §2-6 참조 |
| 교대 | `switchYn` | ✅ |

## 2. 코스 상세 `/zones/:courseSeq`

이 화면은 **4개 API** 를 쓴다: `GetCourseDetail` · `GetCourseHistory`(30일) ·
`GetPointHistory`(미인증) · `GetClassificationPoint`(편성 모달).

### 2-1. 헤더 — 제목·상태·삭제

| 요소 | 출처 | 상태 |
|---|---|---|
| 코스명 | `GetCourseDetail.courseName` | ✅ |
| 사용 뱃지 | `useYn` | ✅ |
| 지점 수·소요시간 요약 | 목록 응답 | ⚠️ **상세 응답에는 `pointCount`·`courseStatus` 가 없다** — 목록에서 받은 값을 들고 온다 |
| 삭제 | `DELETE DeleteCourse?**courseId**=` | ⚠️ **파라미터명만 `courseId`** 다(나머지는 `courseSeq`) — B-12 |

### 2-2. KPI 4칸

**API** — `GetCourseHistory`(30일, `pageSize=100`) + `GetPointHistory`(`status=3`, 건수만)

| 칸 | 쓰는 값 | 상태 |
|---|---|---|
| 30일 순찰 수행 | `totalCount` + 행별 `status`(0 진행·1 완료·2 미완료) | ✅ |
| 평균 소요시간 | 행별 `actualElapsedTime` | ⚠️ **시 단위가 섞여 온다**(`"02:17:40"`) — 프론트가 흡수 중 |
| ″ **기준값**(목업: `설정 45분`) | `totalMin` | 🔴 **못 쓴다** — B-31 |
| 지점 인증률 | `checkedCount` / `pointCount` | ⚠️ ❓ **`순찰제외`(status 2) 지점이 `pointCount` 에 포함됩니까?** 모르면 **영원히 100% 가 안 되는 코스**가 생겨 색을 못 입힌다 |
| 미인증 지점 | `GetPointHistory(status=3).totalCount` | ✅ |

⚠️ **집계 API 가 없어** 30일치 행을 받아 **프론트가 센다**. 기간을 6개월·1년으로 넓히면
`pageSize` 100 상한에 걸려 **총계가 조용히 적게** 나온다 → 그때 **집계 엔드포인트가 필요**하다.

### 2-3. 순찰 동선(지도)

**API** — `GetCourseDetail.points[].gpsLat` / `gpsLng`

| 항목 | 상태 |
|---|---|
| 좌표 전달 | ✅ **B-32 해소 확인**(2026-10-14) — 지점 상세와 **13건 전부 일치**, 전파 실패 0건 |
| 값이 비어 있음 | ⚠️ 사업장 6 에서 **지점 1개**(`pointSeq 19`)가 `null`. ❓ **좌표는 누가 채웁니까?** |
| **범위 검증** | 🔴 **없다** — 사업장 3 에 `gpsLat: 123`(위도는 ±90). **400 으로 거부**해 주십시오. ⚠️ 이미 저장된 값도 **정정이 필요**합니다 — B-33 |

### 2-4. 지점 순서(편성)

**API** — `GetCourseDetail.points[]` / 저장은 `PUT UpdateCourse`

| 항목 | 상태 |
|---|---|
| 지점명·인증수단·구간시간 | ✅ |
| `useYn` | 🔴 **항상 `true`** — 지점을 미사용으로 바꿔도 **코스 응답은 그대로**다. 재현(2026-10-15, 사업장 7 / 코스 78 / 지점 56): `GetPointList`·`DetailPoint` 는 `false`, `GetClassificationPoint` 는 그 지점을 **제외**하는데 **코스 상세만 `true`** 다 — 서버가 실제 값을 읽을 수 있다는 뜻이므로 **코스 상세만 안 읽고 있다**. **지점의 실제 값을 반영**하거나, 반영이 어려우면 **응답에서 빼** 주십시오 — B-36 (**P1**) |
| 구간 **메모** | 🔴 **쓰기 전용** — `UpdateCoursePointDto` 는 받고 200 을 주는데 `GetCourseDetail.points[]` 에 **그 필드가 없다**. 전량 전송 규약과 겹쳐 **다른 경로로 들어간 메모를 조용히 지운다** — B-30 |
| `orderNo` | ⚠️ **중복을 그대로 저장**한다(둘 다 `1` 로 보내면 그대로) — 1..N 재부여는 프론트가 하는 중 |

### 2-5. 편성 모달(지점 추가)

**API** — `GET GetClassificationPoint?siteSeq=`

| 항목 | 상태 |
|---|---|
| 후보 목록 | ✅ **미사용 지점은 서버가 제외**해서 준다(실측 14건 → 13건 → 복귀로 확인) |
| 페이징 | ⚠️ **없다** — 사업장 지점이 전량 내려온다. 지점이 수백 개가 되면 느려진다 |
| **코스 소속 정보** | 🔴 **없다** — 그래서 목업의 **`미배정` 필터를 만들 수 없다**(지점마다 상세 조회 N+1). 필요하면 `usedCount` 같은 값을 **후보 응답에 넣어** 주십시오 |
| 중복 편성 | ⚠️ **서버가 막지 않는다**(같은 지점 2번 통과) — 화면에서 막는 중 |

### 2-6. 기본정보 · 총 소요시간 🔴 **최우선**

**API** — `GetCourseDetail` / 저장은 `PUT UpdateCourse`

| 항목 | 상태 |
|---|---|
| **총 소요시간** | 🔴🔴 **구간시간 합과 다르다.** 재실측(2026-10-14) **7개 중 5개 어긋남** — 아래 표 |
| `siteSeq` | ⚠️ **상세 응답에 없다** — `UpdateCourse` 가 요구하므로 프론트가 선택값을 들고 있다 |
| 설명(`memo`) | ✅ 비울 수 있다(지점과 반대 — B-15 는 지점만) |

```
코스                    totalMin   구간시간 합   지점
nfc인증 가능 코스              10          0      3   ← 🔴
qwe                          0          0      4   ✅
순찰 인증 가능한 지점           25         25      3   ✅
2호선 지옥철 코스              30         25      3   ← 🔴
강남 우체국 계단코스            60         25      2   ← 🔴
주간 순찰 B코스               60          0      0   ← 🔴🔴 지점이 없는데 60분
야간 순찰 A코스               45          5      1   ← 🔴
```

**요청 3건**
1. **저장 시 항상 구간시간 합으로 계산**해 주십시오. 지금은 `totalMin: null` 을 보낼 때만
   계산해 주고, **값을 보내면 검증 없이 그대로 저장**됩니다(`totalMin: 99` + 합 25 → 99 저장).
2. **기존 데이터를 일괄 정정**해 주십시오. 웹에는 총 소요시간 입력란이 **없고 만들지도 않을**
   계획이라(파생값이므로) **우리가 고칠 수 없습니다.**
3. 가능하면 **요청 DTO 에서 `totalMin` 을 빼** 주십시오 — 보낼 수 없으면 틀릴 수도 없습니다.

### 2-7. 최근 순찰 기록 · 미인증/이상 이력

**API** — `GetCourseHistory` + `GetPointHistory`

| 항목 | 상태 |
|---|---|
| 순찰 기록 표 | ✅ |
| 근무자 | ⚠️ `userList` 가 **빈 배열**인 이력이 있다(화면은 "근무자 기록 없음") |
| 완료인데 인증 0 | ⚠️ `status=1` 인데 `checkedCount: 0` 인 행이 있다 — 상태와 인증률이 **독립** |
| 메모 내용 | ⚠️ 목록에 **없어** 행마다 상세 조회(N+1)가 필요 → 지금은 **`메모` 뱃지만** 표시 |
| 필드명 불일치 | ⚠️ 목록 `overtimeYn` ↔ 상세·지점이력 **`overTimeYn`**(대문자 T) — B-4 |
| 타입 불일치 | ⚠️ `pauseTime` 이 목록은 문자열, 상세는 **숫자** — B-5 |
| status 사전 | ⚠️ 코스(`1 완료 / 2 미완료`)와 지점(`3 미완료 / 4 완료`)이 **다르다** — B-7. 통일해 주시면 좋겠습니다 |

### 2-8. 변경계(생성·수정·삭제·토글)

| 호출 | 상태 |
|---|---|
| `POST AddCourse` | 🔴 **`points` 가 무시된다** — 지점을 실어 보내도 `pointCount: 0` 인데 **200 + `data: true`** 가 온다. 성공으로 믿으면 **지점 없는 코스**가 남는다 — B-27 |
| `PUT UpdateCourse` | 🔴 **`points` 는 전량 교체** — 생략·빈 배열·일부 전송 **모두 나머지를 삭제**하고 **200** 이 온다. 코스명만 바꾸려다 지점을 전부 날릴 수 있다 — B-25 |
| ″ `courseSeq` 누락 | 🔴 **401** 이 온다(유효성 오류인데). 프론트 인터셉터가 **토큰 만료로 오해**해 재발급·로그아웃 경로를 탄다 → **400** 이어야 합니다 — B-28 |
| ″ 메서드 | ⚠️ **`PUT`** 이다(지점은 `PATCH`). `UpdateCourseDto` 에 **required 가 하나도 없다** — B-24·B-26 |

## 4. 지점 상세 `/points/:pointSeq`

**API** — `DetailPoint` + `GetPointHistory`(2주) / 변경은 `PATCH UpdatePoint` · `DELETE DeletePoint`

### 4-1. KPI 3칸

| 칸 | 쓰는 값 | 상태 |
|---|---|---|
| 2주 인증 | `GetPointHistory` 행의 `status=4` | ⚠️ **필터 없이 부르면 미완료(3)와 완료(4)가 섞여 온다**(69건 중 미완료 43건). 🔴 **미완료 행도 `checkDt` 를 갖는다** — 프론트가 `status` 로 가르는 중 |
| 최근 순찰 | `DetailPoint.lastPatrolDt` | ✅ |
| 소속 코스 | `courseList.length` | ✅ |

🔴 **`pageSize` 상한이 100** 이다. 우리가 200 을 보내 **이 화면의 조회가 통째로 400** 이었고
화면에는 "순찰 기록이 없습니다" 가 떴다(2026-10-14 수정). **상한을 문서화**해 주시면 좋겠습니다.

### 4-2. 기본정보

| 항목 | 상태 |
|---|---|
| 지점명·설명·인증수단 | ✅ |
| **좌표** | ⚠️ 표시만 한다. 입력 수단이 **없다** — ❓ **누가 채웁니까?** |
| 생성·수정 메타 | — **요청 철회**(B-19). 화면에서 그 칸들을 뺐으므로 **필요 없습니다** |
| 설명 비우기 | 🔴 **불가** — `null`·`''` 를 무시하고 **200 을 준다**(조용히 실패) — B-15 |

### 4-3. 자격증명(QR / NFC)

| 항목 | 상태 |
|---|---|
| `qrCode` | ✅ 있다(`STSP1:{siteSeq}:{pointSeq}:{epoch}:{서명}`) — 화면이 **QR 이미지를 그린다** |
| 발행 메타(발행일·버전) | ⚠️ 없다 — 화면에 **표시하지 않는 중** (B-23) |
| **`reissueQrYn`** | ⚠️ **결과를 바꾸지 않는다**(재측정 2026-10-15 · 6가지 경우 전부 `true`/`false` 동일). 다만 **발급 자체는 정상**이다 — NFC 로 만든 지점(코드 없음)을 QR 로 바꾸면 **플래그와 무관하게 서버가 발급한다**. 🔴 **이미 발급된 코드를 교체할 수단은 없다** → 재발행 버튼을 만들지 않았다. 이전 판의 "재발행 무동작 **P1**" 은 **철회**하고 질문(**Q6**)으로 남긴다 |
| NFC TAG ID | ✅ 표시·수정 가능 |
| TAG ID **비우기** | 🔴 불가(B-15) — NFC→QR 로 바꿔도 **TAG ID 가 남는다**. 화면에서 숨기는 중 |
| TAG ID **중복** | 🔴 **500 + ProblemDetails** — 유효성 오류가 500 으로 새어 **사용자에게 사유를 못 보여준다**("다시 시도해 주세요" 가 뜨는데 다시 해도 안 됩니다). ⚠️ **삭제한 지점이 태그를 계속 점유**합니다 — **400 + 사유 문구**로, 그리고 삭제된 지점의 태그는 **해제**해 주십시오 — B-39 |

### 4-4. 인증수단 전환

| 항목 | 상태 |
|---|---|
| QR↔NFC 전환 | ✅ `PATCH UpdatePoint` 로 동작 |
| NFC 전환 시 TAG ID | ✅ **필수**(`"NFC 값을 입력해주세요."`) — 🔴 **사유를 말해 주는 드문 메시지**라 화면이 그대로 노출합니다. 다른 곳도 이렇게 해 주시면 좋겠습니다 |
| 범위 밖 `authMethod` | ⚠️ `99` 를 보내도 같은 메시지(`"NFC 값을 입력해주세요."`)가 온다 — **9 가 아니면 전부 NFC 로 보는** 분기로 보입니다 — B-38 |
| 부분 갱신 | ✅ 진짜 부분 갱신이다. `authMethod` 를 생략하면 TAG ID 를 묻지 않는다 |
