# 배치관리 API 요청 — 백엔드 전달용

> 작성 2026-10-21 (`spec 039`) · 프론트가 화면을 먼저 만들고, 화면에 필요한 API 를 정리했다.
> 응답 형태는 **기존 API 관례**(`ApiResponse` 래퍼 · `PagedData` · `~Seq` · 정수 상태 코드 + 이름)를 따르면 된다.
> 화면: 현장 사이트 `/deployments` — 근무자가 앱에서 보낸 배치·복귀 요청을 **목적지 사업장 관리자**가 승인·거부한다.

## 필요한 API

1. **배치 요청 목록 API** — 현재 사업장으로 들어온 **대기 중** 배치·복귀 요청 목록(요청자 · 출발 사업장 · 도착 사업장 · 배치/복귀 구분 · 사유 · 요청일시). 페이징.
2. **배치 요청 승인 API** — 대기 중 요청 1건 승인. 승인되면 근무자가 도착 사업장으로 배치(또는 복귀)되고 이력이 1건 생긴다.
3. **배치 요청 거부 API** — 대기 중 요청 1건 거부. **거부 사유(필수)** 를 받는다. 사유는 근무자 앱에만 보인다.
4. **전출 이력 API** — 현재 사업장 **소속** 근무자가 타 사업장으로 배치된 이력(근무자 · 도착 사업장 · 사유 · 시작일 · 복귀일(없으면 배치 중)). 페이징 + **상태 필터(배치 중 / 복귀 완료)**.
5. **전입 이력 API** — 타 사업장 소속 근무자가 현재 사업장으로 배치된 이력(근무자 · 출발 사업장 · 사유 · 시작일 · 복귀일). 페이징 + **상태 필터(배치 중 / 복귀 완료)**.
6. **근무자별 배치 이력 API** — 근무자 1명의 배치·복귀 이력(근무자 상세 화면). 4·5 에 `userSeq` 필터를 붙이는 방식이어도 된다.
7. **배치 현황 요약 API** — 현재 사업장 기준 숫자 3개: **배치 나간 인원**(소속인데 지금 타 사업장에 있는 사람) · **배치 온 인원**(타 소속인데 지금 여기 있는 사람) · **대기 중 요청 건수**. 사이드바 뱃지에도 대기 건수를 쓴다.

## 함께 부탁드리는 것

- 파라미터 이름은 다른 API 와 같게 **`siteSeq`·`userSeq`** 로 맞춰 주세요(근무자 API 는 `siteId`·`userId` 라 따로 맞추고 있습니다).
- 이미 처리된 요청(승인·거부·근무자 취소)을 다시 승인·거부하면 **비즈니스 오류(래퍼 + 사유 메시지)** 로 주세요 — 화면이 "이미 처리된 요청입니다" 를 안내합니다.
- 현장관리자 권한으로 호출할 수 있어야 합니다(근무자 API 는 처음에 403 이었습니다 — B-41).
