# 배치관리 API 요청 — 백엔드 전달용

> 작성 2026-10-21 (`spec 039`) · 프론트가 화면을 먼저 만들고, 화면에 필요한 API 를 정리했다.
> 응답 형태는 **기존 API 관례**(`ApiResponse` 래퍼 · `PagedData` · `~Seq` · 정수 상태 코드 + 이름)를 따르면 된다.
> 화면: 현장 사이트 `/deployments`.
>
> **배치 로직**: ① 근무자가 앱에서 **사업장 · 시작일 · 종료일(선택) · 사유**로 **배치 요청** → **목적지 사업장**
> 관리자가 웹에서 승인·거부 → ② 승인하면 이력에 나온다 → ③ 돌아올 때 근무자가 앱에서 **복귀 요청** →
> **원소속 사업장** 관리자가 웹에서 승인·거부 → ④ 복귀를 승인하면 그 배치가 복귀일로 끝난다.
>
> API 는 **배치(요청 · 승인 · 거부)** · **복귀(요청 · 승인 · 거부)** 로 나뉜다(요청 완료). 요청 생성은 앱에서 쓰고,
> 웹은 아래 목록 · 승인 · 거부와 이력 · 요약을 쓴다.

## 배치

1. **배치 요청 목록 API** — 현재 사업장(목적지)으로 들어온 **대기 중** 배치 요청 목록(요청자 · 출발 사업장 · 도착 사업장 · **시작일 · 종료일(없을 수 있음)** · 사유 · 요청일시). 페이징.
2. **배치 요청 승인 API** — 대기 중 요청 1건 승인. 승인되면 이력이 1건 생긴다(기간 = 요청의 시작일·종료일).
3. **배치 요청 거부 API** — 대기 중 요청 1건 거부. **거부 사유(필수)** 를 받는다. 사유는 근무자 앱에만 보인다.

## 복귀

4. **복귀 요청 목록 API** — 현재 사업장(**원소속**)으로 들어온 **대기 중** 복귀 요청 목록(요청자 · 지금 배치된 사업장 · 돌아올 사업장 · **복귀일** · 사유 · 요청일시 · 닫힐 배치 이력 번호). 페이징.
5. **복귀 요청 승인 API** — 대기 중 복귀 요청 1건 승인. 승인되면 그 배치 이력의 종료일 = 복귀일.
6. **복귀 요청 거부 API** — 대기 중 복귀 요청 1건 거부. **거부 사유(필수)**.

## 이력 · 요약

7. **전입 이력 API** — 타 사업장 소속 근무자가 현재 사업장으로 배치된 이력(근무자 · 출발 사업장 · 사유 · 시작일 · 종료일(없으면 미정)). 페이징 + **근무자 이름 검색(부분 일치)** + **상태 필터(배치예정 / 배치중 / 복귀완료)** — 상태는 서버가 날짜로 계산해서 주면 좋겠습니다(시작 전 = 예정 · 종료일 지나면 복귀완료).
8. **전출 이력 API** — 현재 사업장 **소속** 근무자가 타 사업장으로 배치된 이력(근무자 · 도착 사업장 · 사유 · 시작일 · 종료일). 페이징 + 이름 검색 + 상태 필터(7번과 같다).
9. **근무자별 배치 이력 API** — 근무자 1명의 배치·복귀 이력(근무자 상세 화면). 7·8 에 `userSeq` 필터를 붙이는 방식이어도 된다.
10. **배치 현황 요약 API** — 현재 사업장 기준 숫자: **배치 나간 인원**(소속인데 지금 타 사업장에 **배치중**인 사람) · **배치 온 인원**(타 소속인데 지금 여기 **배치중**인 사람) · **대기 중 배치 요청 건수** · **대기 중 복귀 요청 건수**. 예정·복귀완료는 세지 않는다. 사이드바 뱃지에는 배치 요청 건수만 쓴다.

## 함께 부탁드리는 것

- 파라미터 이름은 다른 API 와 같게 **`siteSeq`·`userSeq`** 로 맞춰 주세요(근무자 API 는 `siteId`·`userId` 라 따로 맞추고 있습니다).
- 이미 처리된 요청(승인·거부·근무자 취소)을 다시 승인·거부하면 **비즈니스 오류(래퍼 + 사유 메시지)** 로 주세요 — 화면이 "이미 처리된 요청입니다" 를 안내합니다.
- 현장관리자 권한으로 호출할 수 있어야 합니다(근무자 API 는 처음에 403 이었습니다 — B-41).
