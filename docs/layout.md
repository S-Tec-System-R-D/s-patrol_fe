# 레이아웃 (layout.md)

> 본 프로젝트의 **레이아웃 셸**과 그 구성 요소 가이드.
> 디자인 토큰은 [`design-system.md`](./design-system.md), 컴포넌트는 [`components.md`](./components.md), 사용자 동선은 [`flow.md`](./flow.md) 참조.
>
> **리디자인 반영 상태 (2026-07-23~)**
> - 현장 사이트: 컴팩트 아이콘 레일 + **TopNav 삭제**로 전환. 아래 §0·§2·§3 참조.
> - `/admin/*` 본사 사이트: 이번 라운드 미적용 → 기존 스펙(사이드바 w-70 + TopNav) 유지.
> - 두 사이트가 서로 다른 셸을 갖는 것이 정상. `AppLayout`은 영역별 분기.

## 0. 전체 셸 구조

### 0-1. 현장 사이트 (`/*`) — 리디자인 반영

```
┌───────────────────────────────────────────────┐
│           .app-shell (자연 스크롤)            │
│ ┌────┬─────────────────────────────────────┐  │
│ │    │ (TopNav 없음)                        │  │
│ │Rail│                                      │  │
│ │68px│ ┌──────────────────────────────┐    │  │
│ │    │ │ 페이지 헤더 (제목 + 서브텍스트│    │  │
│ │    │ │            + 우측 액션)      │    │  │
│ │    │ ├──────────────────────────────┤    │  │
│ │    │ │ 탭 → 필터 칩 → body-row      │    │  │
│ │    │ │ (테이블 카드 + 상세 카드)    │    │  │
│ └────┴─────────────────────────────────────┘  │
└───────────────────────────────────────────────┘
```

- 좌측 레일: **68px 고정 다크 아이콘 레일** (sticky, full-height). 상단 로고 + 아이콘 4개, 하단 프로필 아바타.
- TopNav 없음. 페이지 헤더(제목 + 서브텍스트 + 액션)가 그 역할을 흡수.
- **페이지 자연 스크롤**: 리디자인은 `.app-shell`의 `overflow:hidden` 정책을 폐기하고 페이지 세로 스크롤을 허용. 뷰포트 제한 없는 실제 웹앱 환경을 반영.
- 컨텐츠 영역 배경: `--bg`(연한 톤), 카드는 `--surface`(흰색).

### 0-2. 본사 사이트 (`/admin/*`) — 기존 스펙 유지

```
┌─────────────────────────────────────────────────┐
│              .app-shell (전체 100vh)            │
│ ┌─────────┬─────────────────────────────────┐   │
│ │         │           TopNav                │   │
│ │ Sidebar ├─────────────────────────────────┤   │
│ │  w-70   │                                 │   │
│ │         │   Contents (Outlet)             │   │
│ │         │   bg-contents-background        │   │
│ └─────────┴─────────────────────────────────┘   │
└─────────────────────────────────────────────────┘
```

- `.app-shell` 유틸 = `display:flex; height:100vh; overflow:hidden;` (`src/index.css` 정의)
- 사이드바: 고정 폭 `w-70`
- 우측 컬럼: `flex flex-col min-h-0 flex-1` → TopNav + Contents(`flex-1 overflow-hidden`)
- 컨텐츠 영역은 자체 스크롤. 페이지 단위 패딩(보통 `p-8`)은 각 페이지가 결정.
- 본사 사이트의 리디자인은 추후 별도 라운드로 이월.

## 1. ServiceLayout / AdminLayout

`src/components/layout/ServiceLayout.tsx` + `src/components/layout/AdminLayout.tsx`

**영역 분기는 라우터 레벨에서 이뤄진다** (007 결정 — `useLocation` 조건분기 아님). `AuthGuard`는 인증 여부만 검사하고 `<Outlet />`만 렌더링한다. 셸은 `router/index.tsx`에서 `AuthGuard`의 두 자식 브랜치가 각각 담당한다.

```tsx
// 인증 성공 → AuthGuard(Outlet) → 영역별 라우터 브랜치 → 셸(ServiceLayout | AdminLayout) → 페이지(Outlet)
<AuthGuard>              {/* <Outlet/> */}
  <ServiceLayout />       {/* 현장(/*) 브랜치의 셸 — RailSidebar + 자연 스크롤 */}
  <AdminLayout />         {/* 본사(/admin/*) 브랜치의 셸 — Sidebar w-70 + TopNav */}
</AuthGuard>
```

**규칙**

- **영역 분기**: 라우터가 현장 라우트는 `ServiceLayout` 자식으로, 본사 라우트는 `AdminLayout` 자식으로 각각 묶는다. 단일 컴포넌트 내부 조건분기가 아니라 **라우터 노드 자체가 분리**되어 있다.
  - `ServiceLayout`(현장, `/*`): `RailSidebar`(68px 컴팩트 아이콘 레일) + TopNav 없음 + 페이지 자연 스크롤.
  - `AdminLayout`(본사, `/admin/*`): `Sidebar` w-70 + `TopNav` + 컨텐츠 자체 스크롤(`.app-shell`).
- **현장**: 페이지가 **자체 페이지 헤더**(제목 + 서브텍스트 + 우측 액션)를 그린다. TopNav 없음.
- **본사**: 페이지가 자체 헤더를 그리지 않는다(헤더는 TopNav가 담당).
- 페이지는 `<Outlet>` 안에서 `flex-1` 또는 그에 준하는 레이아웃을 가정한다.

## 2. Sidebar

`src/components/layout/sidebar/Sidebar.tsx` + `SidebarItem`, `sidebar.config.ts`

### 2-A. 현장 사이트 (리디자인 반영)

```
┌────┐
│ SP │  ← 로고 (68×68, 다크 배경)
├────┤
│ ▓  │  ← 순찰이력 (활성: 좌측 액센트 바 + 밝은 배경)
│ ◯  │  ← 코스/지점
│ ◯  │  ← 근무자
│ ◯  │  ← 배치관리 (대기 요청 수 뱃지)
│    │
│ ⋮  │  ← (예약: 알림 버튼 슬롯, 현재 비어 있음)
│ 👤 │  ← 프로필 아바타 (online dot)
└────┘
```

**규칙**

- 폭 **68px 고정**. `position: sticky; top: 0; height: 100vh`.
- 배경: `--rail`(다크). 활성 아이템: `--rail-2`(밝은 하이라이트) + **좌측 2px `--accent` 바**.
- 아이콘 온리. 라벨은 **hover 시 우측 툴팁**으로 노출.
- 아이콘 사이즈 20px, stroke 1.5.
- 그룹 헤더 없음. 아이콘 4개를 세로로 flat 배치.
- 하단: **프로필 아바타 + online dot**. 클릭 → 드롭다운(사용자명 + 로그아웃).
- 프로필 위 슬롯은 **알림 기능 추가 시 알림 버튼용**으로 예약. 현재는 비어 있음.
- 배치관리 아이콘에 **대기 요청 수 뱃지** 표시(우상단 붉은 dot + 숫자).
- 접기 기능 없음(이미 최소폭).

### 2-B. 본사 사이트 (기존 스펙 유지)

```
┌─────────────────┐
│ [🛡] PATROL     │  ← 헤더 (로고 + 사이트 뱃지)
├─────────────────┤
│   본사 관리     │  ← 그룹 헤더
│   ◯ 사업장 관리 │
│   ◯ 관리자 관리 │
├─────────────────┤
│ [<] 접기        │  ← SidebarToggle (좌측 하단, 미권장)
└─────────────────┘
```

- 폭 `w-70`, 텍스트 메뉴 유지.
- 활성: 좌측 보더 `border-l-2 border-primary` + `bg-sidebar-accent` + `text-sidebar-accent-foreground`.

### 2-1. 메뉴 정의 (`sidebar.config.ts`)

```ts
export interface MenuItemType {
  icon: LucideIcon
  title: string           // 툴팁 라벨(현장) / 인라인 라벨(본사)
  url: string
  activeUrl?: string[]    // 동일 영역의 여러 라우트를 한 메뉴로 묶을 때
  badge?: () => number    // 대기 요청 수 등 동적 뱃지 (현장 사이드바 전용)
}
export interface MenuGroupType {
  title: string
  groups: MenuItemType[]
}
```

- **현장 사이트 메뉴** (4개, flat): `순찰이력` / `코스/지점` / `근무자` / `배치관리`.
- **본사 사이트 메뉴**: `본사 관리 > 사업장 관리 / 관리자 관리`.
- 현장 사이드바에서는 `MenuGroupType`을 사용하지 않는다(그룹 헤더 없음).

### 2-2. 활성 판단 규칙 (공통)

- 우선순위: `activeUrl`(배열) > `url`(단일).
- 매칭: `pathname.startsWith(...)`.
- 예: 코스/지점 메뉴는 `activeUrl: ['/zones', '/points']`.

### 2-3. 활성 스타일

- **현장(레일)**: 배경 `bg-rail-2` + 좌측 `border-l-2 border-accent` + 아이콘 색상 승격.
- **본사**: 기존과 동일 (`border-l-2 border-primary` + `bg-sidebar-accent`).
- 아이콘: stroke 1.5.

### 2-4. 접기/펼치기

- **본사 사이드바**: 접기 기능 미권장. `SidebarToggle`은 남아 있으나 사용 금지.
- **현장 사이드바(레일)**: 이미 최소폭이므로 접기 개념 없음.
- 모바일 분할화면 대응은 §5-6에서 별도 처리.

## 3. TopNav

### 3-A. 현장 사이트 — **삭제**

리디자인에서 TopNav 자체를 제거. 사유:
- 페이지 헤더(§5-1)가 제목·서브텍스트·액션을 모두 흡수.
- 알림 기능이 아직 없음 → 알림 벨 불필요.
- 프로필 드롭다운은 **사이드바 하단 아바타**로 이동.
- 향후 알림 기능 추가 시 **사이드바 하단 프로필 위 슬롯**(§2-A)에 알림 버튼 배치.

`TopNav.tsx` / `AlarmSheet.tsx` 파일은 본사 사이트에서 계속 사용되므로 삭제하지 않는다. 현장 셸에서만 렌더링하지 않는다.

### 3-B. 본사 사이트 — 기존 유지

`src/components/layout/topnav/TopNav.tsx` + `ProfileBadge`, `AlarmSheet`

```
┌─────────────────────────────────────────────────┐
│ 현재 메뉴명                  [🔔] [👤 프로필]    │
└─────────────────────────────────────────────────┘
```

| 요소 | 역할 |
|---|---|
| 좌측 라벨 | 현재 진입한 메뉴 이름 (`menu-lookup.ts` 자동 도출) |
| `AlarmSheet` | 알림 아이콘 → 우측 `Sheet` 패널 (본문 미구현) |
| `ProfileBadge` | 사용자 아바타 + 드롭다운(내 정보 · 로그아웃) |

**규칙 (본사)**
- 페이지가 자체 헤더를 그리지 않는다. 페이지명·브레드크럼·필터는 컨텐츠 내부에서 처리.
- 알림은 `Sheet`로 우측에서 슬라이드.
- 프로필 뱃지는 둥근 아바타(목업 기준 그라데이션 또는 이니셜).

## 4. 컨텐츠 영역

`<Outlet />`이 들어가는 자리. 페이지 단위로 자체 레이아웃 책임.

### 4-1. 단일 컬럼

```
┌──────────────────────────────────────┐
│  (페이지 컨텐츠 — p-8)               │
└──────────────────────────────────────┘
```

### 4-2. 마스터-디테일 (가장 흔한 패턴)

```
┌──────────────┬───────────────────────┐
│   목록 카드  │   상세 카드           │
│   (좌)       │   (우, sticky)        │
│              │                       │
└──────────────┴───────────────────────┘
```

- **리디자인 규칙**: 좌우 컬럼을 각각 **동일 레벨의 카드**(테두리 + radius)로 감싼다. 이전에는 우측 상세가 풀블리드로 붙어 있었으나 "따로 노는 느낌" 피드백으로 카드화됨.
- 우측 상세: `position: sticky` — 좌측 리스트가 세로 스크롤될 때 상세가 뷰포트에 남는다.
- 좌 폭 권장: 이력·근무자 등 넓은 테이블은 `flex-7 : flex-3`, 코스/지점처럼 좁은 목록은 `w-64 ~ w-72` 고정.
- 우측 빈 상태: `AppEmpty`.
- **적용 화면**: 순찰이력(코스 탭), 코스/지점(코스 탭 · 지점 탭), 근무자.
- **미적용 화면**: 지점 순찰이력(전체 폭 테이블), 배치관리(대시보드형).

### 4-3. 탭 레이아웃

각 페이지가 자신의 `AppPageHeader` 아래에 로컬 탭 컴포넌트(`PatrolHistoryTabs`, `CourseTabs`)를 직접 렌더. 라우터 레벨 공용 레이아웃(구 `LocationLayout`/`PatrolLayout` + `AppTabs`)은 폐기(009·011, `patterns.md` §9).

```
┌──────────────────────────────────────┐
│  AppPageHeader (제목 + 서브타이틀)    │
├──────────────────────────────────────┤
│  [탭1] [탭2]                         │
├──────────────────────────────────────┤
│  (페이지 컨텐츠)                     │
└──────────────────────────────────────┘
```

### 4-4. 좌측 트리 + 우측 테이블 (본사 사업장 관리)

```
┌──────────────┬───────────────────────┐
│ 관리그룹     │  사업장 테이블        │
│ 트리         │  (검색바 + 행)        │
│              │                       │
└──────────────┴───────────────────────┘
```

- 트리는 `features/zone/components/zone-tree/*` 패턴 참고.
- 사업장 행 클릭 → `/admin/locations/:id` 상세 페이지로 라우팅(브레드크럼 표시).

## 5. 페이지 공통 규칙

### 5-1. 페이지 헤더

**현장 사이트 (필수)**

```
┌────────────────────────────────────────────────┐
│ 근무자                              [+ 근무자 추가] │
│ 강동 테크노타워 소속 근무자 8명                   │
└────────────────────────────────────────────────┘
```

- **좌측**: 페이지 제목(17px) + **서브텍스트 한 줄**(12.5px `--text-2`). 서브텍스트는 컨텍스트 정보(소속 사업장, 카운트 등).
- **우측**: 주요 액션 버튼 (등록·내보내기 등).
- 브레드크럼 없음. 얇은 헤더.

**본사 사이트**

- 사업장 상세 등에서 좌측에 브레드크럼 + 제목, 우측에 액션 버튼(예: "운영중지").
- TopNav가 이미 메뉴명을 노출하므로 페이지 헤더는 필요 시에만.

### 5-2. 필터 바

- 페이지 헤더 아래(탭이 있으면 탭 아래)에 가로 정렬.
- **리디자인**: **아이콘 + 텍스트 컴팩트 버튼** (`📅 기간 선택`, `☰ 코스`, `▽ 결과`). 셀렉트 필드가 아닌 필터 칩/버튼 스타일.
- 검색 인풋은 별도 좌측 배치. 우측 정렬 액션(내보내기 등)은 별도 라인 또는 페이지 헤더에 편입.
- 필터 상태는 URL 쿼리스트링.

### 5-3. 페이지네이션 (테이블 카드 하단)

- 좌: **`페이지당 행 수` 셀렉트** (기본 `25` 또는 `50`).
- 우: **`1–N / 총N 항목` 카운트 + `< >` prev/next 아이콘**.
- 숫자형 페이저(`[1][2][3]`) 사용 금지 — 카운트+화살표로 통일.

### 5-4. 패딩

- 페이지 외곽: `p-6 ~ p-8`.
- 카드 내부 패딩: `p-4 ~ p-5`.
- 마스터-디테일의 좌측 컬럼은 패딩 없이 행 단위로 처리.

### 5-5. 스크롤

- **현장(리디자인)**: `.app-shell`의 `overflow:hidden` 폐기. 페이지 전체가 **자연스럽게 세로 스크롤**된다. 우측 상세 패널은 `sticky`로 남는다.
- **본사(기존)**: `.app-shell`이 `overflow:hidden`, 컨텐츠 영역이 자체 스크롤.

### 5-6. 반응형 (PC 기본)

- PC 기준. 모바일 전용 기능은 만들지 않는다.
- 분할화면 대응 동선은 §5-7에서 상세.

### 5-7. 모바일 / 분할화면 레이아웃

**본사 사이트** — 뷰포트 폭 **`lg` 미만(< 1024px)** 에서 사이드바 표시 방식 전환:

```
[lg 이상 (>= 1024px)]              [lg 미만 (< 1024px)]
┌─────┬──────────────┐             ┌────────────────────┐
│ SB  │ TopNav        │             │ [☰] TopNav         │
│     ├──────────────┤             ├────────────────────┤
│     │ Contents      │             │  Contents          │
└─────┴──────────────┘             └────────────────────┘
                                    햄버거 클릭 → Sidebar Sheet
```

- `lg` 미만: TopNav 좌측 **햄버거 아이콘** 노출(`MenuIcon`, `lg:hidden`) → `ui/sheet`로 좌측 슬라이드.

**현장 사이트 (리디자인)** — 레일이 이미 68px이라 별도 햄버거 불필요:

- 좁은 폭에서도 **레일 유지**. 컨텐츠 영역만 좁아진다.
- **좁은 폭에서 숨기는 요소** (컨텐츠 영역이 압박될 때 조건부 숨김):
  - **코스 상세의 경로 다이어그램 카드**: 뷰포트 폭이 `md`(< 768px) 미만이면 다이어그램 카드 자체를 숨기고 하단 "지점 순서·편집" 카드만 노출. 다이어그램은 시각적 조망용이며, 편집·조회 기능은 리스트 카드가 완전히 커버.
  - 마스터-디테일 우측 상세 패널: 매우 좁은 폭에서는 상세 진입 시 목록을 접고 상세만 표시(모달 아님, 화면 교체).
- **모바일 전용 UI는 만들지 않는다**. PC 기본 + 분할화면 대응.
