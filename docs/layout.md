# 레이아웃 (layout.md)

> 본 프로젝트의 **레이아웃 셸**과 그 구성 요소 가이드.
> 디자인 토큰은 [`design-system.md`](./design-system.md), 컴포넌트는 [`components.md`](./components.md), 사용자 동선은 [`flow.md`](./flow.md) 참조.
>
> **리디자인 반영 상태 (2026-07-23~)**
> - 현장 사이트: 컴팩트 아이콘 레일 + **TopNav 삭제**로 전환. 아래 §0·§2·§3 참조.
> - `/admin/*` 본사 사이트: **`spec 043`(2026-10-23)에서 같은 레일 셸로 전환**. 옛 셸(사이드바 w-70 + TopNav) 파일은 삭제했다.
> - 두 사이트는 **같은 `RailSidebar`** 를 쓰고 메뉴·태그만 다르다. 셸은 라우터 브랜치별(`ServiceLayout` / `AdminLayout`).

## 0. 전체 셸 구조

### 0-1. 현장 사이트 (`/*`) — 리디자인 반영

```
┌───────────────────────────────────────────────┐
│           .app-shell (자연 스크롤)            │
│ ┌────┬─────────────────────────────────────┐  │
│ │    │ (TopNav 없음)                        │  │
│ │Rail│                                      │  │
│ │68px│ ┌──────────────────────────────┐    │  │
│ │    │ │ 페이지 헤더 (제목 + 서브텍스트│    │  │
│ │    │ │            + 우측 액션)      │    │  │
│ │    │ ├──────────────────────────────┤    │  │
│ │    │ │ 탭 → 필터 칩 → body-row      │    │  │
│ │    │ │ (테이블 카드 + 상세 카드)    │    │  │
│ └────┴─────────────────────────────────────┘  │
└───────────────────────────────────────────────┘
```

- 좌측 레일: **68px 고정 다크 아이콘 레일** (sticky, full-height). 상단 로고 + 아이콘 5개, 하단 로그아웃 버튼. 🔴 **`xl` 이상에서만** — 미만은 하단 floating nav(§2-C, `spec 053`).
- TopNav 없음. 페이지 헤더(제목 + 서브텍스트 + 액션)가 그 역할을 흡수.
- **페이지 자연 스크롤**: 리디자인은 `.app-shell`의 `overflow:hidden` 정책을 폐기하고 페이지 세로 스크롤을 허용. 뷰포트 제한 없는 실제 웹앱 환경을 반영.
- 컨텐츠 영역 배경: `--bg`(연한 톤), 카드는 `--surface`(흰색).

### 0-2. 본사 사이트 (`/admin/*`) — 레일 셸 (`spec 043`)

현장(§0-1)과 같은 구조다 — 68px 다크 레일 + TopNav 없음 + 페이지 자연 스크롤 + 페이지가 자기 헤더(`AppPageHeader`)를 그린다.

- 레일 차이: 로고 아래 **`ADMIN` 태그** · 메뉴 2개(사업장 · 관리자) · 뱃지 없음.
- 🔴 본사 셸은 배치 요약(`GetAssignmentCount`)을 부르지 않는다 — 뱃지 훅은 `ServiceLayout` 이 부른다.
- 본사 → 현장 이동 링크는 **없다**(사용자 결정 2026-10-23). 본사 3종은 로그인하면 사업장 선택 없이 본사 화면으로 간다(`flow.md` §2).

## 1. ServiceLayout / AdminLayout

`src/components/layout/ServiceLayout.tsx` + `src/components/layout/AdminLayout.tsx`

**영역 분기는 라우터 레벨에서 이뤄진다** (007 결정 — `useLocation` 조건분기 아님). `AuthGuard`는 인증 여부만 검사하고 `<Outlet />`만 렌더링한다. 셸은 `router/index.tsx`에서 `AuthGuard`의 두 자식 브랜치가 각각 담당한다.

```tsx
// 인증 성공 → AuthGuard(Outlet) → 영역별 라우터 브랜치 → 셸(ServiceLayout | AdminLayout) → 페이지(Outlet)
<AuthGuard>              {/* <Outlet/> */}
  <ServiceLayout />       {/* 현장(/*) 브랜치의 셸 — RailSidebar + 자연 스크롤 */}
  <AdminLayout />         {/* 본사(/admin/*) 브랜치의 셸 — RailSidebar(ADMIN) + 자연 스크롤 */}
</AuthGuard>
```

**규칙**

- **영역 분기**: 라우터가 현장 라우트는 `ServiceLayout` 자식으로, 본사 라우트는 `AdminLayout` 자식으로 각각 묶는다. 단일 컴포넌트 내부 조건분기가 아니라 **라우터 노드 자체가 분리**되어 있다.
  - `ServiceLayout`(현장, `/*`): `RailSidebar`(68px 컴팩트 아이콘 레일) + TopNav 없음 + 페이지 자연 스크롤.
  - `AdminLayout`(본사, `/admin/*`): 같은 `RailSidebar`(`tag="ADMIN"`, `AdminMenus`) + TopNav 없음 + 페이지 자연 스크롤(`spec 043`).
- **두 사이트 모두** 페이지가 **자체 페이지 헤더**(제목 + 서브텍스트 + 우측 액션)를 그린다. TopNav 없음.
- 페이지는 `<Outlet>` 안에서 `flex-1` 또는 그에 준하는 레이아웃을 가정한다.

## 2. Sidebar

`src/components/layout/sidebar/RailSidebar.tsx` + `sidebar.config.ts` — 현장·본사 공용(`spec 043`, props: `menus` · `tag?` · `badges?`)

### 2-A. 현장 사이트 (리디자인 반영)

```
┌────┐
│ SP │  ← 로고 (68×68, 다크 배경)
├────┤
│ ▓  │  ← 순찰이력 (활성: 좌측 액센트 바 + 밝은 배경)
│ ◯  │  ← 코스/지점
│ ◯  │  ← 근무자
│ ◯  │  ← 배치관리 (대기 요청 수 뱃지)
│    │
│ ⋮  │  ← (예약: 알림 버튼 슬롯, 현재 비어 있음)
│ ⎋  │  ← 로그아웃 (확인 모달, `spec 053`)
└────┘
```

**규칙**

- 폭 **68px 고정**. `position: sticky; top: 0; height: 100vh`. 🔴 `hidden xl:flex` — `xl` 미만은 §2-C.
- 배경: `--rail`(다크). 활성 아이템: `--rail-2`(밝은 하이라이트) + **좌측 2px `--accent` 바**.
- 아이콘 온리. 라벨은 **hover 시 우측 툴팁**으로 노출.
- 아이콘 사이즈 20px, stroke 1.5.
- 그룹 헤더 없음. 아이콘 4개를 세로로 flat 배치.
- 하단: **로그아웃 버튼**(`LogoutButton`) → 확인 모달(`AppAlertDialog`) → 토큰 clear + 영역별 로그인 이동. 사용자 이름은 툴팁 · 모달 문구에 넣는다. 🔴 `spec 053` 에서 프로필 드롭다운(`ProfileBadge`)을 걷어냈다 — 동작하는 항목이 로그아웃 하나뿐이었다(내 정보 = 비활성 자리표시).
- 로그아웃 위 슬롯은 **알림 기능 추가 시 알림 버튼용**으로 예약. 현재는 비어 있음.
- 배치관리 아이콘에 **대기 요청 수 뱃지** 표시(우상단 붉은 dot + 숫자).
- 접기 기능 없음(이미 최소폭).

### 2-B. 본사 사이트 (`spec 043` — 레일 공용)

```
┌────┐
│ SP │  ← 로고
│ADMIN│ ← 사이트 태그
├────┤
│ ▓  │  ← 사업장 (/admin/locations)
│ ◯  │  ← 관리자 (/admin/admins)
│    │
│ ⋮  │  ← (예약: 알림 버튼 슬롯)
│ ⎋  │  ← 로그아웃
└────┘
```

- 치수·활성 스타일·툴팁은 §2-A 와 같다. 뱃지 없음.
- 옛 텍스트 사이드바(`Sidebar` · `SidebarGroup` · `SidebarItem` · `SidebarToggle` · `MobileSidebar` · `menu-lookup`)는 **삭제**했다.

### 2-C. `xl` 미만 — 하단 floating nav (`spec 053`)

`src/components/layout/sidebar/FloatingNav.tsx` — 현장 · 본사 공용(props: `menus` · `badges?`).

```
┌──────────────────────────┐
│  (콘텐츠 · 끝에 pb-24)   │
│ ╭──────────────────────╮ │
│ │ ⏱ 📍 👥 ⇄² 📢 │ ⎋  │ │  ← 하단 가운데 pill
│ ╰──────────────────────╯ │
└──────────────────────────┘
```

- 왜: 휴대폰 폭(390px)에서 68px 레일이 화면의 17% 를 먹어 현장관리자 화면이 담을 수 있는 내용이 너무 적었다(사용자 결정 2026-10-27).
- `xl:hidden` · `fixed bottom-4` 가운데 · 배경 `--rail` · 아이템 44px(레일과 같은 치수).
- 내용: 메뉴 아이콘(레일과 같은 순서) · 대기 뱃지 · 구분선 · 로그아웃. 로고 · `ADMIN` 태그는 없다.
- 활성: `bg-rail-2` + **아이콘 아래 점**(`bg-point`) — 가로 배치라 레일의 왼쪽 바 대신.
- 툴팁은 위쪽(`side="top"`).
- 🔴 `z-40` — 모달 · 시트(`z-50`)가 nav 를 덮는다. 지도(Leaflet, 컨트롤 z 1000)는 `index.css` 에서 `.leaflet-container { isolation: isolate }` 로 가둬 nav 아래로 깐다.
- 🔴 콘텐츠 영역(`ServiceLayout` · `AdminLayout`)에 `pb-24 xl:pb-0` — 마지막 행 · 페이지네이션이 nav 에 가리지 않게. `min-h-screen` — 레일이 없으면 짧은 페이지 아래가 비어 보인다.
- 뱃지 숫자는 레일과 같은 값(레이아웃이 한 번 세서 둘에 넘긴다).

### 2-1. 메뉴 정의 (`sidebar.config.ts`)

```ts
export interface MenuItemType {
  icon: LucideIcon
  title: string           // 툴팁 라벨
  url: string
  activeUrl?: string[]    // 동일 영역의 여러 라우트를 한 메뉴로 묶을 때
  badge?: 'deploymentPending'  // 뱃지 종류(키). 숫자는 레이아웃이 훅으로 세서 `badges` 로 넘긴다
}
```

- **현장 사이트 메뉴** (`ServiceMenus`, flat 5개): `순찰이력` / `코스/지점` / `근무자` / `배치관리` / `공지사항`.
- **본사 사이트 메뉴** (`AdminMenus`, flat 2개): `사업장` / `관리자`. 그룹 헤더(`MenuGroupType`)는 폐기했다.

### 2-2. 활성 판단 규칙 (공통)

- 우선순위: `activeUrl`(배열) > `url`(단일).
- 매칭: `pathname.startsWith(...)`.
- 예: 코스/지점 메뉴는 `activeUrl: ['/zones', '/points']`.

### 2-3. 활성 스타일

- **현장(레일)**: 배경 `bg-rail-2` + 좌측 `border-l-2 border-accent` + 아이콘 색상 승격.
- **본사**: 현장과 같다(레일 공용).
- 아이콘: stroke 1.5.

### 2-4. 접기/펼치기

- 두 사이트 모두 레일이라 접기 개념 없음(`SidebarToggle` 삭제).
- 모바일 분할화면 대응은 §5-6에서 별도 처리.

## 3. TopNav

### 3-A. 현장 사이트 — **삭제**

리디자인에서 TopNav 자체를 제거. 사유:
- 페이지 헤더(§5-1)가 제목·서브텍스트·액션을 모두 흡수.
- 알림 기능이 아직 없음 → 알림 벨 불필요.
- 프로필 드롭다운은 **사이드바 하단 아바타**로 이동.
- 향후 알림 기능 추가 시 **사이드바 하단 프로필 위 슬롯**(§2-A)에 알림 버튼 배치.

`TopNav.tsx` / `AlarmSheet.tsx` 는 본사도 레일로 바뀌면서 **삭제**했다(`spec 043`). `ProfileBadge` 도 `spec 053` 에서 로그아웃 버튼(`LogoutButton`)으로 바뀌며 **삭제**했다(`topnav/` 폴더 없음).

### 3-B. 본사 사이트 — **삭제** (`spec 043`)

현장과 같은 이유로 제거했다. 페이지명은 각 페이지의 `AppPageHeader` 가 그린다.

## 4. 컨텐츠 영역

`<Outlet />`이 들어가는 자리. 페이지 단위로 자체 레이아웃 책임.

### 4-1. 단일 컬럼

```
┌──────────────────────────────────────┐
│  (페이지 컨텐츠 — p-8)               │
└──────────────────────────────────────┘
```

### 4-2. 마스터-디테일 (가장 흔한 패턴)

```
┌──────────────┬───────────────────────┐
│   목록 카드  │   상세 카드           │
│   (좌)       │   (우, sticky)        │
│              │                       │
└──────────────┴───────────────────────┘
```

- **리디자인 규칙**: 좌우 컬럼을 각각 **동일 레벨의 카드**(테두리 + radius)로 감싼다. 이전에는 우측 상세가 풀블리드로 붙어 있었으나 "따로 노는 느낌" 피드백으로 카드화됨.
- 우측 상세: `position: sticky` — 좌측 리스트가 세로 스크롤될 때 상세가 뷰포트에 남는다.
- 좌 폭 권장: 이력·근무자 등 넓은 테이블은 `flex-7 : flex-3`, 코스/지점처럼 좁은 목록은 `w-64 ~ w-72` 고정.
- 우측 빈 상태: `AppEmpty`.
- **적용 화면**: 순찰이력(코스 탭), 코스/지점(코스 탭 · 지점 탭), 근무자.
- **미적용 화면**: 지점 순찰이력(전체 폭 테이블), 배치관리(대시보드형).

### 4-3. 탭 레이아웃

각 페이지가 자신의 `AppPageHeader` 아래에 로컬 탭 컴포넌트(`PatrolHistoryTabs`, `CourseTabs`)를 직접 렌더. 라우터 레벨 공용 레이아웃(구 `LocationLayout`/`PatrolLayout` + `AppTabs`)은 폐기(009·011, `patterns.md` §9).

```
┌──────────────────────────────────────┐
│  AppPageHeader (제목 + 서브타이틀)    │
├──────────────────────────────────────┤
│  [탭1] [탭2]                         │
├──────────────────────────────────────┤
│  (페이지 컨텐츠)                     │
└──────────────────────────────────────┘
```

### 4-4. 좌측 관리그룹 트리 + 우측 본문 (본사 사업장 · 관리자, `spec 043`)

```
┌──────────────┬───────────────────────┐
│ 관리그룹 [✎] │  본문(사업장 목록 등) │
│ ▾ 회사       │                       │
│   ▾ 🏢 본부  │                       │
│       ■ 지사 │                       │
└──────────────┴───────────────────────┘
```

- **XL(1280px) 이상**: 248px 고정 패널(`GroupFilterPanel`, 페이지 래퍼에 `sticky top-6`). **미만**: 본문 위 경로 버튼(`GroupFilterButton`) → 좌측 시트(같은 트리, 44px 행). 시트를 연 채 XL 로 커지면 닫힌다.
- 선택 그룹은 URL `?group` — 없거나 잘못되면 루트.
- 트리는 처음에 전부 펼친다. 단계 구분: 하위 있는 그룹 = 펼침 화살표, 본부 = 건물 아이콘, 지사 = 네모 닷 + 글자 굵기(회사 굵게 · 본부 중간 · 지사 보통). 개수는 지사 행에만 "N개".
- 트리 머리의 편집 아이콘 버튼(시스템관리자 · Master 만) → **관리그룹 편집 모달**(`components.md` 관리그룹 절).
- 컴포넌트: `features/groups/components/{GroupTree,GroupFilterPanel,GroupFilterButton,GroupEditTrigger,GroupEditDialog}.tsx`.

## 5. 페이지 공통 규칙

### 5-1. 페이지 헤더

**현장 사이트 (필수)**

```
┌────────────────────────────────────────────────┐
│ 근무자                              [+ 근무자 추가] │
│ 강동 테크노타워 소속 근무자 8명                   │
└────────────────────────────────────────────────┘
```

- **좌측**: 페이지 제목(17px) + **서브텍스트 한 줄**(12.5px `--text-2`). 서브텍스트는 컨텍스트 정보(소속 사업장, 카운트 등).
- **우측**: 주요 액션 버튼 (등록·내보내기 등).
- 브레드크럼 없음. 얇은 헤더.

**본사 사이트**

- 목록은 현장과 같다(제목 + 서브텍스트 = 범위 + 수 — `○○ 하위 사업장 N개` · `○○ 담당 관리자 N명`).
- 상세(사업장)는 **현장 상세와 같은 머리**(`046` #3 — 044 의 뒤로 버튼을 바꿨다): 브레드크럼(`사업장 › 사업장 상세`) → 그룹 경로(보조 줄) + 이름. 액션은 머리가 아니라 **기본정보 카드 아래**. 로딩 · 실패 화면에도 브레드크럼을 둔다.

### 5-2. 필터 바

- 페이지 헤더 아래(탭이 있으면 탭 아래)에 가로 정렬.
- **리디자인**: **아이콘 + 텍스트 컴팩트 버튼** (`📅 기간 선택`, `☰ 코스`, `▽ 결과`). 셀렉트 필드가 아닌 필터 칩/버튼 스타일.
- 검색 인풋은 별도 좌측 배치. 우측 정렬 액션(내보내기 등)은 별도 라인 또는 페이지 헤더에 편입.
- 필터 상태는 URL 쿼리스트링.

### 5-3. 페이지네이션 (테이블 카드 하단)

- 좌: **`페이지당 행 수` 셀렉트** (기본 `25` 또는 `50`).
- 우: **`1–N / 총N 항목` 카운트 + `< >` prev/next 아이콘**.
- 숫자형 페이저(`[1][2][3]`) 사용 금지 — 카운트+화살표로 통일.

### 5-4. 패딩

- 페이지 외곽: **`p-4 xl:p-8`**(`spec 053` — 휴대폰 폭에서 32px 를 더 콘텐츠에 준다).
- 카드 내부 패딩: `p-4 ~ p-5`.
- 마스터-디테일의 좌측 컬럼은 패딩 없이 행 단위로 처리.

### 5-5. 스크롤

- **현장(리디자인)**: `.app-shell`의 `overflow:hidden` 폐기. 페이지 전체가 **자연스럽게 세로 스크롤**된다. 우측 상세 패널은 `sticky`로 남는다.
- **본사(기존)**: `.app-shell`이 `overflow:hidden`, 컨텐츠 영역이 자체 스크롤.

### 5-6. 반응형 (PC 기본)

- PC 기준. 모바일 전용 기능은 만들지 않는다.
- 분할화면 대응 동선은 §5-7에서 상세.

### 5-7. 모바일 / 분할화면 레이아웃

**두 사이트 공통** (`spec 053` — 2026-10-27, 전에는 "좁은 폭에서도 레일 유지"였다)

```
[xl 이상 (>= 1280px)]              [xl 미만 (< 1280px)]
┌────┬───────────────┐             ┌────────────────────┐
│Rail│ Contents      │             │ Contents (p-4)     │
│68px│ (p-8)         │             │ … 끝에 pb-24       │
│    │               │             │  ╭──────────────╮  │
└────┴───────────────┘             └──╰ floating nav ╯──┘
```

- `xl` 미만: 레일을 숨기고 **하단 floating nav**(§2-C). 페이지 여백 `p-4`.
- 🔴 **가로로 넘치면 안 된다** — 문서가 화면보다 넓으면 모바일 브라우저가 페이지 전체를 축소해 "스크롤이 안 되고 레일이 짧게 보이는" 증상이 난다(053 진단). 그래서:
  - 필터 줄: `flex-wrap xl:flex-nowrap` + 검색 `w-full xl:w-[260px]` → 좁은 폭에서 검색이 한 줄, 필터 · 생성 버튼이 다음 줄.
  - 카드 없는 표(`AppTable`): 상자 안에서만 가로 스크롤(`relative overflow-x-auto`).
  - 탭 줄이 넘치는 화면(배치관리): 탭 줄만 가로 스크롤.
  - 페이지네이션: 줄바꿈 허용 · 문구 꺾임 방지.
- 옛 본사 `lg` 햄버거 + Sheet 안은 본사가 레일로 바뀌며(`spec 043`) 쓰이지 않았고, 이 절에서 지웠다.

**좁은 폭에서 숨기는 요소** (컨텐츠 영역이 압박될 때 조건부 숨김):
  - **코스 상세의 경로 다이어그램 카드**: 뷰포트 폭이 `md`(< 768px) 미만이면 다이어그램 카드 자체를 숨기고 하단 "지점 순서·편집" 카드만 노출. 다이어그램은 시각적 조망용이며, 편집·조회 기능은 리스트 카드가 완전히 커버.
  - 마스터-디테일 우측 상세 패널: 매우 좁은 폭에서는 상세 진입 시 목록을 접고 상세만 표시(모달 아님, 화면 교체).
- **모바일 전용 UI는 만들지 않는다**. PC 기본 + 분할화면 대응.
