## 0. 범례

**위험도 (Risk)**

- **A** — 인증·권한·데이터 변형. 틀리면 치명적 → 풀 스펙 필요
- **B** — 일반 CRUD/조회 → 경량 스펙
- **C** — 정적/단순 → 한 줄

**진행도 (현재 src 기준)**

- ✓ — 페이지·핵심 컴포넌트 대부분 구현 (다듬기만 남음)
- △ — 일부 골격/컴포넌트 존재, 데이터·디테일·다이얼로그 미완
- ✗ — 미시작 (라우트 자체 없음 또는 placeholder)

**용어**: 본 문서는 명세서 표준어인 **"순찰코스 / 순찰지점"**을 사용한다. 코드의 `Zone` = 순찰코스, `Point` = 순찰지점.

### 1-3. 순찰코스 / 순찰지점 관리

> 코드·목업 모두 **탭(코스/지점)** 한 화면 안에서 좌측 목록 + 우측 상세 패턴.

| 화면                                | 라우트               | Risk | 진행도 | 한 줄 설명                                                                                                          |
| ----------------------------------- | -------------------- | :--: | :----: | ------------------------------------------------------------------------------------------------------------------- |
| 순찰코스 **목록** + 선택 코스 상세  | `/zones`             |  B   |   △    | 좌측 코스 목록. 우측 = **경로 다이어그램 카드**(체크포인트 zigzag, 점선 커넥터, 구간 소요시간 라벨, **4개마다 줄바꿈**) + **하단 별도 지점 순서·편집 카드**(드래그 리스트). 교대허용/코스활성화 토글, 사용지점 N/M, 총 소요시간. 좁은 폭에서 다이어그램 자동 숨김 (layout.md §5-7) |
| 순찰코스 **추가/수정/삭제**         | (모달, `/zones` 내)  |  A   |   △    | 코스명·설명 다이얼로그 + 코스 내 지점 **드래그 정렬** + 지점별 소요시간 설정. 드래그는 하단 편집 카드에서 처리      |
| 코스 내 지점 설정 (소요시간/활성화) | (모달, `/zones` 내)  |  A   |   △    | 코스 컨텍스트에서 지점 행 수정. 분 단위 시간 + 활성/비활성 토글                                                     |
| 순찰지점 **목록** + 선택 지점 상세  | `/points`            |  B   |   △    | 단일 컬럼 목록(검색 + 정사각형 추가 버튼) + 우측 상세 카드(기본정보·소속 코스·**인증수단 세그먼트 QR/NFC**·NFC TAG ID·수정/삭제 액션) |
| 순찰지점 **추가/수정**              | (모달, `/points` 내) |  A   |   △    | 이름·설명·인증수단(QR/NFC)·지점사용. **모달 유지**(리디자인 후에도 편집은 모달, 상세는 조회용 카드). NFC ID 14자리 HEX 검증·QR 다운로드 디테일 미확인 |
| 순찰지점 **삭제**                   | (액션)               |  A   |   ✗    | 사용 중 코스 영향 확인 필요 (Open Question)                                                                         |

**경로 다이어그램 카드 스펙** (신규):
- 체크포인트 = 큰 원형 번호 노드 + 하단 이름·설명·인증뱃지.
- 노드 사이 **점선 커넥터 + 구간 소요시간 라벨**(예: `5분`, `8분`).
- 레이아웃: **4개 지점마다 줄바꿈**(zigzag). 10개 이상도 계속 줄바꿈으로 표시.
- **조회 전용**. 드래그·수정·삭제 액션은 하단 "지점 순서·편집" 카드에서.
- S-Patrol만의 공간적 시각 정체성 요소.

### 1-4. 근무자 관리

> 리디자인 이후 메뉴명 = **"근무자"** (기존 "사용자 관리"에서 변경). 페이지 서브텍스트에 소속 카운트 노출("강동 테크노타워 소속 근무자 8명"). 현재 코드엔 라우트 없음.

| 화면                           | 라우트(예상) | Risk | 진행도 | 한 줄 설명                                                                                                                                              |
| ------------------------------ | ------------ | :--: | :----: | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 근무자 목록 + 선택 근무자 상세 | `/users`     |  B   |   ✗    | 검색 + 필터(근무상태/사용자상태) + 우측 상세 카드(기본정보 + **배치 변경 이력(참고 표시)** + 액션). 액션: **비밀번호 / 수정 / 근무자 삭제** — 배치변경 버튼은 §1-4A로 이관됨. 마스터-디테일 |
| 근무자 추가 / 수정             | (모달)       |  B   |   ✗    | 이름·연락처·소속사업장·초기비밀번호. **현장관리자만 생성 가능**                                                                                         |

**리디자인 변경 사항**
- 페이지명 "사용자 관리" → **"근무자"**.
- 소속 사업장 값 표기: 부서명("정문경비") 사용 금지 → **실제 건물명**("강동 테크노타워") 사용.
- **배치변경 버튼 완전 제거** — 배치 워크플로 변경(관리자 주도 → 근무자 APP 요청 + 관리자 승인)과 정합.
- 배치 변경 이력은 상세 하단에 조회 전용으로 유지.

### 1-4A. 배치관리 (신규, 리디자인 재정의)

> **워크플로 변경**: 관리자 주도(구) → **근무자 APP 요청 + 목적지 관리자 승인(신)**.
> 근무자가 APP에서 특정 사업장으로 **배치(파견) 또는 복귀**를 요청 → **목적지 사업장 관리자**가 승인·거부.
>
> - 관리자 액션: **승인**(즉시 확정) / **거부**(사유 입력 모달)
> - 근무자 측: 대기 요청 **1인 1건**만 보유. 사용자 취소 가능
> - 현재 소속 사업장 관리자에게는 별도 통보 없음(근무자 상세의 배치 이력에서 사후 확인)

**화면 구조 (대시보드형)**: 배치는 자주 발생하지 않는 이벤트라 마스터-디테일 대신 **대시보드형 단일 화면**으로 구성.

```
┌────────────────────────────────────────────────────┐
│ 배치관리                                            │
│ 강동 테크노타워 소속 근무자의 배치 이력과 요청을 확인합니다 │
├────────────────────────────────────────────────────┤
│ ┌─KPI─┐  ┌─KPI─┐  ┌─KPI─┐                          │
│ │→ 1명│  │← 2명│  │⏱ 2건│                          │
│ └─────┘  └─────┘  └─────┘                          │
├────────────────────────────────────────────────────┤
│ 배치 요청 목록  (검색 · 페이지네이션)                │
│ ┌─ 사업장 · 이름 · 사유 · 요청일    [✓승인][✕거부] ─┐│
│ ├─ 사업장 · 이름 · 사유 · 요청일    [✓승인][✕거부] ─┤│
│ └────────────────────────────────────────────────┘│
├────────────────────────────────────────────────────┤
│ [배치 나간 이력] [배치 온 이력]  ← 탭 2개            │
│ 이름 · 배치 경로 · 사유 · 기간 · 상태               │
└────────────────────────────────────────────────────┘
```

| 영역                    | Risk | 진행도 | 한 줄 설명                                                                                                             |
| ----------------------- | :--: | :----: | ---------------------------------------------------------------------------------------------------------------------- |
| KPI 3종 (상단)          |  C   |   ✗    | `→ 배치 나간 인원` / `← 배치 온 인원` / `⏱ 대기중인 배치요청`. 클릭 시 아래 해당 영역으로 스크롤 (선택)                |
| 배치 요청 목록 (중단)   |  A   |   ✗    | 카드형 row (사업장명 · 근무자명 · 요청 사유 · 요청일). **인라인 `[✓ 승인] [✕ 거부]` 버튼**. 검색 필터 + 페이지네이션    |
| 배치요청 **승인**       |  A   |   ✗    | 인라인 클릭 → 즉시 확정 (모달 없음). 근무자 소속 이동 + `WorkerAssignmentHistory` 1건 자동 생성 + toast              |
| 배치요청 **거부**       |  A   |   ✗    | 인라인 클릭 → **사유 입력 모달** → 거부 확정. 사유는 근무자 APP에 노출                                                 |
| 배치 이력 (하단)        |  B   |   ✗    | 탭 2개(`배치 나간 이력` / `배치 온 이력`). 컬럼: 이름 · 배치 경로("A → B") · 사유 · 기간 · 상태 뱃지                    |

**설계 근거**
- **마스터-디테일 폐기**: 배치 요청은 판단에 필요한 정보(사업장·이름·사유·요청일)만 노출하면 즉시 승인/거부 가능 → 상세 패널 불필요.
- **KPI가 최상단**: 관리자가 화면 진입 시 "지금 뭐가 급한지"를 즉시 파악.
- **이력이 요청보다 아래**: 요청 처리(액션)가 우선순위 높음.
- **이력 탭 분리 (토글 아님)**: 배치 나간/온 방향은 표시할 컬럼(경로 방향·상태 종류)이 서로 달라 필터 토글로 통합할 수 없음.
- **배치 경로 표기**: 실제 건물명 기준 (예: "강동 테크노타워 → 강서 스퀘어타워").

**사이드바 표기**: 대기 요청 건수를 사이드바 배치관리 아이콘 위에 **붉은 dot + 숫자 뱃지**로 표시.

## 4. 라우트 ↔ 명세서 화면 매핑 (요약)

현재 코드 라우트 vs 명세서 표기 매핑. 코드 식별자(Zone)와 명세서 용어(코스)가 다른 점 주의.

| 현재 라우트                 | 명세서 화면          | 비고                                |
| --------------------------- | -------------------- | ----------------------------------- |
| (없음) `/`                  | 랜딩(신설)           | 정적, 현장 로그인 진입 링크         |
| `/login`                    | 로그인 (현장)        | 명세서의 "로그인" 화면              |
| (없음) `/admin/login`       | 본사 로그인(신설)    | URL 직접 접근                       |
| `/patrol/zones`             | 순찰이력 — 코스 이력 | 코드명 "Zone" = 명세 "코스"         |
| `/patrol/points`            | 순찰이력 — 지점 이력 | 리디자인으로 스펙 확정              |
| `/zones`                    | 순찰코스 목록/설정   | 리디자인: 경로 다이어그램 + 편집 카드 분리 |
| `/points`                   | 순찰지점 목록/설정   | 리디자인: 상세 카드 (편집은 모달)   |
| (없음) `/users`             | 근무자 관리          | 라우트 신설 필요. 메뉴명 "근무자"   |
| (없음) `/deployments`       | 배치관리 (신규)      | 대시보드형 (KPI + 요청 + 이력)      |
| (없음) `/notice`            | 공지사항             | 사이드바 메뉴만 등록됨, 리디자인 대상 |
| (없음) `/settings/keywords` | 환경설정 키워드      | 표현 방식 TBD                       |
| (없음) `/admin/admins`      | 관리자 관리          | `/admin/*` 영역 전체 미시작, 리디자인 미적용 |
| (없음) `/admin/locations`   | 사업장/관리그룹 관리 | 사업장 상세 = 탭(기본정보·헬스체크), 리디자인 미적용 |

## 5. 작업 우선순위 힌트 (참고)

진행도와 위험도 조합으로 본 다음 작업 후보. (확정 우선순위는 별도 결정)

- **A + ✗** = 가장 위험. 손도 안 댐 → 로그인, 사업장 CRUD, 관리자 추가/할당, 사업장 상세, 헬스체크
- **A + △** = 위험하나 골격 있음 → 순찰코스/지점 추가·수정, 드래그 정렬, NFC ID 검증
- **B + ✗** = 양 많음 → 근무자 관리 전부, 공지사항, 지점 이력
- **B + △** = 마무리 단계 → 코스 이력 화면 디테일
