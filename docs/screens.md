## 0. 범례

**위험도 (Risk)**

- **A** — 인증·권한·데이터 변형. 틀리면 치명적 → 풀 스펙 필요
- **B** — 일반 CRUD/조회 → 경량 스펙
- **C** — 정적/단순 → 한 줄

**진행도 (현재 src 기준)**

- ✓ — 페이지·핵심 컴포넌트 대부분 구현 (다듬기만 남음)
- △ — 일부 골격/컴포넌트 존재, 데이터·디테일·다이얼로그 미완
- ✗ — 미시작 (라우트 자체 없음 또는 placeholder)

**용어**: 본 문서는 명세서 표준어인 **"순찰코스 / 순찰지점"**을 사용한다. 코드의 `Zone` = 순찰코스, `Point` = 순찰지점.

>
> **미정 3가지** — 착수 전에 정해야 한다:
> 1. **갱신 방식** — 폴링(몇 초?)인가 수동 새로고침인가. 🔴 이 프로젝트에 **폴링도 websocket 도
>    아직 한 건도 없다**. 첫 사례가 되므로 `patterns.md` 에 규약이 생긴다
> 2. **범위** — 코스 단위만인가, 지점별 진행(몇 번째 지점까지 찍었는지)까지인가
> 3. **진입 위치** — 사이드바 신규 항목인가, `/patrol/*` 의 탭인가
>
> ⚠️ **전용 엔드포인트가 있는지 미실측.** 없다면 `GetCourseHistory?eventType=0` 으로 만든다.

## 4. 라우트 ↔ 명세서 화면 매핑 (요약)

현재 코드 라우트 vs 명세서 표기 매핑. 코드 식별자(Zone)와 명세서 용어(코스)가 다른 점 주의.

| 현재 라우트                 | 명세서 화면          | 비고                                |
| --------------------------- | -------------------- | ----------------------------------- |
| (없음) `/`                  | 랜딩(신설)           | 정적, 현장 로그인 진입 링크         |
| `/login`                    | 로그인 (현장)        | 명세서의 "로그인" 화면              |
| (없음) `/admin/login`       | 본사 로그인(신설)    | URL 직접 접근                       |
| `/patrol/zones`             | 순찰이력 — 코스 이력 | 코드명 "Zone" = 명세 "코스"         |
| `/patrol/points`            | 순찰이력 — 지점 이력 | 리디자인으로 스펙 확정              |
| (없음) `/progress`(예상)    | 진행 중인 순찰 현황  | **신규·미착수**(§1-2A). 🔴 `spec 023` 이 코스 목록에서 **상태 컬럼을 뺀 근거**다 |
| `/zones`                    | 순찰코스 목록        | `spec 023` 재구성 — 전체 폭 6컬럼 테이블(상태 컬럼 제거) |

## 5. 작업 우선순위 힌트 (참고)

진행도와 위험도 조합으로 본 다음 작업 후보. (확정 우선순위는 별도 결정)

- **A + ✗** = 가장 위험. 손도 안 댐 → 로그인, 사업장 CRUD, 관리자 추가/할당, 사업장 상세, 헬스체크
- **A + △** = 위험하나 골격 있음 → 순찰코스/지점 추가·수정, 드래그 정렬, NFC ID 검증
- **B + ✗** = 양 많음 → 근무자 관리 전부, 공지사항
- **B + △** = 마무리 단계 → 순찰코스/지점 목록·상세 화면 디테일 (코스 이력은 009, 지점 이력은 010에서 ✓)
