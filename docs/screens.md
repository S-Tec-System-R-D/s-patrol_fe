# 모바일순찰 — 화면 명세 (screens.md)

> 입력: [`docs/functional-spec.md`](./functional-spec.md), [`docs/overview.md`](./overview.md), `docs/ui-mock/**` (1차 UI 목업)
> 목적: WEB이 만들어야 할 화면 인벤토리. **묶음 단위 / 위험도 / 진행도 / 한 줄 설명**.
> 깊은 화면 스펙(필드·검증·상태기계)은 별도 문서/추후 화면 카드에서 다룬다.

---

## 0. 범례

**위험도 (Risk)**

- **A** — 인증·권한·데이터 변형. 틀리면 치명적 → 풀 스펙 필요
- **B** — 일반 CRUD/조회 → 경량 스펙
- **C** — 정적/단순 → 한 줄

**진행도 (현재 src 기준)**

- ✓ — 페이지·핵심 컴포넌트 대부분 구현 (다듬기만 남음)
- △ — 일부 골격/컴포넌트 존재, 데이터·디테일·다이얼로그 미완
- ✗ — 미시작 (라우트 자체 없음 또는 placeholder)

**용어**: 본 문서는 명세서 표준어인 **"순찰코스 / 순찰지점"**을 사용한다. 코드의 `Zone` = 순찰코스, `Point` = 순찰지점.

## 1-0. 공개 영역 (인증 불필요)

도메인: **s-patrol.co.kr**. 메뉴로 연결되지 않으며 URL 직접 접근.

| 화면                | 라우트         | Risk | 진행도 | 한 줄 설명                                                                                |
| ------------------- | -------------- | :--: | :----: | ----------------------------------------------------------------------------------------- |
| 랜딩 (서비스 소개)  | `/`            |  C   |   ✗    | 정적 소개 페이지. **현장 로그인(`/login`) 진입 링크만**. 본사 로그인 링크는 노출하지 않음 |
| **현장** 로그인     | `/login`       |  A   |   ✗    | 사번 6자리 + 비번 8자리(영문·숫자·특수 1+ 포함). 현장관리자/Admin 3종이 사용              |
| **본사** 로그인     | `/admin/login` |  A   |   ✗    | URL 직접 접근. 시스템관리자/Master/Manager가 사용. 명세서엔 별도 표기 없으나 운영상 필요  |

## 1. `/*` — 현장 운영 사이트 (주 사용자: 현장관리자)

### 1-1. 인증 → `1-0` 공개 영역의 `/login`을 통해 진입한다.

### 1-2. 순찰이력 (조회 전용, 생성·수정·삭제 없음)

| 화면                              | 라우트           | Risk | 진행도 | 한 줄 설명                                                                                                                                           |
| --------------------------------- | ---------------- | :--: | :----: | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 순찰이력 — **코스 이력** + 검색   | `/patrol/zones`  |  B   |   △    | 코스 단위 이력 테이블. 필터(시작일/종료일/구역/결과) + 우측 상세 패널(순찰 정보 + 타임라인). 최신순/전체기간 디폴트, URL 쿼리스트링 저장             |
| 순찰이력 — **지점 이력** + 검색   | `/patrol/points` |  B   |   ✗    | 지점 단위 이력 테이블. 필터(시작일/종료일/순찰코스/인증수단/순찰자/결과) + 결과 뱃지(이상없음/순찰기록/시간초과/이력없음/순찰제외). 현재 placeholder |
| 지점이력 — 기록 상세 (다이얼로그) | (모달)           |  B   |   ✗    | "변경 가능성"으로 표기된 보조 화면. 기록내용 + 첨부사진(N/M 페이저)                                                                                  |
| 순찰이력 Export                   | (액션)           |  B   |   ✗    | Excel / PDF. 두 이력 화면 공용 액션                                                                                                                  |

### 1-3. 순찰코스 / 순찰지점 관리

> 코드·목업 모두 **탭(코스/지점)** 한 화면 안에서 좌측 목록 + 우측 상세 패턴.

| 화면                                | 라우트               | Risk | 진행도 | 한 줄 설명                                                                                                          |
| ----------------------------------- | -------------------- | :--: | :----: | ------------------------------------------------------------------------------------------------------------------- |
| 순찰코스 **목록** + 선택 코스 상세  | `/zones`             |  B   |   △    | 좌측 코스 목록, 우측 선택 코스 + 지점 카드 리스트. 교대허용/코스활성화 토글, 사용지점 N/M, 총 소요시간              |
| 순찰코스 **추가/수정/삭제**         | (모달, `/zones` 내)  |  A   |   △    | 코스명·설명 다이얼로그 + 코스 내 지점 **드래그 정렬** + 지점별 소요시간 설정. 드래그 정렬 미구현 검증 필요          |
| 코스 내 지점 설정 (소요시간/활성화) | (모달, `/zones` 내)  |  A   |   △    | 코스 컨텍스트에서 지점 행 수정. 분 단위 시간 + 활성/비활성 토글                                                     |
| 순찰지점 **목록** + 선택 지점 상세  | `/points`            |  B   |   △    | 단일 컬럼 목록 + 우측 상세(기본정보·소속 코스·인증수단·QR 다운로드)                                                 |
| 순찰지점 **추가/수정**              | (모달, `/points` 내) |  A   |   △    | 이름·설명·인증수단(QR/NFC)·지점사용. NFC ID 14자리 HEX 검증·QR 다운로드 디테일 미확인                               |
| 순찰지점 **삭제**                   | (액션)               |  A   |   ✗    | 사용 중 코스 영향 확인 필요 (Open Question)                                                                         |

## 2. `/admin/*` — 본사 관리 사이트 (주 사용자: 시스템관리자)

> 진입: `/admin/login` (URL 직접 접근). 사이드바 2개 메뉴: **사업장 관리 / 관리자 관리**. 헤더에 `ADMIN` 뱃지, 좌측 하단 "현장 사이트로 이동" 링크.

### 2-1. 관리자 관리

| 화면                           | 라우트(예상)    | Risk | 진행도 | 한 줄 설명                                                                                                                                 |
| ------------------------------ | --------------- | :--: | :----: | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 관리자 목록 + 선택 관리자 상세 | `/admin/admins` |  B   |   ✗    | 검색 + 필터(권한/소속그룹/사용자상태) + 테이블. 우측 상세 = 기본정보 + 담당 사업장 다중 + 액션(비밀번호/비활성화/수정/삭제). 마스터-디테일 |
| 관리자 추가                    | (모달)          |  A   |   ✗    | 이름·연락처·권한·소속그룹·초기비밀번호. **시스템관리자 → Master 생성, Master → Manager 생성**                                              |
| 관리자에게 사업장 할당         | (모달)          |  A   |   ✗    | 소속 그룹 하위 사업장 중 다중 선택                                                                                                         |

### 2-2. 사업장 / 관리그룹 관리

| 화면                                                      | 라우트(예상)                      | Risk | 진행도 | 한 줄 설명                                                                                                                                                            |

## 4. 라우트 ↔ 명세서 화면 매핑 (요약)

현재 코드 라우트 vs 명세서 표기 매핑. 코드 식별자(Zone)와 명세서 용어(코스)가 다른 점 주의.

| 현재 라우트                 | 명세서 화면          | 비고                                |
| --------------------------- | -------------------- | ----------------------------------- |
| (없음) `/`                  | 랜딩(신설)           | 정적, 현장 로그인 진입 링크         |
| `/login`                    | 로그인 (현장)        | 명세서의 "로그인" 화면              |
| (없음) `/admin/login`       | 본사 로그인(신설)    | URL 직접 접근                       |
| `/patrol/zones`             | 순찰이력 — 코스 이력 | 코드명 "Zone" = 명세 "코스"         |
| `/patrol/points`            | 순찰이력 — 지점 이력 | —                                   |
| `/zones`                    | 순찰코스 목록/설정   | 좌측 목록 + 우측 상세 + 지점 카드   |
| `/points`                   | 순찰지점 목록/설정   | —                                   |
| (없음) `/users`             | 근무자 관리          | 라우트 신설 필요                    |
| (없음) `/notice`            | 공지사항             | 사이드바 메뉴만 등록됨              |
| (없음) `/settings/keywords` | 환경설정 키워드      | 표현 방식 TBD                       |
| (없음) `/admin/admins`      | 관리자 관리          | `/admin/*` 영역 전체 미시작         |
| (없음) `/admin/locations`   | 사업장/관리그룹 관리 | 사업장 상세 = 탭(기본정보·헬스체크) |

## 5. 작업 우선순위 힌트 (참고)

진행도와 위험도 조합으로 본 다음 작업 후보. (확정 우선순위는 별도 결정)

- **A + ✗** = 가장 위험. 손도 안 댐 → 로그인, 사업장 CRUD, 관리자 추가/할당, 사업장 상세, 헬스체크
- **A + △** = 위험하나 골격 있음 → 순찰코스/지점 추가·수정, 드래그 정렬, NFC ID 검증
- **B + ✗** = 양 많음 → 근무자 관리 전부, 공지사항, 지점 이력
- **B + △** = 마무리 단계 → 코스 이력 화면 디테일

## 6. Open Questions (이 문서에서 결정 미루는 것)

- [ ] 명세서엔 있고 목업엔 없는 **"환경설정 — 키워드"**의 실제 UX (입력 폼? 태그 리스트? 다국어?)
- [ ] 사업장 **삭제 패스워드 확인** 화면 (인라인 다이얼로그? 별도 페이지?)
- [ ] **권한 실패 시 리다이렉트 정책** (`/login` vs 본인 영역 홈 vs 403 화면)
- [ ] 순찰코스 **진행 중**일 때 코스/지점 편집 가능 여부 (명세서 Open Q)
- [ ] 지점이력 상세("변경 가능성") 표기 의미 — 표현 방식 변경 검토 중인지, 데이터 변경 권한 의미인지
- [ ] 비밀번호 **찾기/재설정** 동선 (명세서 미정의)
- [ ] `/admin/*` 헬스체크 탭에 **비상연락망**이 통합된 상태 — 명세서는 별도 항목으로 분리되어 있는데, 최종 IA를 어느 쪽으로 갈지
