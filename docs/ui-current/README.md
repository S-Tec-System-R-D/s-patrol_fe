## 🔴 바이트 비교로 회귀를 판단하지 말 것 (2026-10-10)

**같은 코드로 두 번 찍어도 1~2장은 ±1% 차이가 난다.** 매번 다른 파일이 흔들리는 것으로 보아
Chromium 렌더링 자체의 비결정성(안티앨리어싱·PNG 압축)이다. 그래서 **파일 크기·해시 비교는
신호가 아니라 잡음**이고, 비교는 **눈으로** 한다.

줄일 수 있는 원인 둘은 이미 제거했다:

| 원인 | 조치 | 증상 |
|---|---|---|
| `AppEmpty` 의 **무한 바운스 애니메이션** | `reducedMotion: 'reduce'`(config) | 빈 상태가 있는 화면이 **찍는 순간마다** 달랐다 |
| 웹폰트 늦은 적용 | `document.fonts.ready` 대기 | 글자 모양이 달라졌다 |

**의미 있는 회귀는 이런 것들이다** — 크기가 **수 KB 단위로** 변하거나, 화면 높이(세로 px)가
변하거나, 내용이 사라지는 것. 실제로 `spec 027` 재촬영에서 `deployments--대시보드` 가
**-6%(3.9KB)** 로 튀어 **배치관리가 빈 화면이 된 것**을 잡았다(아래 이력 참조).

## 재캡쳐 방법

```bash
npm run capture
```

playwright가 dev 서버를 **직접 띄우고**(`--mode capture`, 포트 5174) 캡쳐 후 내린다.
별도로 `npm run dev` 를 띄워둘 필요 없다.

### `--mode capture` 인 이유 (중요)

`.env.local` 의 `VITE_API_BASE_URL`(실 백엔드 IP)이 적용되면 **캡쳐가 깨진다.**
MSW 핸들러는 상대 경로(`/api/...`)로 등록돼 페이지 origin에 매칭되는데, base URL이 채워지면
요청이 외부 origin으로 나가 가로채지지 않는다 → `useMe` 실패 → `AuthGuard`가 로그인으로 리다이렉트.

그래서 `.env.capture` 를 두고 `--mode capture` 로 띄운다.
Vite env 로딩 순서상 `.env.[mode]` 가 `.env.local` 보다 **뒤에 로드되어 이긴다.**

> 같은 함정을 `vitest` 에서도 겪었다. 그쪽은 `vitest.config.ts` 의 `test.env` 로 고정해뒀다.

### 인증 처리

`e2e/capture.pw.ts` 가 `localStorage` 에 토큰을 직접 주입해 `AuthGuard` 를 통과시킨다.
키는 `src/lib/auth/tokens.ts` · `src/lib/auth/site.ts` 와 일치해야 한다
(`auth.accessToken` / `auth.refreshToken` / `auth.siteSeq` / `auth.siteName`).

> 🔴 **`spec 021` 이후 `auth.siteSeq` 도 필요하다.** `AuthGuard` 가 현장 영역에서
> **사업장 미선택** 을 막기 때문에, 이 값이 없으면 보호 라우트가 전부 로그인으로 리다이렉트되어
> **캡쳐가 전부 로그인 화면이 된다.** 본사 영역(`/admin/*`) 은 이 체크에서 제외된다.
>
> ⚠️ `npm run capture` 는 `verify`/`test` 에 포함되지 않아 **자동 검증망 밖** 이다.
> 가드에 새 조건이 붙을 때마다 seed 를 함께 갱신해야 하고, 빠뜨리면 **다음 캡쳐까지 드러나지 않는다.**
> 020(토큰) 과 021(사업장) 에서 각각 한 번씩 이 함정을 밟았다.

> 🔴 **`spec 020` 이후 그 토큰은 진짜 JWT여야 한다.** 사용자 정보가 `/api/auth/me`(실재하지 않는
> 엔드포인트) 에서 **JWT 클레임** 으로 바뀌었다. 의미 없는 문자열을 넣으면 디코딩이 실패해
> `useMe` 가 `isError` 를 반환하고 **캡쳐가 전부 로그인 화면이 된다.**
> `capture.pw.ts` 안의 `makeAccessToken()` 이 클레임을 만들어 주며, 권한은 `dev.role` 이 아니라
> **토큰의 role 클레임** 이 정한다(`dev.role` 은 020에서 제거).

## ✅ baseline 이 스스로 흔들리던 문제 — 해소 (2026-10-20)

덮기 전 전수 비교에서 **손대지 않은 화면 7장이 달랐다.** 둘 다 코드 변경이 아니다:

| 원인 | 해당 | 확인 |
|---|---|---|
| **애니메이션 위상** | `공통/404` · `현장/users--목록` (각 1.02%) | 빈 상태 아이콘의 **공전하는 점** 위치만 다르다 — 두 화면의 diff 영역이 **116×134 로 똑같다**(같은 컴포넌트) |
| **상대 날짜 드리프트** | `patrol-zones--목록/상세` · `points--목록/상세` · `zones--상세` (0.05~0.19%) | MSW 시드가 `daysAgo` 기준이라 **찍는 날마다** 날짜 문구가 바뀐다 |

### 원인 둘 다 잡았다 (036 수정사항 작업에서 처리)

**① 애니메이션 — `index.css` 의 reduced-motion 블록에 한 줄이 빠져 있었다.**

`playwright.config.ts` 는 처음부터 `reducedMotion: 'reduce'` 였고 CSS 에도 규칙이 있었는데,
그 규칙이 `animation-duration: 0.01ms` **만** 두고 **`animation-iteration-count: 1` 을
빠뜨렸다.** `bounce-anim` 은 `infinite` 라 **0.01ms 짜리 주기를 계속 돌고**, 캡쳐가 그중
**아무 프레임**이나 잡는다. 반복을 1회로 끊으면 100% 지점(`translateY(0)`)에서 **끝나 고정**
된다. 표준 reduced-motion 리셋에 원래 함께 들어가는 줄이다.

**② 날짜 — `e2e/capture.pw.ts` 에서 시각을 고정한다.**

`page.clock.setFixedTime(CAPTURE_NOW)` 로 `CAPTURE_NOW = 2026-10-20T09:00:00+09:00` 에
묶었다. 🔴 **`install()` 이 아니라 `setFixedTime` 이다** — `install()` 은 타이머까지
가져가는데 이 캡쳐는 MSW 응답·트랜지션 안착을 전부 **실제 시간으로 기다린다**
(`waitForTimeout`). 타이머를 멈추면 그 대기가 영영 끝나지 않는다.
🔴 **토큰 시각도 같은 상수에서 만든다** — 페이지 시계만 멈추면 세월이 흐른 뒤 `nbf` 가
**페이지의 현재보다 미래**가 된다. 지금은 클라이언트가 `exp`·`nbf` 를 검사하지 않아
괜찮지만, 검사가 붙는 순간 **캡쳐가 전부 로그인 화면**이 되고 원인을 찾기 어렵다.

### 확인 — 같은 코드로 두 번 찍어 대조했다

**13장 중 12장이 바이트까지 동일**했다. 전에는 7장이 흔들렸다.
남은 1장은 `patrol-zones--상세`(**0.14% · 116바이트**)이고 **외부 지도 타일** 때문이다 —
032 가 측정한 노이즈(0.06%)와 같은 종류다. 지도가 없는 화면은 이제 **0%** 다.

🔴 **그래서 이제 "나머지 무변화" 를 바이트로 확인할 수 있다**(지도 화면 제외). 다만
**바이트가 같다 ≠ 눈으로 안 봐도 된다** — 2026-10-13 기록처럼 **±0% 인데 실제로 바뀐
화면**(`deployments--대시보드`)이 있었다. `CAPTURE_OUT` 으로 먼저 찍어 비교하는 규칙은
그대로다.

## 🔴 지도 3화면은 네트워크가 있는 곳에서 찍어야 한다 (2026-10-20)

`patrol-zones--상세` · `patrol-points--상세` · `zones--상세` 는 **V-World 타일을 외부에서
받는다**(`.env.capture` 가 `VITE_MAP_TILE_URL` 을 덮지 않아 `.env.local` 이 적용된다).
타일을 못 받으면 Leaflet 은 **회색 바탕 + 귀퉁이 `© VWorld` 표기만** 그린다 — 화면이
**30~68% 작아지는데 에러는 나지 않는다.**

⚠️ **그 상태로 덮으면 지도가 사라진 baseline 이 저장된다.** 파일 크기가 크게 줄었는데
지도 화면이면 **먼저 타일 로드를 의심한다.**

🔴 **그래서 이 3장은 일부러 낡은 채로 둔다**(사용자 결정 2026-10-20). 재촬영을 미룬 것이
아니라 **하지 않기로 한 것**이다 — 지도 자체는 변하지 않았고, 네트워크 되는 자리에서 따로
찍는 비용이 그 3장을 최신으로 유지하는 값어치보다 크다.
⚠️ **그러므로 이 3장은 "현재 화면" 이 아니다.** 2026-10-20 이후의 공용 컴포넌트 변경
(KPI 제목 줄 · 순번 칩 · 기록 건수 · 메모 흰 바탕)이 **빠져 있다.** 이 셋을 기준으로
회귀를 판단하지 말 것 — 다음에 **지도 화면 자체를 손볼 때** 함께 새로 찍는다.
