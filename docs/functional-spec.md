## 1. 프로젝트 한 줄 정의

에스텍시스템의 사업장 순찰 업무를 디지털화하는 솔루션의 WEB 파트.
관리자/근무자 5단계 권한 체계 하에 순찰코스·지점·이력을 관리한다.
근무자의 실제 순찰 수행은 APP에서, WEB은 관리·조회·설정을 담당한다.

## 2. 시스템 구성

- **WEB-Admin (`/admin/*`)** — 본사 직원 전용. 회사 운영 측 도구.
- **WEB-Service (`/*`)** — 현장 운영 사이트. 주 사용자는 현장관리자.
- **APP** — 근무자 순찰 수행 (별도 팀)
- **Backend** — 별도 팀

**내 담당 = WEB-Admin + WEB-Service**

## 3. 사용자 권한 (5단계 Role)

| Role | 설명 | 생성 권한 | 사업장 범위 | 사용자 수정 | WEB 접근 |
|---|---|---|---|---|---|
| 시스템관리자 | 에스텍 운영진(개발부서) | Master 생성 | 전체 | 전체 | /admin, /* |
| Master | 고객사 총괄(지원팀) | Manager 생성 | 전체 | 본인만 | /admin, /* |
| Manager | 본부/지사 관리 | 사용자 생성 불가 | 할당된 부서 사업장만 | 본인만 | /admin, /* |
| 현장관리자 | 사업장 팀장 | 근무자 생성 | 본인 사업장 | (확인 필요) | /* 만 |
| 근무자 | 순찰 수행 | — | — | — | **불가** (APP만) |

**인증**: JWT에 role 포함 + 로그인 시 본인 계정정보 조회로 가드.

## 4. 라우트/사이트 구조

```
/admin/*  (본사 직원 사이트)
  접근: 시스템관리자 / Master / Manager
  용도: 관리그룹·사업장·헬스체크 설정 등 회사 운영 측 작업

/* (현장 운영 사이트)
  주 사용자: 현장관리자
  접근: 현장관리자 + (시스템관리자/Master/Manager도 가능)
  용도: 근무자/순찰지점/순찰코스/순찰이력 관리

근무자는 WEB 접근 없음 (APP 전용)
```

→ Admin 3종(시스템/Master/Manager)은 양쪽 모두 진입 가능.
→ 현장관리자는 `/*`만.
→ `/* `의 주 사용자가 현장관리자이므로, 거기에 가장 공들임.

## 5. 핵심 도메인

- **관리그룹** — Level 3 트리, Level1 = "에스텍시스템" 고정
- **사업장** — 관리그룹 하위, 헬스체크/비상연락망 설정 보유
- **근무자** — 사업장 소속, 배치 이력 보유 (배치는 근무자 APP 요청 → 목적지 사업장 관리자 승인)
- **순찰지점** — QR 또는 NFC 인증수단
- **순찰코스** — 지점들의 순서 있는 묶음, 드래그 정렬, 지점별 소요시간
- **순찰이력** — 지점이력 / 코스이력 두 가지 관점
- **부가**: 공지사항, 키워드(환경설정), 헬스체크 설정

## 6. 순찰 상태값

- **코스 상태**: `진행중` / `완료` / `미완료`
- **지점 상태**: `대기중` / `진행중` / `미완료` / `순찰제외`
- **지점 기록 상태**: `이상없음`(기록X) / `순찰기록`(기록O)
- **시간초과**: `overtime_yn` (boolean)

## 7. WEB이 만들어야 할 화면 인벤토리

### 7-1. `/admin/*` (본사 직원)

| 화면 | 위험도 | 반응형 | 비고 |
|---|---|---|---|
| 관리자 목록 | B | O | 좌: 관리그룹 트리 / 우: 테이블 (마스터-디테일) |
| 관리그룹 관리 | A | O | Level 3 트리, 권한 로직 복잡 |
| 사업장 목록/추가/변경 | A | O | |
| 사업장 삭제 | A | O | 패스워드 확인 |
| 사업장 헬스체크 설정 | A | O | 시간/예외/주기/반복 |
| 사업장 비상연락망 수신대상 설정 | B | O | 다중선택 + 요일 |

### 7-2. `/*` (현장 운영, 주 사용자: 현장관리자)

| 화면 | 위험도 | 반응형 | 비고 |
|---|---|---|---|
| 로그인 | A | O | 사번 6자리 + 비번 8자리(영문/숫자/특수 1+ 포함) |
| 근무자 목록 | B | O | |
| 근무자 추가/변경 | B | O | 현장관리자가 생성 |
| 근무자 정보/이력 | B | O | 기본정보 + 배치 이력(참고) 표시. 상세 액션: 수정 / 비밀번호 / 삭제 |
| 배치관리 (신규) | A | O | `/deployments` 별도 페이지. 근무자 APP 요청 → 목적지 사업장 관리자가 승인·거부(사유 입력 옵션). 근무자 취소 가능, 대기 요청 1인 1건 |
| 순찰지점 목록 | B | O | |
| 순찰지점 설정 | A | O | QR/NFC 선택, QR 다운로드, NFC ID(14자리 HEX) |
| 순찰코스 목록 | B | O | 진행/대기 구분 표시 |
| 순찰코스 설정 | A | O | 지점 드래그 정렬 + 지점별 소요시간 |
| 순찰이력 — 지점이력 + 검색 | B | O | 최신순/전체기간 디폴트, URL 쿼리스트링 저장 |
| 순찰이력 — 코스이력 + 검색 | B | O | |
| 순찰이력 Export | B | O | Excel / PDF |
| 환경설정 — 키워드 | C | O | |
| 공지사항 | B | O | 제목/내용/첨부 (표현 방식 TBD) — APP 알림 트리거 |

**위험도 기준**
- A: 인증/권한/데이터 변형(틀리면 치명적) → 풀 스펙
- B: 일반 CRUD/조회 → 경량 스펙
- C: 정적 → 한 줄 스펙

## 8. 횡단 관심사 (모든 화면 공통)

- **라우트 가드**
  - `/admin/*` → Admin 3종(시스템/Master/Manager)만
  - `/*` → 현장관리자 + Admin 3종
  - 미인증/근무자 role → `/login` 리다이렉트
- **화면 내 액션 권한**
  - Manager는 사업장 CRUD 불가
  - Master는 사용자 수정 본인만
  - 현장관리자만 근무자 생성 + 순찰지점/코스 CRUD
- **반응형**: 모든 화면. 단, 모바일 전용 기능은 없음(분할화면 대응 목적)
- **검색 조건**: URL 쿼리스트링 저장 (기존 `useQueryParams` 패턴 재사용)
- **에러/로딩/빈 상태**: 공통 컴포넌트 사용 (전역 규칙)

## 9. 범위 (Scope)

**할 것**
- WEB-Admin과 WEB-Service 전체
- 관리자/관리그룹/사업장/근무자/지점/코스/이력/공지/키워드/헬스체크 설정

**안 할 것**
- APP 기능 일체
- 백엔드 일체
- 헬스체크 응답 수신 UX (APP 영역)
- 비상연락 전화 발신 (APP 영역, WEB은 수신대상 등록만)

## 10. 제약

- **스택**: React 19 + Vite + TypeScript + Tailwind
- **반응형**: PC 기준 + 모바일(분할화면 대응 UI만, 모바일 전용 기능 X)
- **라우트**: `/admin/*` 와 `/*` 이중 구조
- **인증**: JWT 토큰 기반, role 포함
- **검색 상태**: URL 쿼리스트링 저장
